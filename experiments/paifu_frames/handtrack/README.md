# 손패 번호 추적 실험 재료 (handtrack, 2026-11-16)

위에서 내려다본 헤드 녹화(11-14, 1496×1496, 초당 10장)에서 **화료자 한 명의 세운 손패 13칸을 번호로 따라갈 수 있는지** 재기 위한 재료.
사람(판정자)이 대조표 그림을 보고 구간마다 "몇 번 칸이 나가고 뽑은 패가 몇 번째 칸에 들어갔나" 를 적으면, `replay.py` 가
버린 패(강)·끝 손패(공개)로 번호에 종류를 붙여 매 순 손패와 시작 손패를 거꾸로 복원한다.

개발 판: `n03_150528`(왼쪽 자리 화료, 7p 퐁, 쯔모 추정) · `r18_141259`(남3국, 왼쪽 자리 = 1번, 리치 쯔모).

## 돌리는 법

```
cd experiments/paifu_frames/handtrack
python -X utf8 run.py <판 id>            # features → segment → river → game → sheets
python -X utf8 run.py <판 id> sheets     # 그 단계부터
python -X utf8 replay.py <판정 파일.json> [--out <폴더>]
```

새 판(시험 판)은 `config/<판 id>.json` 하나만 만들면 된다(아래). 손으로 정할 값을 고르는 도움 스크립트:

- `snap.py <출력 폴더> <시각…> [--crop x0,y0,x1,y1 --side left --scale 1]` — 그 시각 프레임(전체 또는 잘라 돌린 것)을 저장.
- `probe.py <판 id>` — 1초마다 탐색 영역(search)의 패 화소 범위를 찍음(띠를 정할 때 참고, 펠트 끝 흰 줄·패산이 섞여 대충만 맞음).

시간: 판 하나(약 8분) features 1분 · river 2~3분(검출 약 0.5~1.5초 × 정지 상태 3장) · sheets 1분 안팎. 검출·분류는 CPU ONNX.

결과는 `experiments/paifu_frames/results/handtrack/<판 id>/`, 프레임 이름 캐시·특징·임시 파일은 `results/handtrack/_work/`.
주의: `.gitignore` 는 `experiments/**/*.jpg` 만 막는다 — 결과 폴더의 json 은 무시되지 않으니 커밋하지 말 것(`results/` 는 원래 추적 안 됨).

## 손으로 정한 값: `config/<판 id>.json`

| 칸 | 뜻 |
|---|---|
| `side` | 화료자 자리(bottom/right/top/left, 그림 기준). `winner_side_how` 에 어떻게 확인했는지 |
| `t_start` | 판 시작(rounds.json t_start 또는 manifest first_at). features 는 이 3초 전부터 잼 |
| `t_ready` | **손패 정리가 끝나 13장 줄이 가만히 선 첫 시각** = 번호 1~13 을 붙이는 상태. 이 앞 프레임은 안 씀. `ready_note` 에 근거 |
| `t_reveal`, `reveal_frame` | 공개 시각(판 구간 끝 = t_reveal + post_sec 4초), 끝 손패를 읽을 프레임(앞뒤 0.5초 3장 다수결) |
| `band` | 손패 띠 [x0,y0,x1,y1](원본 1496 좌표). 줄 오른쪽 끝 밖(뽑은 패를 떼어 두는 곳)과 줄 앞쪽 여백을 포함. 판 동안 줄이 움직이는 범위를 정지 프레임으로 보고 정함 |
| `sheet_band`, `sheet_band_note` | 대조표에 그리는 띠(줄 방향으로 넓힌 것, `bandfit.py`). 없으면 `band` |
| `river` | 화료자 강 영역(남의 강 패 중심이 들어오지 않게 좁힘) |
| `meld` | 화료자 울기 자리(화료자 오른쪽 앞 모서리) |
| `reveal_region` | 공개 때 눕힌 손패·화료패가 놓이는 영역 |
| `wide` | 넓은 화면(화료자 쪽 탁자 절반) |
| `search` | probe.py 탐색 영역(참고용) |
| `result`, `result_how`, `riichi` | 쯔모/론("tsumo?" = 추정), 리치 — 라벨·rounds.json 메모에서 |
| `notes` | 그 밖에 손으로 정한 것·판 특이 사항 |

`band` 를 정할 때 주의(시험 판에서 겪음): 띠 안에 가만히 있는 피부색 물체(자리 표시 주황 패찰 등)나 늘 쉬고 있는 손이 들어오면
피부 문턱(0.003) 때문에 판 전체가 한 활동 구간이 된다 → 그런 것을 피해 `band` 를 잡고(n07: 주황 패찰, n02·n05: 위 자리 손이 줄 오른쪽 끝에 늘 놓임),
대조표에 보일 범위는 `sheet_band` 로 따로 넓힌다.

띠 크기 제약(v1): 대조표 한 장 = 2열 × (1560 − 머리 26) ÷ (띠 높이 + 4) 줄, 폭 = 2 × (60 + 띠 폭) + 6 ≤ 1560 → **띠 폭(대국자 시점 가로) ≤ 717px**.
지금 두 판은 `band [140, 500, 280, 1215]`(왼쪽 자리 → 시점 715×140, 한 장 2×10 = 20줄).

대국자 시점 회전: `htcommon.ROT`(반시계 각도, `np.rot90(원본, 각도//90)`): bottom 0 · left 90 · top 180 · right 270.
돌린 그림에서 화료자가 아래, 화료자 왼손 쪽이 왼쪽. 칸 번호는 이 그림의 왼쪽부터 1.

## 단계와 결과 파일

1. `features.py` → `_work/<판>_feat.npz`: 프레임마다(반 해상도) 띠의 앞 프레임·3장 앞과의 차이 비율(회색 20단계 초과), 피부 비율, 강·울기 자리 차이·피부, 띠 회색 1/4 축소.
2. `segment.py` → `segments.json`: 활동 = 띠 차이 > 0.002 또는 띠 피부 > 0.003 또는 강 차이 > 0.003 또는 강 피부 > 0.01.
   앞뒤 2장 넓히고 0.6초 미만 정지는 활동에 붙임. 강 쪽을 더한 까닭: 손패 줄을 안 건드리는 쯔모기리(리치 뒤)를 놓치지 않으려고.
   손이 띠 위에 가만히 있어도 활동(줄 상태를 믿을 수 없으므로). 헛 구간(남의 손이 지나감 등)은 판정에서 none.
3. `river.py` → `river_states.json`: 정지 구간마다 3장(처음·가운데·끝, 피부 적은 프레임)을 화료자 시점으로 돌려
   운영 검출기(`tile-obb-r8`, 서버 `LocalReader._seat_raw`) + 분류기(크롭 긴 변 96 미만이면 96 으로 키워 읽기)로 강·울기 자리를 읽고 자리별 다수결.
   활동 구간마다 앞·뒤 정지 상태를 비교해 `river_new`(새로 놓인 패, 가로면 `sideways` = 리치 선언 패) · `river_gone`(빠짐 = 울려 감) ·
   `river_changed`(같은 자리 종류 바뀜 = 분류 흔들림) · `meld_new/meld_gone`.
4. `game.py` → `game.json`: 화료자 자리·근거, 회전, 판 구간, 영역, 쯔모/론, 리치(라벨 + 강에서 본 구간), **끝 손패 `final_hand.closed`(대국자 왼쪽 → 오른쪽)**,
   `win_tile`(줄 옆에 떼어 둔 패 또는 줄 끝에 가로로 붙인 패), 울기, 공개 프레임 이름, 공개 때 화료자 강 전체(`river_final`, 강 줄 순서),
   판 구간 전 버림(`river_before_ready`), 울려 간 버림(`river_called_away`), 라벨 비교(`compare`: label.json · 역할 세트 라벨, 다르면 다르다고만 적음).
5. `sheets.py` → `sheets/` + `index.json`:
   - `seg_NNN_pK.jpg`: 손패 띠 대조표. 왼쪽 열 위→아래, 다음 오른쪽 열. 띠는 원본 화소 그대로(돌리기만). 왼쪽 칸 = 시각(분:초.0.1초, 내림), `#줄 번호`.
     파란 칸 = 직전 정지 상태(첫 줄), 주황 칸 = 직후 정지 상태(마지막 줄). 바로 앞 남긴 줄과 1/4 축소 회색에서 12단계 넘게 다른 화소가 0.2% 이하면 생략하고,
     생략이 있으면 다음 남긴 줄 칸에 "생략 n장 시작~끝". 같은 0.1초 안에 프레임이 둘 들어오면 시각이 겹친다 — `#줄 번호`로 가릴 것.
   - `seg_NNN_wide.jpg`: 넓은 화면, 구간 안 고르게 8장(0.48배 축소, 2열).
   - `still_pK.jpg`: 정지 상태 목록(정지 구간마다 가운데 프레임 띠 한 줄, `정지k`, 길이, `→다음 구간`).
   - `index.json`: 구간마다 `seg, t0, t1, dur, frames, rows, sheets, wide, prev_still, next_still, row_list[{no, t, frame, mark, skipped_before}]`,
     `river`(강·울기 변화 — **그림에는 안 적음**, 판정자에게 줄지는 따로 정함). JPEG 품질 95·4:4:4.

- 뒤 정지 상태가 없는 마지막 구간의 마지막 줄 = 주황 "끝(뒤 정지 없음)". 시각은 0.01초까지.
- 넓은 화면 머리글에 "대국자 시점 — 화료자 손패 줄이 아래쪽", 작은 그림마다 가장 가까운 띠 줄 번호 `#n`(`index.json wide_rows`).
- 개발 두 판의 v1 대조표는 `sheets_v1/`·`index_v1.json`(v1 판정의 줄 번호 근거). `sheets.py --out-sheets <이름>` 으로 다른 폴더에 만들 수 있다.

## 판정 파일 형식 (`replay.py` 입력)

```json
{"game": "r18_141259", "start_tiles": 13,
 "judgments": [
  {"seg": 3, "kind": "tedashi", "out_pos": 5, "in_pos": 9, "moves": [], "conf": "high", "note": ""},
  {"seg": 7, "kind": "tsumogiri", "conf": "low"},
  {"seg": 8, "kind": "draw", "in_pos": 14},
  {"seg": 9, "kind": "discard", "out_pos": 3},
  {"seg": 12, "kind": "call", "meld_pos": [4, 5], "meld_tiles": ["7p", "7p"], "out_pos": 2},
  {"seg": 20, "kind": "unclear", "discards": 1},
  {"seg": 37, "kind": "reveal"}
 ]}
```

제안 형식에서 바꾸거나 더한 것:

- `kind` 에 `draw`·`discard` 를 더함 — 뽑기와 버리기가 정지 상태를 사이에 두고 두 구간으로 갈리는 경우.
  `draw.in_pos` = 뽑은 뒤 n+1장 줄에서의 칸(오른쪽 끝에 떼어 두었으면 n+1), `discard.out_pos` = n+1장 줄에서 나간 칸(뽑은 패를 버리면 쯔모기리로 셈).
- `tsumogiri`·`tedashi` 는 제안 그대로: `out_pos` = 뽑기 전 n장 줄의 칸, `in_pos` = 버린 뒤 n장 줄의 칸(n = 13 − 3 × 울기 수).
- `call`: `meld_pos` = 울기 전 줄에서 울기로 나간 칸들(퐁·치는 2장), 선택 `meld_tiles`(그 패 종류), 선택 `out_pos`(울기 패를 뺀 줄에서 버린 칸).
  깡(4장·영상 보충패)은 다루지 않는다 → `unclear`.
- `unclear`: 여기서 끊는다. 선택 `discards`(이 구간의 화료자 버림 수, 없으면 index 의 강 변화 수 — 버림 ↔ 강 순서를 맞추려고), `calls`(울기 수).
- `moves` 는 주 동작이 끝난 줄에서 차례로 적용(`[옮기기 전 칸, 옮긴 뒤 칸]`). 어느 kind 에나 붙일 수 있다.
- 판정 없는 구간은 none 으로 보고 경고. `reveal` 이 없으면 마지막에 공개를 적용.

## `replay.py` 가 하는 일·검사

- 번호: 첫 덩어리는 1~13, 뽑을 때마다 14, 15, …. `unclear` 뒤 새 덩어리는 B1~B13, B14, …
- 버림 종류 = 판 구간 안 `river_new` 를 구간·강 순서로 이어 붙인 순서의 k번째(판정 구간과 강 기록 구간이 다르면 경고).
  끝까지 남은 번호 = `game.json final_hand.closed`(자리 순서), 쯔모면 마지막에 뽑은 번호 = `win_tile`.
- 결과 `replay_<판정 파일 이름>.json/.txt`: 덩어리별 시작 손패(끊김이 없으면 = 복원된 시작 손패), 구간마다 나간 번호·뽑은 번호·칸·그때 손패(종류),
  번호 → 종류 표, 버림 목록(쯔모기리/손에서, 리치 뒤, 울기 뒤).
- 검사(오류 목록): 뽑기 전 줄 장수(n ↔ n+1), 같은 번호가 두 번 나감, 칸 번호가 줄 밖, 같은 패 5장 이상(번호 전체·순마다),
  리치(가로 놓인 버림) 뒤 손에서 냄, 울기 직후 쯔모기리, 공개 때 줄 장수 ≠ 끝 손패, 번호 종류 충돌.
- 정렬 검사: 끝 손패에서 무늬 묶음 순서·숫자 방향을 읽고, 뽑은 패가 끼어든 칸(tedashi `in_pos`, draw 가 줄 안쪽일 때)의 양옆이
  그 정렬과 맞물린 비율 vs 같은 줄의 아무 칸에나 넣었을 때 맞물릴 기대 비율(종류를 모르는 이웃이 있으면 셈에서 뺌). 순마다 이웃 쌍 정렬 비율도.
- 끊긴 뒤는 마지막 덩어리만 끝 손패에서 거꾸로 채워지고, 앞 덩어리는 버린 번호만 종류를 안다.

형식 시험용 가짜 판정: `examples/fake_r18_a.json`(끊김 없음·draw/discard 갈림), `examples/fake_n03_c.json`(울기).
칸 번호는 아무렇게나 넣은 것이라 결과 손패는 의미 없다. `--out` 을 주지 않으면 결과가 판 결과 폴더에 쌓이니 시험 때는 `--out` 을 줄 것.

## 알려진 한계

- n03 은 판 시작 뒤 화료자가 손패를 세우며 정리하는 동안(15:05:28~15:06:07) 이미 3z·9m 을 버렸다 → `t_ready` 15:06:08 부터, 그 두 장은 `river_before_ready`.
- 울기 자리 읽기는 울기를 놓는 중에 흔들린다(n03 구간 29~30 의 meld_new). 울기 종류는 끝 공개 울기(`final_hand.melds`)를 믿을 것.
- 강 영역 끝에 남의 강 패가 걸치면 그 패가 나타났다 사라지는 것으로 읽혀 헛 구간·헛 변화가 생긴다 — 영역을 좁혀 두 판에서는 없앴다.
- `hand_line` 의 화료패 찾기: 줄에서 패 0.6장 넘게 떨어진 패, 또는 줄 끝에 가로로 붙인 1장. 둘 다 아니면 `win_tile` null + `win_tile_note`.
