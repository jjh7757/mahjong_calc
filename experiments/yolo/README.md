**평가 세트는 갤러리 장면 B·C·D(사진 6장)만** — 사용자 결정(화료패가 사진에 없는 A·E 는 뺌). 스크립트 기본값도 `run_yolo.EVAL_SCENES = "BCD"`.

아래 숫자는 모두 B·C·D 로 다시 집계했다(처음에 A~E·손패 근접·매장 사진으로도 쟀던 것은 맨 아래 "참고").

### 4-2. int8 양자화 (`quant/quant.py`, 결과 `quant/quant_*.json`·`server_bench/server_run_int8.txt`, 2026-10-26)

onnxruntime 정적 양자화(QDQ, 가중치 채널별 int8, 활성 uint8, MinMax 보정). 보정 사진은 평가에 안 쓰는 A·E 4장 + 매장 거치 사진 8장, 평가는 B·C·D. 양자화한 ONNX 는 `C:/Users/jjh7757/dev/_downloads/onnx/int8/`.

하다가 고친 것 두 가지:
- **출력층은 fp32 로 남김:** YOLO 출력은 상자 좌표(0~1280)·확신도(0~1)·마스크 계수가 한 텐서라, 다 int8 로 하면 확신도가 0 으로 뭉개져 상자를 하나도 못 찾았다(0/152). 마지막 모듈의 디코드 부분과 가지 끝 1×1 conv 를 빼고 양자화.
- **직사각형 입력(동적 ONNX):** 처음 내보낸 정사각형 고정 입력은 가는 손패 구역 크롭이 1024×1024 회색 여백 속에 작게 들어가 패를 1~2장만 찾았다(4-1 의 검증기 측정도 이 상태). PyTorch 추론처럼 긴 변만 맞추고 짧은 변은 32 배수로 채우게 바꿈 — fp32 끝까지 손패 64/78(82%).

## 5. YOLO26 단독 개선 (`yolo26_eval.py`, 결과 `results/y26/`)

사진을 15° 씩 24각도로 돌려 자리마다 손패 구역이 가장 잘 잡히는 각도 → 손패 윤곽 기울기 보정 → 구역 마스크·여백 없음·조각 거르기·떨어진 무더기 붙이기 → 패 YOLO 후보와 색(펠트 위 흰 면) 후보 중 장수·텐파이 검사로 고르기(pick).

| 설정 | 화료자 손패 재현율 / 정밀도 | 통째 정답 |
| --- | --- | --- |
| 처음(각도 검색만) | 59% / 57% | 2/6 |
| + 기울기·마스크·여백·조각·줄 | 67% / 64% | 3/6 (C 둘, D k16) |
| + 색 후보 고르기(pick) | 67% / 64% | 3/6 |

- **B 두 장은 24각도 검색이 오른쪽 자리에서 강을 손패로 골라 완전히 틀림** — 1절처럼 화료자 쪽으로 90° 돌리면 B 는 거의 다 찾는다. B·C·D 기준으로는 각도 검색이 90° 회전보다 나쁘다 → 축에 맞춰 찍은 사진은 90° 회전 + 기울기 보정만 쓰는 쪽이 맞다.
- D k12: 南 한 장(떨어진 화료패)·울기 한 장 누락.
- 효과 없던 것: 분류 4방향 TTA, 여러 크기 × 낮은 확신도 검출, 패 imgsz 1600, 각도를 패 개수로 다시 찾기.

**medium 모델:** HaseLab 공개 가중치는 전부 nano(이전 커밋의 `best40.pt` 도 같은 14구역 nano, 3.1M 파라미터). 학습 코드(github haselab-dev/mahjong-cg)는 비공개(404) → medium 은 우리 사진으로 직접 학습해야 한다.
