# 프레임 투표(개선 계획 6단계) — 측정 전에 적는 정의 (2026-11-06 새벽)

이 문서는 `frame_vote.py` 를 돌리기 **전에** 적었다. 결과를 본 뒤 짝·변형·지표를 바꾸지 않는다.

## 규칙(앱 `lib/table/frame_vote.dart` 와 같아야 한다, 명세 `test/fixtures/frame_vote.json`)

- 판독 하나 = 화료자 자리의 `/v2/localroles` 답: 손패 `tiles`(코드, 적5 는 `0m`·`0p`·`0s` 로 따로), 떼어 둔 패 `separate`(없으면 null), 울기 `melds`(패 코드 목록 + 안깡 표시).
- 같음 = 손패 다중집합·떼어 둔 패·울기 다중집합(울기 안은 정렬, 안깡 표시 포함)이 **모두** 같음. 확신도·순서는 안 본다.
- 결과 `agree`(같음) / `mismatch`(다름) / `none`(두 번째 판독 없음: 정지 아님·헤드 실패·서버 실패 — 투표 못 함).
- 앱: `agree` 면 지금처럼 자동 반영, `mismatch` 면 자동 반영 막고 경고 '프레임 불일치', `none` 이면 지금처럼(투표가 없던 때와 같게) — 이유는 촬영 기록에.

오프라인 자료에는 `separate` 가 따로 없다(회귀 세트·`field_bench.py` 는 손패에 합쳐 저장, 앱 흐름 로그는 병합 뒤 `closed`+`win_tile`).
그래서 서버 단독 자료는 "합친 손패(`separate` = null) + 울기" 로 비교한다 — 앱 규칙보다 **덜 엄격**(같다고 볼 수 있는 쌍이 조금 더 많음)하므로 막는 수는 앱보다 작거나 같게 나온다.
앱 흐름 로그는 `tiles` = 병합 손패 `closed`(화료패 포함), `separate` = `win_tile`, 울기는 `[..]` = 드러낸 울기·`(..)` = 안깡.

## 지표(짝 단위)

- 불일치율 = mismatch 짝 / 전체 짝.
- 불일치 때 "하나 이상 틀림" = mismatch 짝 중 두 판독 중 하나라도 틀린 짝 / mismatch 짝.
- 일치 때 "둘 다 틀림" = agree 짝 중 (같은 답이) 틀린 짝 / agree 짝. **자동 반영될 답 기준** = 그중 첫 판독이 자동 반영 대상(서버: 검사 통과 + block 아님, 앱: `auto_block` 없음)인 짝.
- **막는 수** = 순서 있는 짝(A 먼저, B 두 번째)에서 A 가 "자동 반영될 틀린 답" 인데 B 와 달라 막히는 수 / A 가 자동 반영될 틀린 답인 순서 짝 수. 같은 순서 짝으로 헛막음(A 가 맞고 자동인데 B 가 달라 막힘)도 센다.
- 틀림의 정의: 서버 단독은 `ok`(회귀)·`seat_ok`(테스트), 앱 흐름은 `flow_visit` 의 `complete`(개발)·`summarize_field` 의 손패·방총자·점수(테스트). 앱의 "자동 반영될 틀린 답" 은 경고 유무와 상관없이 `auto_block` 이 없는데 틀린 것.
