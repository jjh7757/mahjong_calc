# AI 모델 없이 패 종류 맞히기 (2026-10-26 밤, problem_log 20번)

판독을 "한 장씩 자르기 → 무슨 패인지 고르기" 로 나눌 때, 두 번째를 학습 없이 할 수 있는지 본 실험. 결론: **판독에 쓰지 않음**(Gemini 에 크게 못 미침).

```
python -I experiments/template/faces.py          # 크롭에서 가운데 패 흰 면 잘라 세우기, faces_sheet.png 로 확인
python -I experiments/template/match.py          # 흑백 상관 · HOG · HOG+무늬 색
python -I experiments/template/match_shift.py    # 안쪽 면 + 위치·크기 찾기(matchTemplate)
DENSE=1 python -I experiments/template/embed.py dinov2_s dinov2_b   # 비전 임베딩 검색(DENSE=1 은 위치별 패치 특징)
```

- 크롭: `tile_tool/tiles_raw`(손패), `river_ok.txt`(강), `more_ok.txt`(매장 촬영 Q), `speed/tileset2/tiles`(집 패 정면).
- 시험 = B·C·D 손패 78장. 기준 그림은 시험 장면 사진에서 가져오지 않는다. **강 크롭은 시험에서 뺀다** — 갤러리 장면들이 같은 판을 시간 차를 두고 찍어 강 패가 겹친다(넣으면 49/49 로 샘).
- 가중치: HF 캐시의 timm 모델(`HF_HUB_OFFLINE=1`), `pip install timm`.

**ResNet-50 특징 + 최근접 비교(2026-10-27, 외부 제안 확인, `resnet_nn.py`, 로그 `log_resnet_nn.txt`):** 제안 = "YOLO 로 자른 패를 표준 크기로 → 패마다 기준 그림 3~5장 → ImageNet ResNet 특징 최근접(0°/180°) → 1·2등 점수 차가 작으면 Gemini 로". 같은 시험(B·C·D 손패 78장, 기준은 시험 장면 밖 — 종류별 중앙 11장).

| 입력 / 특징 | 기준 전부 | 기준 3장 | 기준 5장 | 점수 차로 절반 넘기면 남은 패 정답 | 99% 정답이 되게 거르면 남는 패 |

- 템플릿(63~68%)보다 훨씬 나쁘다 — "CNN 특징이 조명에 강하다" 는 맞을 수 있어도, 이 문제의 어려움은 조명이 아니라 획 하나·무늬 개수 차이와 비스듬한 각도다. ImageNet 특징은 그 차이를 구분하도록 배우지 않았다.
- 점수 차로 애매한 패를 넘겨도 정답률이 크게 오르지 않음(절반 넘겨도 36%) → 1·2등 차가 "맞았다" 의 신호가 못 됨. 손패 13장이 모두 안 넘겨질 확률 ≈ 0% → 사실상 매번 Gemini 를 부르게 되어 속도 이득도 없음.
- 기준 그림 3장 vs 5장 vs 전부 차이 작음 — 기준 수가 병목이 아님.

**무늬 필터 + 코드로 세는 검증기(2026-10-27, 사용자 요청, `pattern_count.py`, 로그 `log_pattern_*.txt`):** 패 면 → 무늬 마스크 → 덩어리 →
수패 종류(무늬 없음 = 白 / 둥근 무늬 = 통 / 세로로 선 고른 막대 = 삭 / 빨간 萬 아래·검은 숫자 위 = 만)와 통수 원 중심·삭수 막대 개수. 모르면 말하지 않고, Gemini 답과 어긋날 때만 표시.
절차: 개발은 집 패 세트(평가 밖)로 → v1 을 B·C·D 로 한 번 평가 → B·C·D 를 보고 v2 로 고침(이웃 패가 섞인 면은 가운데 패 비율만, 원은 거리 변환 봉우리, 막대는 굵기·길이가 고를 때만) → 평가 밖 A·E·매장 크롭으로 확인.

| | 헛경보(맞는 답인데 표시) | 13장 손패 하나라도 헛경보 | 기록된 Gemini 오독 유형을 표시 | 9삭→6삭 |
| --- | --- | --- | --- | --- |
| v1, B·C·D(처음 평가) | 14.0% | 86% | 61% | 0/6 |
| v2, B·C·D(보고 고침) | 0.4% | 6% | 41% | 2/6 |
| v2, A·E(평가 밖, 참고) | 4.1% | 42% | 43% | 0/1 |
| v2, 매장 크롭(평가 밖, 참고) | 7.5% | 64% | 16% | 0/4 |
| v2 + 개수 차이 2 이상만 표시, B·C·D / A·E / 매장 | 0% / 0% / 1.1% | 0% / 0% / 13% | 18% / 19% / 9% | 2/6 / 0/1 / 0/4 |

- 패 종류 판단은 말할 때 늘 맞았다(B·C·D 57/57, A·E 50/50, 매장 19/19) — 다만 말하는 비율이 20~29%.
- 개수는 B·C·D 98% → 평가 밖 85%·63% 로 떨어짐(과적합). 가장 노린 9삭→6삭은 평가 밖 0/5 — 9삭은 막대 9개가 작고 촘촘해 덩어리가 붙거나 끊긴다.
- 지금 안전장치(3번 만장일치)가 못 거르는 "같은 쪽 오독" 을 잡을 수 있는 건 개수 차이가 큰 경우(6삭↔9삭 등) 일부뿐. 판독 흐름에는 아직 안 넣음.

약한 곳: 비스듬한 오른쪽 자리 B(10~17/26), 만수끼리(2·3·4만 → 8만, "萬" 이 같아 위 숫자 한 획 차이). 다시 할 때는 우리 크롭(label.json)으로 작은 분류기를 학습해 같은 평가로.
