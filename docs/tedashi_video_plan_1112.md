## 2. 무엇을 찍나

### 2-1. 촬영

- **장소·사람:** 같은 매장, 실제 4명 대국. 연출(혼자 네 자리)은 손 습관이 달라 쓰지 않는다.
- **분량:** 5판 이상, 버림 200건 이상(한 판 40~50건). 판 단위로 **개발 3판 / 시험 2판** 으로 나누고, 어느 판이 시험인지는 찍기 전에 정한다(4·5번째 판).
- **기기(기본값): 헤드 앱 녹화 모드**(0단계에서 만든다). 같은 휴대폰·같은 거치·같은 4:3 화각이고, 앱 판독·추적이 그대로 돈다.
  - 헤드는 이미 12MP 스트림을 프레임마다 받고 있다(`HeadCamera.kt` 분석 콜백). 지금은 300ms 에 한 번만 복사해 쓰는데, 녹화 모드에서는 초당 10장을 목표로 프레임을 **2×2 평균으로 줄여(2040×1530, 패 약 40px)** JPEG 로 헤드 저장소(`Download/mahjong_calc/video_<시각>/f_<밀리초>.jpg`)에 쓴다. 건너뛰어 줄이지 않는다(problem_log 56번).
  - 소리는 녹음하지 않는다(권한 추가 없음).
  - `/preview`·`/capture` 는 지금과 같은 최신 프레임 버퍼에서 만든다 → 태블릿 쪽은 바뀌는 것이 없다.
  - 저장 용량: 장당 0.3~0.5MB 로 어림하면 30분에 5~9GB. 0단계에서 실제 크기를 재고 촬영 전 남은 용량을 확인한다.
  - CameraX 동영상 녹화(`VideoCapture`)를 스트림 하나 더 묶는 길은 쓰지 않는다 — "미리보기 + 12MP YUV + 녹화" 는 보장 조합이 아니라 12MP 판독 해상도가 깎일 수 있다.
- **대안(녹화 모드가 0단계 기준을 못 넘을 때만): 기본 카메라 앱 동영상**(UHD 30fps). 동영상은 16:9 라 위·아래 손패 줄이 잘릴 수 있어 화면으로 확인하고, 안 들어오면 0.6배로 찍는다. 찍는 동안 헤드 앱이 꺼져 **그 판들은 앱 판독·추적이 없다.**
- **평소대로 치게 한다.** 쯔모 패를 놓는 자리·정리 습관을 바꾸라고 하지 않는다.

### 2-2. 정답(쯔모기리 / 손에서 냄)

- 대국자는 아무것도 하지 않는다. 평소대로 친다.
- **기준 판정** = 녹화한 프레임을 전부(초당 10장, 패 약 40px) 쓰고, 손패 띠만이 아니라 **패산 ~ 손패 ~ 강까지 한 화면**으로 잘라 쯔모 패가 어디로 갔는지 따라가며 낸 판정. Opus 5.5(중간) 에이전트 **둘이 서로의 답을 모르고** 사건마다 `쯔모기리 / 손에서 냄 / 모름` 을 적는다.
- 둘의 답이 같고 "모름" 이 아니면 그 사건의 정답으로 쓴다. 둘이 다르거나 하나라도 "모름" 이면 **정답 없음**으로 두고 낮은 속도 조건 채점에서 뺀다(개수는 Q1 지표로 쓴다).
- 다른 사건은 이 세션이 전부 다시 보고 "누가 틀렸는지" 를 적되, 정답으로 되살리지는 않는다(기준을 결과에 맞춰 넓히지 않기 위해).
- 이 정답은 영상에서 나온 것이라 영상과 무관한 확인이 아니다. 한계는 6절.

### 2-3. 버림 사건 목록

- 영상에서 초당 1장을 뽑아 표 12 의 `paifu_frames.py` 로 버림 시각을 얻고, 사람이 순서를 확인한다(`truth.json` 과 같은 형식). 강 패 종류는 이번 채점에 쓰지 않는다 — 자리와 시각만 쓴다.
- T = 버림패가 강에 놓이는 순간(영상에서 0.5초 단위로 맞춤). 표 12-6 처럼 한 프레임 늦게 잡히는 문제를 없앤다.

## 3. 무엇을 재나

### 3-1. 조건(같은 영상을 PC 에서 낮춤)

| 축 | 값 |
| --- | --- |
| 프레임 속도 | 초당 10 / 5 / 3 / 1 / 3초에 1장(지금) |
| 해상도 | 패 약 40px(영상 그대로 또는 그에 가깝게) / 약 20px(지금 프레임 수준, 평균으로 줄임) |

- 다 곱하면 10조건이지만 다 재지 않는다. **속도 다섯 × 패 40px** 과 **초당 10·3 × 패 20px** 일곱 조건만 잰다.
- 사건마다 T−4초 ~ T+2초 구간의 그 자리 손패 띠를 잘라 대조표로 만든다(`tedashi_trace.py sheets` 를 영상 입력으로 넓힘). 초당 10장은 60줄이라 두 장으로 나눈다.

### 3-2. 판정하는 쪽

- **판정은 사람 눈 대신 Opus 5.5(중간) 에이전트 눈**이다(사용자 지침: 자료 만들기는 Opus 5.5 중간 여러 대, 이 세션은 검토). 대조표만 보고 사건마다 `쯔모기리 / 손에서 냄 / 모름` + 확신(high / low) + 한 줄 근거를 적는다.
- **같은 사건을 같은 에이전트가 두 번 보지 않는다**(기준 판정이든 낮은 속도 조건이든 — 먼저 본 답이 뒤 판정에 새지 않게). 사건 × 조건을 에이전트 몫으로 나눌 때 지킨다. 결과 파일은 몫마다 따로.
- 기준 판정 표는 다른 에이전트에게 주지 않는다. 초당 10장·패 40px 조건은 기준 판정이 곧 그 조건의 결과다(따로 다시 재지 않는다).
- 검토(이 세션): 조건마다 표본 20건을 라벨을 가리고 먼저 판정한 뒤 대조한다. 다름이 3건을 넘으면 그 몫을 다른 에이전트로 다시 한다(재시도는 이 경우만, 정답을 보기 전에).

### 3-3. 지표

전체 = 버림 − 울기 뒤 − 리치 뒤. **가림·첫 순 정리는 빼지 않는다**(실제로 겪는 일이라 "모름" 으로 세야 한다).

기준 판정(초당 10장)에 대해:

- **기준 판정률** = 두 에이전트 답이 같고 "모름" 이 아닌 수 / 전체
- **두 판정 일치율** = 둘 다 답한 사건 중 답이 같은 비율

낮은 속도·낮은 해상도 조건에 대해(분모 = 정답이 있는 사건):

- **판정률** = 쯔모기리 또는 손에서 냄으로 답한 수 / 분모
- **기준과 같은 비율** = 기준 판정과 같은 수 / 답한 수 (소리 정답이 없으므로 "정확도" 라고 부르지 않는다)
- **기준과 다른 확정** = 기준과 다르게 답한 수 / 분모
- 자리별·사람별, 쯔모기리 / 손에서 냄 따로도 적는다(한쪽으로 쏠리면 "다 손에서 냄" 이라고만 해도 맞기 때문).
- 기준선: "전부 손에서 냄" 이라고 답했을 때 기준과 같은 비율(= 손에서 냄 비율).

## 4. 합격 기준 (촬영 전에 적음)

판정은 **시험 2판**으로만 한다. 개발 3판은 대조표 모양·자르기 좌표·에이전트 지시문을 다듬는 데 쓴다.

### 4-1. Q1 — 영상 속도면 되나 (초당 10장, 패 40px)

| 결과 | 판정 |
| --- | --- |
| 기준 판정률 ≥ 90% 이고 두 판정 일치율 ≥ 95% | **된다** → Q2·3단계로 |
| 기준 판정률 70 ~ 90% 이고 두 판정 일치율 ≥ 95% | **일부만 된다**("모름" 을 그대로 보여 주는 기능으로만) → 사용자 결정 |
| 기준 판정률 < 70% 또는 두 판정 일치율 < 95% | **위 카메라로는 안 된다** → 여기서 멈춤 |

두 판정이 다 "손에서 냄" 으로만 쏠려 있으면(쯔모기리 답이 전체의 10% 미만) 일치율이 높아도 "된다" 로 치지 않고 사용자에게 보인다.

### 4-2. Q2 — 초당 몇 장이면 되나

- **필요 속도** = 판정률이 기준 판정률에서 5%p 안쪽이고 기준과 같은 비율 ≥ 95% 인 가장 낮은 속도.
- 해상도: 패 20px 에서 판정률이 40px 보다 5%p 넘게 떨어지면 "띠는 지금 프레임보다 곱게 잘라야 한다" 로 적는다.

| 필요 속도 | 4단계에서 헤드가 할 일 |
| --- | --- |
| 3초에 1장 ~ 초당 1장 | 헤드는 그대로, 태블릿이 받는 간격만 줄임 |
| 초당 3장 | 헤드 복사 간격(300ms) 안쪽 — 손패 띠만 따로 보내는 길을 더함 |
| 초당 5장 이상 | 헤드 분석 콜백에서 띠를 바로 잘라 헤드 안에서 판정(전송 안 함) |

### 4-3. 금지

- 결과를 본 뒤 기준·시험 판·조건을 바꾸지 않는다. 시험 2판은 한 번만 채점한다.
- 시험 판 대조표를 보고 지시문을 고치지 않는다.

## 6. 위험과 한계

- **정답이 영상에서 나온다.** 두 에이전트가 같은 영상을 보고 같은 쪽으로 틀리면(예: 쯔모 패를 줄에 끼운 뒤 바로 옆 패를 내는 동작, 손에 가려진 채 바꿔치기) 일치율은 높게 나오고 틀린 줄 모른다. "된다" 는 결론은 "전체 프레임을 보면 두 판정이 같다" 까지이고, 실제로 맞는지는 이 실험으로 증명되지 않는다. 나중에 확인하려면 몇 판만 손패를 아는 사람이 적은 기록과 맞춰 본다(이 계획 밖).
- **일부러 섞는 사람**(小手返し 등)은 이 매장 사람들에게 없으면 못 잰다. 결과는 "평소 손놀림" 에 한한다.
- **한 매장·네 사람.** 사람 습관(끝에 붙임 / 떼어 둠)에 따라 크게 달라진다. 사람별로 따로 적는다.
- **에이전트 눈 ≠ 규칙 판정기.** 1~3단계는 "보이는가" 의 상한이다. 실제 판정기는 더 낮을 수 있다.
- **16:9 화각.** 초광각으로 찍으면 가장자리(손패 줄)가 휜다. 줄 장수 세기에 방해되는지 개발 판에서 본다.
- 영상에는 손과 팔만 담기고 소리는 없다. 그래도 같이 치는 사람들에게 녹화한다고 알리고 영상은 노트북 밖으로 내보내지 않는다.
- 3단계가 "된다" 로 나와도 헤드 발열·배터리 때문에 못 쓸 수 있다(11-11: 선 없이 오래 쓰기가 고민이었다).
