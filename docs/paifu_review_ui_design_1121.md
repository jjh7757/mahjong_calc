# 설계서 — 패보 복기 화면을 "한 문장 먼저" 구조로 (2026-11-21)

계기: 2026-11-21 사용자가 체스닷컴 게임 리뷰 화면 네 장을 보여 주며 "이런 식의 서비스가 더 나아 보인다"고 했습니다. 네 장은 ① 단계 말풍선("오프닝"), ② 수 말풍선("훌륭합니다" · 평가값 −0.11), ③ 수 말풍선("최선입니다" · +0.27, 까닭 한 문장), ④ 판 요약(정확성 · 등급별 개수 · "리뷰 시작")입니다. 같은 날 "mahjong-helper 기준 참고값 넣은 것이 보기 힘들다"는 말도 있었습니다. 같은 날 저녁 사용자가 같은 네 장을 다시 주며 "위 같은 화면을 참고해줘"라고 해서, 화면 배치를 그 네 장에 더 가깝게 고쳤습니다. 이어서 사용자가 일본어 마작 AI 복기 화면 한 장(손패 위 후보별 막대, 후보 13줄 × 숫자 8열 표, "Player 打 / AI 打" 두 줄, 이전 · 다음 오류 단추, 순위 확률 원그래프)을 보여 주며 "이건 어떠니"라고 물었고, 손패 위 막대와 두 줄 비교만 가져오기로 해 넣었습니다(이 판, 2절 · 3-3 · 3-9).

**상태: 11-21 밤 사용자가 9절을 정했고("마작용어 쓰고 나머지는 권장으로 구현해줘") 6절 1~5단계를 구현했습니다(커밋 전).** 구현은 Opus 하위 에이전트, 검토는 설계한 세션이 했습니다. 아래 본문의 3-8 문장 틀이 화면 글의 기준입니다.

**검토(11-21 밤):** `flutter analyze` 문제 없음, `flutter test` 1,359개 모두 통과(검토 세션이 다시 돌림). 웹 빌드로 400×800 · 1280×800 에서 요약 화면 · 복기 화면(r19 남4국 6순) · 최선 보기 막대 · 후보 펼침을 눈으로 확인, 콘솔 오류 없음. 기기(태블릿)에서는 안 봄.
- **설계 전제가 틀렸던 것:** 7절에 "예시 11판에는 짐작 손패가 없다"고 적었는데, 실제로는 7판(L16 · r11 · r12 · r13 · r14 · r17 · r19)의 첫 순(r11은 첫 두 순)에 `guess: true`가 있습니다(녹화 전 손패를 복원 때 짐작으로 채운 것). 그래서 3-6을 넣으면 그 차례가 "손패 모름"으로 빠지고 패효율이 셋 바뀝니다: r19 94 → 93, r11 71 → 60, r13 91 → 90. 나머지 차례의 등급은 그대로입니다. `reviewPaifu(..., gradeGuessed: true)`로 부르면 11판 모두 전과 같은 값이 나오는지 시험으로 확인했습니다. 기본은 설계대로 `false`(짐작은 평가 안 함)이고, 사용자가 이 값으로 확정했습니다(11-21 밤 "그대로 둬").
- 같은 까닭으로 배패 단계 말풍선(3-4)은 예시 7판에서 나오지 않습니다(첫 뽑기가 짐작이라 배패를 모름).
- 상태는 새 값 `ReviewStatus.guessed`로 만들었습니다(3-6에서 열어 둔 것). `reviewFacts`의 `statuses`에 7번째 키 `guessed`가 생깁니다 — LLM 해설 설계서 부록 A-2 예시(키 6개)와 다릅니다.
- 남은 것: 최선 보기 막대 띠가 왼쪽 자리 강 끝을 살짝 덮음, 수 띠 칸 폭 74px이라 긴 글이 잘릴 수 있음, 재생 화면("처음부터 보기")에는 평가 카드가 없고 사건 목록 배지만 남음.

## 0. 요약

- 바꾸는 것은 **보여 주는 순서와 배치**입니다. 등급, 유효패, 참고값을 내는 계산은 그대로 둡니다. 한 가지만 더합니다: 손패를 짐작으로 채운 걸음(`guess`)은 등급을 매기지 않습니다(3-6).
- 참고 화면의 세로 배치를 그대로 따릅니다: **위에 말풍선 → 가운데 탁자 → 아래에 수 띠 → 맨 아래 펼침 단추와 큰 "다음" 단추.**
- 바꾸는 곳은 다섯 군데입니다.
  1. **판 요약 화면**을 새로 만듭니다. 패보를 열면 패효율 점수와 등급별 개수(아이콘 · 색 · 개수의 세로 표)를 먼저 보여 주고 "복기 시작" 단추를 둡니다.
  2. 수마다 **말풍선 하나**를 보여 줍니다. 등급 아이콘, "4만 버림 · 실수", 구석의 숫자 하나, 한 문장만 넣습니다.
  3. **탁자 위 배지**: 방금 버린 패(강의 마지막 패)에 등급 아이콘을 붙입니다.
  4. **수 띠**: 사건 목록 대신 화면 아래에 가로 띠를 두고, 내 버림마다 등급 아이콘을 붙입니다.
  5. 후보 목록과 참고값은 **접어 두고** 단추를 눌렀을 때만 펼칩니다. "최선 보기"를 누르면 탁자 위 내 손패의 패마다 **막대**(그 패를 버리면 유효패 수)를 세워, 후보를 글줄 대신 손패 위에서 보여 줍니다.
- 말풍선 제목 아래에 **"내 버림 4만 / 최선 3만" 두 줄**을 둡니다(두 번째 참고 화면의 "Player 打 / AI 打").
- 단계 말풍선(배패 · 리치 · 끝)도 둡니다. 참고 화면의 "오프닝" 말풍선에 해당합니다.
- 한 문장은 우선 코드가 만듭니다. LLM 해설(`docs/paifu_review_llm_design_1118.md`)이 평가를 넘으면 같은 자리에 끼웁니다.
- 참고한 화면의 그림, 색, 캐릭터, 아이콘 모양은 가져오지 않고 구조만 참고합니다.

## 1. 지금 화면과 문제

지금 재생 화면은 가로면 탁자 왼쪽 · 패널 오른쪽, 세로면 탁자 위(높이 56%) · 패널 아래입니다(`lib/ui/paifu/paifu_screen.dart` `LayoutBuilder`). 패널은 위에서부터 이렇게 쌓여 있습니다(`lib/ui/paifu/review_view.dart`).

| 순서 | 위젯 | 보이는 것 |
| --- | --- | --- |
| 0 | 재생 단추 줄 · 속도 칩 | 처음 · 앞 · 재생 · 뒤 · 다음 내 차례 · 끝, "12 / 80" |
| 1 | `PaifuReviewPanel` | 요약 한 줄("패효율 94 · 최선 6 · 부정확 1 · 실수 1")과 "다음 지적" 단추 |
| 2 | `ReviewCard` | 등급 배지, "4만 버림 → 1샹텐 · 유효패 10장(4종)", "최선은 3만 → 15장 (5장 적음)", 후보 버림 3~4줄 |
| 3 | `EngineReviewBox` | "참고값 (mahjong-helper 기준)" 제목과 4~5줄(개량 뒤 유효패 평균, 속도, 국수지, 추천, 위협 자리와 방총 위험, 가장 안전) |
| 4 | 사건 목록 | 걸음마다 한 줄과 등급 배지 |

문제는 다섯 가지입니다.

1. **숫자가 먼저 나옵니다.** 한 걸음에 처음 보이는 줄이 10줄 안팎이고, 무엇이 문제였는지는 읽는 사람이 숫자를 견줘서 알아내야 합니다.
2. **용어를 알아야 읽힙니다.** 샹텐, 유효패, 국수지를 모르면 카드가 뜻을 전하지 못합니다. 이 앱이 겨냥하는 사람은 초보자입니다.
3. **참고값 상자가 카드와 같은 무게로 보입니다.** 등급의 근거가 아닌 값인데도 화면의 절반을 차지합니다.
4. **판 전체 요약이 한 줄뿐입니다.** 판을 열었을 때 "이 판에서 무엇을 보면 되는지"를 알려 주는 화면이 없습니다.
5. **평가가 탁자와 떨어져 있습니다.** 등급은 패널 안에만 있고 탁자에는 표시가 없습니다. 세로 화면에서는 카드가 목록 스크롤 아래로 숨습니다(HANDOFF 11-18 절 "다음" ②).

## 3. 화면 설계

세로(휴대폰)를 기준으로 그리고, 가로(태블릿)는 3-7에서 옮깁니다.

### 3-1. 판 요약 화면 (새로 만듦, 참고 ④)

손패가 있는 패보(`Paifu.hasHeroHands`)를 열면 재생 화면보다 먼저 보여 줍니다. 손패가 없는 판은 지금처럼 바로 재생 화면으로 갑니다.

```
┌────────────────────────────────────┐
│ ←        복기              ⚙        │
├────────────────────────────────────┤
│ 2026-11-14 2반장 남4국 · 론          │
│                                    │
│ 패효율                    ┌──────┐  │
│                           │  94  │  │
│                           └──────┘  │
│ 버림 13번 가운데 8번을 평가했습니다.   │
│ 유효패 수만 본 값입니다. 수비와       │
│ 점수 판단은 들어 있지 않습니다.        │
│ ────────────────────────────────── │
│ 최선        (★)          6         │
│ 좋음        (✓)          0         │
│ 부정확      (?!)         1         │
│ 실수        (?)          1         │
│ 큰 실수     (??)         0         │
│ ────────────────────────────────── │
│ 평가 안 함   리치 중 3 · 수비 0       │
│             화료 형태 0 · 손패 모름 2 │
│ ────────────────────────────────── │
│ 배울 장면                            │
│ (?)  6순 4만 버림   유효패 −5장    › │
│ (?!) 7순 1삭 버림   유효패 −2장    › │
│                                    │
│ ┌────────────────────────────────┐ │
│ │           복기 시작              │ │
│ └────────────────────────────────┘ │
│            처음부터 보기              │
└────────────────────────────────────┘
```

- **패효율 큰 숫자**: `PaifuReview.efficiencyPct`를 그대로 씁니다. 그 아래에 평가한 건수와 "유효패 수만 본 값"이라는 줄을 반드시 둡니다(8절 위험 1). 평가한 버림이 없으면(null) "—"과 "평가할 버림이 없습니다"를 적습니다.
- **등급 표**: 참고 ④처럼 이름 · 아이콘 · 개수를 한 줄씩 세로로 둡니다. 개수가 0인 줄도 지우지 않고 흐리게 둡니다(표의 모양이 판마다 같아야 견주기 쉽습니다).
- **평가 안 함**: 등급이 아닌 상태를 표 아래 회색으로 적습니다. 리치 중(`forced`), 수비(`defense`), 화료 형태(`complete`), 손패 모름(`unknownHand` + `inconsistent` + 짐작 손패 `guess`, 3-6)의 네 묶음입니다. 등급 표의 합 + 이 네 묶음의 합 = 내 버림 수입니다(7절).
- **배울 장면**: 최대 세 개. 큰 실수 → 실수 → 부정확 순으로 고르고, 같은 등급 안에서는 큰 실수는 `shantenLoss`가 큰 것, 나머지는 `ukeireLoss`가 큰 것이 먼저입니다. 같으면 앞 순이 먼저입니다. 누르면 그 걸음으로 갑니다. 지적이 하나도 없으면 "이 판은 유효패 수에서 지적할 곳이 없습니다"라고 적습니다.
- **복기 시작**(큰 단추): 첫 걸음으로 가고 배패 말풍선(3-4)부터 보여 줍니다. **처음부터 보기**(글 단추): 말풍선 없이 지금 재생 화면처럼 첫 걸음으로 갑니다.
- 재생 화면 위 막대에 "요약" 단추를 두어 다시 열 수 있게 합니다.

### 3-2. 복기 화면 배치 (참고 ②③)

```
┌────────────────────────────────────┐
│ ←        복기          요약   ⚙     │
├────────────────────────────────────┤
│ ┌────────────────────────────────┐ │  ← 말풍선(3-3). 높이 고정
│ │ (?) 4만 버림 · 실수       [−5장] │ │
│ │ 내 버림 4만 · 유효패 10장        │ │
│ │ 최선   3만 · 유효패 15장        │ │
│ │ 3만을 버렸다면 유효패가 5장 더   │ │
│ │ 많았습니다. 차이가 큽니다.        │ │
│ └────────────────────────────────┘ │
│ ┌────────────────────────────────┐ │
│ │                                │ │
│ │          탁자 (지금 그대로)       │ │  ← 마지막 버림에 배지 (?)
│ │                                │ │
│ │      ▂ █ ▅ ▂ ▂ ▂ ▃ ▃ ▃ ▁ ▁ ▁ ▁ │ │  ← "최선 보기" 면 손패 위 막대(3-9)
│ │ 내 손패 1 2 3 4만 …             │ │
│ └────────────────────────────────┘ │
│ ‹  5·9통(★)  6·4만(?)  7·1삭(?!)   › │  ← 수 띠(3-5)
│                                    │
│ [최선 보기] [후보] [참고값]  [ 다음 ] │  ← 단추 줄. "다음" 이 가장 큼
└────────────────────────────────────┘
```

- 말풍선은 탁자 **위**에 둡니다(참고 화면과 같음). 높이를 고정해 걸음을 넘겨도 탁자가 위아래로 흔들리지 않게 합니다.
- 지금의 재생 단추 줄(처음 · 앞 · 재생 · 뒤 · 끝)과 속도 칩은 "⚙" 안이나 수 띠 양 끝의 ‹ ›로 옮깁니다. 자동 재생은 복기 화면에서는 기본으로 숨기고, "처음부터 보기"로 들어온 재생 화면에서만 보입니다(9절 ⑥).
- 펼친 후보 · 참고값은 탁자 위를 덮는 아래 시트로 엽니다. 탁자를 밀어내지 않습니다.
- **단추가 하는 일(구현 기준):** 큰 "다음" = 다음 **내 버림** 걸음으로 갑니다(그 사이에 단계 말풍선이 있으면 거기서 먼저 멈춤). 마지막 내 버림 뒤에는 끝 걸음(끝 단계 말풍선)으로 갑니다. 수 띠 양 끝 ‹ › = 한 걸음씩. 수 띠 오른쪽 끝의 "다음 지적" 아이콘 단추 = 지금의 `PaifuReviewIndex.nextFlagged`. 키보드(←→↑↓ · 스페이스)는 지금처럼 둡니다.

### 3-3. 수 말풍선 (지금의 평가 카드를 대신함)

```
┌────────────────────────────────────┐
│ (?) 4만 버림 · 실수          [−5장] │
│ 내 버림  4만 · 유효패 10장           │
│ 최선     3만 · 유효패 15장           │
│ 3만을 버렸다면 유효패가 5장 더 많았  │
│ 습니다. 차이가 큽니다.                │
└────────────────────────────────────┘
```

- **제목 줄**: 등급 아이콘, 버린 패, 등급 이름을 적습니다. 최선이면 참고 ③처럼 "4만 버림 · 최선입니다"로 적습니다.
- **두 줄 비교**(두 번째 참고 화면의 "Player 打 / AI 打"): "내 버림 ○ · 유효패 N장"과 "최선 ○ · 유효패 M장"을 위아래로 둡니다. 값은 `actual`과 `best`의 `ukeire.total`입니다. 샹텐이 다르면(큰 실수) 장수 대신 "N샹텐"을 적습니다. 최선이면 두 번째 줄을 빼고 한 줄만 둡니다. 텐파이에서는 "유효패"를 "대기"로 씁니다. 등급이 없는 걸음(리치 중 · 수비 · 화료 형태 · 손패 모름)에서는 두 줄을 빼고 문장만 둡니다.
- **구석의 숫자 하나**: 유효패 차이(`ukeireLoss`)를 "−5장"처럼 적습니다. 샹텐이 뒤로 간 버림(`shantenLoss > 0`)은 숫자 대신 "샹텐 후퇴"(2 이상이면 "N샹텐 후퇴")라고 적습니다. 최선이면 비워 둡니다. 손해면 어두운 배지, 아니면 밝은 배지입니다(참고 ②의 −0.11과 ③의 +0.27).
- **본문**: 한 문장이고 두 줄을 넘기지 않습니다. 문장은 아래 순서로 고릅니다.
  1. LLM 해설이 있고 서버 검증을 통과했으면 그 글을 씁니다(해설 설계서 2단계 뒤).
  2. 없으면 코드가 만든 문장을 씁니다(3-8).
- **내 버림이 아닌 걸음**(남의 버림, 내가 뽑는 걸음): 말풍선 틀은 남기고 안에 "남 자리 · 7만 버림"처럼 한 줄만 회색으로 적습니다. 말풍선이 사라지면 탁자가 흔들리기 때문입니다.
- 걸음이 단계 시작(3-4)이면 단계 말풍선을 먼저 보이고, "다음"을 한 번 더 눌러야 그 걸음의 수 말풍선으로 갑니다.

### 3-4. 단계 말풍선 (참고 ①의 "오프닝")

체스의 오프닝 · 중반 · 끝내기 자리에 마작의 세 단계를 둡니다. 수 띠 끝에 단계 아이콘 세 개를 두고, 누르면 그 단계 말풍선으로 갑니다.

| 단계 | 언제 보이나 | 문장(코드가 만듦) | 쓰는 값 |
| --- | --- | --- | --- |
| 배패 | 첫 걸음 | "배패는 N샹텐이었습니다."(0이면 "배패 텐파이였습니다.") | 시작 손패 13장의 샹텐(`lib/engine/shanten.dart` `shanten`) |
| 리치 | 누군가 리치한 걸음 | 내 리치: "N순에 리치했습니다. 그 뒤 M번은 뽑은 패를 그대로 버렸습니다." / 남의 리치: "○ 자리가 리치했습니다. 여기부터 수비 판단은 평가하지 않습니다." | `riichiDeclared`, `forced` 개수, `riichiSeats` |
| 끝 | 마지막 걸음 | "론 · 8,000점" / "유국" 등 결과 한 줄 + "이 판 패효율 94" | `PaifuScore`, `efficiencyPct` |

- 배패 말풍선은 손패가 있는 판에서만 보입니다. 손패를 모르면 이 단계를 건너뜁니다.
- 남의 리치가 여러 번이면 첫 번째만 단계로 둡니다.

### 3-5. 수 띠 (지금의 사건 목록을 대신함, 참고 ①②③ 아래 띠)

- 가로 한 줄로 걸음을 늘어놓고, 지금 걸음을 가운데 밑줄로 표시합니다. 양 끝 ‹ ›는 한 걸음씩 움직입니다.
- 내 버림은 "6 · 4만"과 등급 아이콘, 남의 버림 · 뽑기는 흐린 글로 짧게("남 7만") 둡니다. 평가하지 않은 내 버림(리치 중 등)은 아이콘 없이 둡니다.
- 띠를 좌우로 밀면 걸음을 고를 수 있고, 누르면 그 걸음으로 갑니다.
- 지금의 사건 목록(세로)은 "⚙ → 사건 목록"으로 남깁니다. 지우지 않습니다.

### 3-6. 짐작 손패는 평가하지 않음 (새로 정함)

11-21 오전에 만든 손패 복원(`lib/paifu/hand_restore/`)은 울기 뒤의 손패 · 뽑은 패를 짐작으로 채우고 사건에 `guess: true`를 적습니다. 지금 `reviewPaifu`는 이 표시를 보지 않아, 짐작한 손패로 "실수"를 매기고 요약의 배울 장면에도 올릴 수 있습니다.

- 버림 사건 또는 그 직전 뽑기 사건이 `guess`이면 그 걸음은 등급을 매기지 않습니다. 상태는 새로 만들지 않고 `unknownHand`와 같은 묶음("손패 모름")에 넣되, 말풍선 문장은 "이 순의 손패는 짐작이라 평가하지 않습니다."로 따로 적습니다.
- `ReviewStatus`에 값을 더할지(`guessed`), `TurnReview`에 `guessed` 칸만 더할지는 구현 때 정합니다. `reviewFacts`(LLM 사실표)의 `statuses`에도 같은 묶음이 들어가야 합니다.
- 이것은 계산을 바꾸는 유일한 곳입니다. 짐작 손패가 없는 판(예시 11판 전부)은 결과가 바뀌지 않아야 합니다(7절).

### 3-7. 가로 화면(태블릿)

- 탁자를 왼쪽에, 오른쪽 패널에 위에서부터 말풍선 → 수 띠 → 단추 줄을 둡니다. 세로와 순서가 같습니다.
- 펼친 후보 · 참고값은 오른쪽 패널 안에서 말풍선 아래로 펼칩니다(가로는 자리가 남습니다).

### 3-8. 코드가 만드는 문장

상태와 등급마다 틀을 하나씩 둡니다. 숫자와 패 이름은 `TurnReview`의 값을 그대로 넣습니다.

| 상태 · 등급 | 문장 틀 | 쓰는 값 |
| --- | --- | --- |
| 최선 | 유효패가 가장 많은 버림입니다. | 없음 |
| 좋음 | 최선(○)과 N장 차이로 거의 같습니다. | `best.tile`, `ukeireLoss` |
| 부정확 | ○을 버렸다면 유효패가 N장 더 많았습니다. | `best.tile`, `ukeireLoss` |
| 실수 | ○을 버렸다면 유효패가 N장 더 많았습니다. 차이가 큽니다. | 위와 같음 |
| 큰 실수 | 샹텐이 N 늘었습니다. ○을 버리면 그대로였습니다. | `best.tile`, `shantenLoss` |
| 리치 중(`forced`) | 리치 중이라 뽑은 패를 그대로 버립니다. | 없음 |
| 수비(`defense`) | 다른 자리가 리치 중입니다. 버린 패는 현물입니다. / 현물이 아닙니다. / (모르면) 현물인지 판단하지 않습니다. | `genbutsu`(true / false / null) |
| 화료 형태(`complete`) | 화료 형태에서 버렸습니다. 화료하지 않은 까닭은 판단하지 않습니다. | 없음 |
| 손패 모름 | 이 순은 손패 기록이 없어 평가하지 않습니다. | 없음 |
| 짐작 손패(3-6) | 이 순의 손패는 짐작이라 평가하지 않습니다. | 없음 |

- 텐파이(샹텐 0)에서는 "유효패"를 "대기"로 바꿉니다. 지금 카드도 이렇게 나눠 씁니다.
- 용어는 **마작 용어**로 씁니다(9절 ① 사용자 결정, 11-21 밤): "유효패", "N샹텐", "텐파이", "대기". 쉬운 말로 바꾸는 설정은 두지 않습니다.
- 최선과 유효패 수가 같은 버림이 여럿이면 "3만(또는 6만)"처럼 둘까지 적습니다. 지금 `best`는 `options.first` 하나뿐이라, 같은 값의 후보를 `options`에서 더 찾습니다.
- 문장 함수는 화면과 떼어 순수 함수로 만듭니다(`TurnReview`를 받아 글을 돌려줌). 그래야 시험할 수 있고, LLM 해설이 검증에서 떨어졌을 때의 대체 문장으로도 같이 씁니다.

### 3-9. 펼침: 최선 보기, 후보, 참고값 (참고 ②③의 "보이기 · 최고")

셋 다 기본은 접혀 있습니다. 후보와 참고값은 한 번 펼치면 그 판을 보는 동안은 펼친 채로 둡니다.

- **최선 보기**(두 번째 참고 화면의 손패 위 막대): 탁자 위 내 손패(버리기 전 14장)의 패마다 위에 막대를 세웁니다. 다시 누르면 끕니다. 최선이었던 걸음에서도 켤 수 있습니다.
  - **막대 높이** = 그 패를 버렸을 때 유효패 수(`options`의 `ukeire.total`). 가장 높은 후보를 꽉 찬 높이로 두고 나머지는 비율로 그립니다. 같은 종류의 패가 여러 장이면 맨 오른쪽 한 장 위에만 그립니다.
  - **샹텐이 뒤로 가는 후보**는 막대 대신 회색 점으로 둡니다. 유효패 수를 같은 눈금에 놓으면 샹텐이 다른 후보가 더 좋아 보일 수 있기 때문입니다.
  - **색**: 최선 후보(같은 값 모두) = 초록, 실제로 버린 패 = 등급 색, 나머지 = 회색. 색만으로 가르지 않도록 최선 막대 위에 ★, 실제 버린 패 막대 위에 "버림"을 적습니다.
  - 막대를 누르면 말풍선 아래에 "3만을 버리면 유효패: 1만 4만 2삭 5삭 (15장)" 한 줄을 띄웁니다.
  - **어느 손패 위에 그리나:** 평가는 버린 **뒤** 걸음(`eventIndex + 1`, `PaifuReviewIndex`)에 붙어 있어 그때 탁자 손패는 13장입니다. 막대는 버리기 **전** 14장 위에 그려야 하므로, 최선 보기를 켜면 손패 줄(`_heroStrip`)을 `TurnReview.before`(버리기 전 닫힌 패)로 바꿔 그리고, 실제로 버린 패를 제자리에 흐리게 되돌려 놓습니다. 끄면 원래 13장으로 돌아갑니다. 적5는 `before`가 34칸이라 구분이 없으므로, 그 걸음의 손패 기록에서 적 표시를 옮겨 옵니다.
  - 손패를 모르는 걸음 · 남의 걸음에서는 단추를 흐리게 두고 누르면 "이 걸음은 손패 기록이 없습니다"를 띄웁니다.
- **후보**: 지금 `ReviewCard`의 후보 목록을 그대로 옮깁니다(후보 패, 샹텐 수, 유효패 장수, "실제"와 "최선" 표시).
- **참고값**: 지금 `EngineReviewBox`의 4~5줄을 **세 줄로 줄입니다.**

```
참고값 (공개 마작 도구 mahjong-helper 계산 · 등급과 따로 셈)
  점수·화료까지 본 추천   5삭   ← 말풍선의 최선(3만)과 다를 수 있음
  이 패 방총 위험         약 1.7% (위협: 남 자리)
  가장 안전한 패          5통
                                     [자세히]
```

  - 첫 줄 이름은 "추천 버림"으로 줄이지 않고 **"점수 · 화료까지 본 추천"**을 유지합니다. 말풍선의 최선(유효패 최다)과 다른 패가 나올 수 있어서, 이름까지 줄이면 "최선이 두 개"로 읽힙니다. 두 패가 같으면 "말풍선의 최선과 같음"이라고 적습니다.
  - 개량 뒤 유효패 평균, 속도, 국수지는 "자세히" 안으로 넣습니다.
  - "자세히" 안은 두 번째 참고 화면의 큰 표처럼 **후보마다 한 줄인 표**로 둡니다(숙련자용). 열은 우리에게 있는 값만: 버릴 패 · 샹텐 · 유효패 · 개량 뒤 평균 · 화료율(텐파이일 때) · 이 패 방총 위험(위협이 있을 때) · 국수지. AI 선택 확률 열은 없습니다.
  - 위협 자리가 없으면(리치한 사람이 없으면) 방총 위험과 가장 안전한 패 줄은 빼고 추천 한 줄만 보여 줍니다.
  - "등급과는 따로 센 값"이라는 지금의 도움말은 그대로 둡니다.

지금의 `ReviewGrade`와 배지 색을 그대로 쓰고 아이콘만 더합니다. 색만으로 가르지 않도록 모양을 함께 씁니다. 아이콘은 Material 아이콘과 글자(?!, ?, ??)로 우리가 그립니다.

| --- | --- | --- | --- |
| `best` | 최선 | ★ | 초록 |
| `good` | 좋음 | ✓ | 연한 초록 |
| `inaccuracy` | 부정확 | ?! | 노랑 |

| `blunder` | 큰 실수 | ?? | 빨강 |

"큰 실수"라는 이름과 등급 문턱(10%, 30%)은 여전히 임시값입니다(9절 ④).

| `lib/paifu/review_facts.dart` | 3-6의 묶음을 `statuses`에 반영 |
| `lib/ui/paifu/review_view.dart` | 말풍선 위젯, 수 띠 위젯, 펼침 시트. `ReviewCard` 후보 목록과 `EngineReviewBox`를 펼침 안으로 옮기고 참고값을 세 줄로 줄입니다 |
| `lib/ui/paifu/review_summary_view.dart` (새 파일) | 3-1의 판 요약 화면 |
| `lib/ui/paifu/paifu_screen.dart` | 요약 화면을 먼저 띄우는 연결, 3-2 · 3-7의 배치, 탁자 마지막 버림 배지(`PaifuTableView` `_riverTile`)와 손패 위 막대(`_heroStrip`, 최선 보기 때 버리기 전 14장으로 바꿔 그림) |
| `test/` | 문장 함수 시험, 짐작 손패 시험, 요약 getter 시험, 말풍선 · 수 띠 · 요약 화면 위젯 시험 |

- LLM 해설의 호출과 저장은 이 설계의 범위가 아닙니다. 말풍선은 문장을 밖에서 받도록 만들어 두고, 해설 설계서의 2단계가 끝나면 그 자리에 끼웁니다.
- **시작 전에:** `paifu_screen.dart` · `paifu.dart`에는 손패 복원 작업(11-21 오전)이 커밋되지 않은 채 있습니다. 그 작업을 먼저 커밋해야 이 작업의 덩어리와 섞이지 않습니다.

## 6. 단계

1. 문장 함수, 짐작 손패 처리, 요약 getter와 시험을 만듭니다(화면 없음).
2. 말풍선과 탁자 배지로 바꾸고 후보 · 참고값을 접습니다.
3. 판 요약 화면을 만들고 연결합니다.
4. 수 띠와 세로 배치(3-2)를 만듭니다.
5. 단계 말풍선(3-4), 최선 보기의 손패 위 막대(3-9), "자세히" 후보 표를 더합니다.
6. LLM 해설 문장을 끼웁니다(해설 설계서 2단계 뒤).

1~4단계까지가 "체스닷컴식 구조"의 최소 범위입니다.

## 7. 확인 기준 (재기 전에 적는 안)

- 문장 함수: 3-8의 열 가지 경우와 3-4의 단계마다 시험이 있고, 문장 속 숫자와 패 이름이 `TurnReview`의 값과 같습니다.
- 예시 패보 11판(`assets/paifu`) 전부에서 문장이 만들어지고, 문장 속 숫자가 평가 값과 어긋나는 건이 0건입니다.
- 예시 11판의 등급 · `efficiencyPct`가 3-6을 넣기 전과 같습니다(짐작 손패가 없는 판).
- 요약 화면의 등급별 개수 합과 평가 안 함 네 묶음의 합이 내 버림 수와 같습니다(11판 전부).
- 1280×800(가로 태블릿)과 400×800(세로 휴대폰)에서 말풍선 · 탁자 · 수 띠 · "다음" 단추가 스크롤 없이 한 화면에 보입니다.
- 한 걸음에서 펼치기 전에 보이는 글이 말풍선 안 다섯 줄 이하입니다(제목, 두 줄 비교, 문장 최대 두 줄). 지금은 10줄 안팎입니다.
- 걸음을 넘겨도 탁자의 위치가 바뀌지 않습니다(말풍선 높이 고정).
- 손패 위 막대: 예시 11판의 평가한 걸음 전부에서 막대 높이 순서가 `options`의 유효패 순서와 같고, ★ 막대가 `best`와 유효패 수가 같은 후보들과 일치합니다. 400×800에서 막대가 패 폭 안에 들어갑니다.
- 마지막으로 사용자가 실제 기기에서 눈으로 확인합니다.

## 8. 위험과 한계

1. **패효율 점수가 실력 점수처럼 읽힐 수 있습니다.** 참고 ④의 "정확성 89.4"와 같은 자리에 숫자를 두면 더 그렇습니다. 체스는 모든 정보가 공개돼 평가값이 하나로 정해지지만, 마작은 숨은 패와 운이 있고 지금 평가기는 유효패 수만 봅니다. 그래서 요약 화면에 "유효패 수만 본 값"이라는 줄을 반드시 둡니다.
2. **등급 문턱이 임시값입니다.** 요약 표로 크게 보여 주면 임시 기준이 확정된 것처럼 보일 수 있습니다.
3. **마작 용어가 초보자에게는 어려울 수 있습니다.** 사용자 결정으로 마작 용어(유효패 · 샹텐)를 씁니다.
4. **문장이 단조롭습니다.** 틀이 열 개뿐이라 같은 문장이 반복됩니다. 참고 ③의 "무료로 폰 하나를 얻었습니다"처럼 까닭("뽑은 패로 된 순자를 헐었다")까지 말하려면 LLM 해설이 필요합니다.
5. **결과로 평가하지 않는다는 원칙은 그대로입니다.** 실수로 표시된 버림이 화료로 이어졌어도 등급은 바꾸지 않습니다.
6. **세로 화면이 빽빽합니다.** 말풍선 · 탁자 · 수 띠 · 단추 줄을 400×800에 다 넣으면 탁자가 지금(높이 56%)보다 작아집니다. 강의 패가 읽히는 크기인지 4단계에서 재 봐야 합니다.

## 9. 사용자 결정 (2026-11-21 밤, "마작용어 쓰고 나머지는 권장으로 구현해줘")

1. 용어: **마작 용어**(유효패 · N샹텐 · 텐파이 · 대기). 쉬운 말 설정은 두지 않습니다.
2. 요약 화면: 손패가 있는 패보를 열면 **자동으로 먼저** 띄웁니다.
3. 코치 캐릭터: **두지 않습니다.** 말풍선은 캐릭터 자리 없이 만듭니다.
4. 등급 문턱(10% · 30%)과 이름: **지금 값 그대로**, 요약 화면 도움말에 "임시 기준"이라고 적습니다.
5. 참고값: **접어 둡니다**("참고값" 단추, 안에 "자세히" 후보 표).
6. 자동 재생: **복기 화면에서는 숨기고**, "처음부터 보기"로 들어간 재생 화면에서만 보입니다.
