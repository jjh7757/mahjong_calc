# 설계서 — 외부 AI 를 채점자로: 우리 패효율 등급은 얼마나 맞나 (2026-11-18)

**설계만 — 구현 · 내려받기 · 외부 서비스 호출 없음.** 사용자 결정(11-18): 외부 마작 AI 는 제품에 넣지 않고 채점자로만 쓴다. 라이선스 · 조건은 `docs/license_check.md` 끝 절.

## 1. 무엇을 알고 싶나

`reviewPaifu` 의 등급은 패효율(샹텐 · 유효패)만 본다. 그래서 일부러 물러난 수도 지적으로 찍힌다(계획서 5-3, 설계서 9절). 붙이기 전에 알아야 할 것:

1. **"큰 실수"(샹텐 후퇴)라고 찍은 수를 강한 AI 도 틀렸다고 보나** — 이름을 그대로 둘지, "샹텐 후퇴" 처럼 중립으로 바꿀지.
2. **"실수 · 부정확"(같은 샹텐에서 덜 받음)** 은 어떤가 — 문턱 10 · 30% 가 쓸 만한가.
3. **우리 "최선" 버림이 강한 AI 의 첫째 수와 얼마나 같나** — 초반 · 중반 · 종반, 도라 · 역패가 걸린 손에서 갈리는 정도.
4. 강한 AI 가 "플레이어와 같다" 고 한 수를 우리가 지적한 비율(거짓 지적).

## 2. 재료

| | 것 | 메모 |
| --- | --- | --- |
| 채점자 | Mortal 온라인 리뷰(mjai.ekyu.moe) | 반장전만, tenhou.net/6 JSON 또는 천봉 URL, 결과 HTML(차례마다 플레이어 수 · Mortal 수 · 후보 Q 값 · 확률) |
| 대국 기록 | 온라인 대국 패보(네 명 손패 · 뽑기 · 쯔모기리가 다 있음) | (가) 공개 천봉 패보 몇 판 (나) 사용자의 온라인 대국 — 사용자 결정 |
| 우리 쪽 | 그 기록을 우리 패보 형식(`lib/paifu/paifu.dart`)으로 바꿔 네 자리 각각을 hero 로 `reviewPaifu` | 변환기를 새로 만든다(tenhou.net/6 JSON → 패보 JSON × 4) |

- 규모: 반장 한 판 = 8 ~ 12국 × 네 명 × 등급 매긴 버림 약 8 ~ 12 → **한 판에 버림 300 ~ 500건**, 그중 샹텐 후퇴는 어림 5 ~ 10%. **5 ~ 10판이면 지적 100 ~ 300건** — 외부 서비스를 사람이 쓰는 만큼만 써도 된다.
- 천봉 룰(적 3장 · 쿠이탕 있음)로 둔 판이고 Mortal 도 그 룰로 배웠다 → 매장 룰과 다르다. 이 실험은 "패효율 등급 대 강한 AI" 를 재는 것이지 매장 판을 재는 것이 아니다.

## 3. 흐름

```
온라인 패보(tenhou.net/6 JSON) ─┬─▶ 변환기 ─▶ 우리 패보 × 4 ─▶ reviewPaifu ─▶ 차례별 등급 · 최선
                               └─▶ Mortal 리뷰(자리마다) ─▶ 결과 HTML ─▶ 읽기 ─▶ 차례별 Mortal 수 · 플레이어 수의 확률
                                                         두 줄을 (국 · 자리 · 몇 번째 버림)으로 맞붙여 표로
```

- 맞붙이는 열쇠는 (국, 자리, 그 자리의 몇 번째 버림). 양쪽 다 같은 JSON 에서 나오므로 버린 패가 같은지로 어긋남을 검사한다.
- 비교는 **버림 결정만**(리치 선언 · 울기 · 깡 · 화료 선택은 뺀다). 우리 `forced`(리치 뒤)도 뺀다. `defense`(다른 자리 리치 중)는 따로 센다.
- Mortal 쪽 "틀렸다" 의 정의(재기 전에 고정): **플레이어의 버림이 Mortal 의 첫째 수가 아니고, 그 수의 확률이 10% 미만**(온도 0.1 표시값). 5% · 20% 로도 같이 적는다.

## 4. 기준(안 — 재기 전에 사용자 확정)

| 물음 | 지표 | 판단(안) |
| --- | --- | --- |
| 큰 실수 이름 | 우리 큰 실수 중 Mortal 도 틀렸다고 본 비율 | 80% 이상 → 그대로 / 60 ~ 80% → "샹텐 후퇴" 로 이름만 바꿈 / 60% 미만 → 등급에서 빼고 사실만 표시 |
| 실수 · 부정확 | 같은 비율 | 60% 미만이면 문턱을 올리거나 한 단계로 합침 |
| 거짓 지적 | Mortal 이 플레이어와 같다고 한 버림 중 우리가 부정확 이상으로 찍은 비율 | 10% 이하 |
| 최선 일치 | 우리 최선 버림 = Mortal 첫째 수 | 기준 없음, 순목 구간별로 적기만 |

판 수는 지적이 100건 넘을 때까지(어림 5판), 고른 판은 미리 적고 결과를 본 뒤 바꾸지 않는다.

3. 맞붙이기 · 표 스크립트. 결과는 `docs/metrics.md` 표 15-3 이후, 판단은 `docs/problem_log.md`.

## 8. 결정과 바뀐 흐름 (2026-11-18)

- **사용자 결정: 대국 기록은 사용자의 온라인 대국.** 공개 패보는 받지 않는다.
- 그래서 흐름이 가벼워진다: 사용자가 자기 대국 URL 을 mjai.ekyu.moe 에 직접 넣고 결과 페이지를 넘긴다(저장한 HTML 을 `experiments/paifu_review/mortal/` 에 두거나 결과 URL). 예시 결과 페이지에는 국마다 **tenhou.net/6 JSON 로그 블록**이 같이 들어 있어, 그 한 페이지에서 대국 기록(→ 변환기 → `reviewPaifu`)과 Mortal 의 수를 둘 다 얻을 수 있다 — 실제 페이지로 확인 전.
- 이 세션이 외부 서비스에 양식을 넣거나 패보를 내려받는 일은 없다.
- 순서: ① 먼저 **한 판**의 결과 페이지를 받아 기계로 읽히는지 본다(Classic 화면과 KillerDucky 화면 중 어느 쪽이 읽기 쉬운지 포함) ② 읽히면 변환기 · 읽기 · 맞붙이기를 만든다 ③ 나머지 판.
- 판 고르기(미리 적음): **가장 최근 4인 반장전부터 차례로**, 결과를 보고 빼지 않는다. 한 페이지는 한 자리만 리뷰하므로 사용자 자리만 보면 한 판에 등급 매긴 버림이 어림 80 ~ 120건 — 지적 100건을 채우려면 판을 늘리거나(10 ~ 20판) 같은 판의 네 자리를 다 리뷰한다(판당 4페이지). 첫 판을 보고 정한다.
- 아직 모르는 것: 플랫폼(천봉 / 작혼), 반장전 기록이 있는지.

## 9. 매장(오프라인) 패보를 천봉 형식 JSON 으로 바꿔 넣기 — 되는가 (2026-11-18, 사용자 질문 · 분석만)

**된다 — 단, 안 보이는 부분을 지어서 채워야 하고 표본이 아주 작다.**

- 천봉 형식(tenhou.net/6 JSON)은 국마다 네 명의 시작 손패 · 뽑은 패 전부 · 버림 전부 · 점수 · 결과를 요구한다. 매장 패보에는 hero 한 명의 손패와 네 자리 버림 · 울기만 있다.
- 리뷰 엔진은 **지정한 한 사람 시점**으로만 본다(자기 손패 · 자기가 뽑은 패 · 모두의 버림 · 울기 · 도라 · 점수). 그래서 다른 세 사람의 손패 · 뽑은 패는 **아직 안 보인 패로 앞뒤가 맞게만 채우면** hero 의 판단 평가에는 영향이 없을 것으로 본다 — 엔진 입력에 정말 안 들어가는지는 변환 도구 소스를 읽어 확인해야 한다(확인 전).

| 빠진 것 | 채우는 법 | 잃는 것 |
| --- | --- | --- |
| 다른 세 사람의 시작 손패 · 뽑은 패 | 안 보인 패에서 뽑아, 각자의 버림 · 울기와 앞뒤가 맞게 거꾸로 만든다 | (엔진이 안 본다면) 없음 |
| hero 의 첫 1 ~ 2순 손패(녹화 전) | 그 순을 쯔모기리로 가정하면 시작 손패 = 2순째 손패 | 그 순의 평가(어차피 우리도 "손패 모름" 으로 안 매김) |
| 다른 자리의 쯔모기리 / 손에서 냄(거의 null) | 한쪽으로 가정(전부 손에서 냄) | **수비 · 밀기 판단의 재료가 왜곡됨** — 엔진은 이 정보를 본다 |
| 점수 상황 · 공탁 | 패보에 없음 → 25,000 균등 · 공탁 0 으로 가정(그날 대국 기록에서 옮길 수 있으면 옮김) | 순위를 건 판단(오라스 등)이 왜곡됨 |
| 룰 | 매장 룰 ≠ 엔진이 배운 천봉 룰 | 적도라 · 쿠이탕 등이 다르면 평가가 어긋남 |

- **표본:** 손패가 적힌 판은 r11 · r12 · r17 · r19 넷, hero 가 판마다 다른 자리(그 판의 화료자)다. 등급 매긴 버림 28 + 수비 2 = **30건, 지적은 5건**(큰 실수 3 · 실수 1 · 부정확 1). "큰 실수 이름이 맞나" 를 비율로 답하기엔 턱없이 모자라고, **"우리 판의 그 다섯 수를 강한 AI 는 어떻게 보나" 를 하나씩 보는 용도**로는 쓸 만하다.
- 반장전 조건: 국마다 hero 가 달라 한 국짜리 로그 넷을 따로 넣게 된다 — 한 국만 든 사용자 로그를 서비스가 받는지는 넣어 봐야 안다.
- 그래서 둘을 나눈다: ① **매장 4판 = 낱낱이 보기**(변환기 `우리 패보 → tenhou.net/6 JSON`, 지어 채운 부분은 note 에 밝힘) ② **비율로 답하기 = 온라인 대국 기록**(8절). 사용자에게 온라인 기록이 없으면 ②는 공개 패보(6절 1번)로 돌아간다.
- 손패 기록 자동화가 풀려 매장 판이 쌓이면 ①이 그대로 ②가 된다 — 변환기는 그때도 쓴다.

## 부록 B. 변환기 규격 — 우리 패보 한 국 → tenhou.net/6 JSON (2026-11-18)

형식은 `Equim-chan/mjai-reviewer` 의 `convlog`(tenhou → mjai 변환) 소스를 읽어 확인한 것이다(`json_scheme.rs` · `conv.rs` · `tenhou/log.rs` · `tenhou/tile.rs`). 그 변환이 오류 없이 받아야 리뷰가 돈다.

### B-1. 출력 꼴

```
{ "title": ["", ""], "name": ["A", "B", "C", "D"], "rule": {"disp": "般南喰赤", "aka": 1},
  "log": [ [ [kyoku_num, honba, kyotaku], [점수 4], [도라 표시패…], [뒷도라 표시패…],
             배패0[13], 뽑기0[…], 버림0[…],  배패1, 뽑기1, 버림1,  배패2, 뽑기2, 버림2,  배패3, 뽑기3, 버림3,
             [결과…] ] ] }
```

- **패 번호:** 만 11~19 · 통 21~29 · 삭 31~39 · 자패 41~47(동 남 서 북 백 발 중) · 적5 는 51(만) · 52(통) · 53(삭). 다른 수는 변환기가 거절한다.
- **`rule.disp`:** `東` 이나 `East` 가 들어가면 동풍전, `三` 이나 `3-Player` 가 들어가면 거절 → 반장전으로 읽히게 `般南喰赤`. `aka` 1 = 적5 있음. 이름은 A~D(실제 이름 안 씀).
- **`kyoku_num`:** (장풍 0~3) × 4 + (국 번호 − 1). 친 = `kyoku_num % 4` 번 자리, 장풍 = `kyoku_num / 4`.
- **자리 맞춤:** 우리 자리 s → 천봉 자리 `(s − dealer + kyoku_num % 4) mod 4`(차례 순서 유지, 친이 `kyoku_num % 4` 에 오게). **리뷰 대상 = hero 의 천봉 자리.**
- **뽑기 목록:** 그 사람이 패산에서 뽑은 패(수)와 울기(문자열)가 일어난 순서대로.
  - 치: `"c" + 가져온 패 + 내 패 둘`(예 `c275226`). 늘 윗자리(왼쪽, `(나 + 3) % 4`)에서.
  - 퐁: `p` 의 자리로 누구 것인지 — 윗자리 `pTTTTTT` · 맞은편 `TTpTTTT` · 아랫자리 `TTTTpTT`. `p` 바로 뒤가 가져온 패.
  - 깡(대명깡 `m`, 버림 목록의 안깡 `a` · 가깡 `k`)은 **이번 변환기에서 지원하지 않는다**(만나면 오류).
- **버림 목록:** 버린 패(수). **60 = 쯔모기리**(뽑기 목록에는 60 을 쓰면 안 됨). 리치 선언은 `"r" + 패`(쯔모기리 리치는 `"r60"`). 수로 적은 버림은 "손에서 냄" 으로 읽힌다.
- **끝:** 론 = 방총자의 버림 뒤 모두의 뽑기 목록이 다 쓰인 상태, 쯔모 = 화료자의 뽑기가 버림보다 하나 많음, 유국 = 마지막 버림 뒤 뽑기가 다 쓰임.
- **결과:** 화료 `["和了", [점수 변화 4], [화료자, 방총자(쯔모면 화료자), 화료자, ""]]`, 그 밖 `["流局", [0,0,0,0]]`. 점수 변화는 0 으로 둔다(역 · 점수 문자열은 변환기가 안 본다). 결과가 없는 패보(`result` null)는 `流局`.
- 버림 뒤 다음 차례: 기본은 다음 자리, 누군가의 다음 뽑기 항목이 그 버림을 가져가는 울기면 그 자리.

### B-2. 지어 채우는 규칙(전부 `assumptions` 목록에 사람 말로 남긴다)

1. **점수:** 인자로 안 주면 네 자리 25,000. 공탁 0.
2. **hero 의 앞 순 손패가 없을 때:** 첫 "손패가 적힌 뽑기 사건" 앞의 hero 차례는 전부 쯔모기리로 본다(뽑은 패 = 버린 패, 버림은 60) → 배패 = 그 첫 손패. 손패가 적힌 뒤로 hero 의 뽑기 · 손패가 한 번이라도 비면 **오류**(지어 채우지 않는다). hero 손패가 아예 없는 판도 오류.
3. **hero 의 차례마다 검사:** 손패 + 뽑은 패 − 버린 패 = 다음에 적힌 손패. 어긋나면 오류.
4. **hero 버림 표기:** 버린 패가 뽑은 패와 같은 종류 · 같은 적5 여부이고 패보의 `tsumogiri` 가 false 가 아니면 60, 아니면 수.
5. **다른 자리의 쯔모기리 표시:** 패보에 true → 60, false → 수(손에서 냄), **null → 정책 인자 `unknownAs`(tedashi 기본 / tsumogiri)**. 울기 바로 뒤 버림은 늘 손에서 냄. 리치 선언 뒤 버림은 60.
6. **다른 자리의 손패 · 뽑은 패(안 보이는 것):** 안 보인 패 더미 = 136장(수패 5 는 적5 한 장 + 보통 세 장) − hero 가 쥐었던 모든 패 − 네 자리 버림 − 모든 울기 묶음 − 도라 · 뒷도라 표시패 − (다른 자리가 화료했고 끝 손패가 적혀 있으면 그 손패 · 화료패). 더미가 음수가 되는 종류가 있으면 오류(패보가 5장째를 쓴 것).
   - 그 자리의 **끝 손패**를 더미에서 뽑는다(`13 − 3 × 울기 수` 장, 시드 고정 난수. 화료자면 적힌 끝 손패).
   - 사건을 **거꾸로** 되감아 배패를 만든다: 버림 되돌리기(손에 그 패를 더함) → 그 차례의 뽑기 되돌리기(쯔모기리면 그 패를 빼고 그것이 뽑은 패, 손에서 냄이면 손의 다른 패 하나를 빼서 그것을 뽑은 패로 — 고르는 순서는 정해 둠) → 울기 되돌리기(묶음에서 가져온 패를 뺀 나머지를 손에 더함). 다 되감으면 13장.
   - 울기 묶음이 "가져간 한 장" 만 적힌 경우(종류 모름)는 오류.
7. **도라:** `dora_indicators` 그대로(첫 장이 도라 표시패로 쓰이고, 나머지는 깡이 없으면 안 쓰인다), `ura_indicators` 그대로. 패보의 표시패 두 장이 도라 + 뒷도라로 섞여 적힌 판이 있을 수 있다 — 구분이 없어 첫 장을 도라로 본다(assumptions 에 적음).
