# 실험 계획서 — 2040 으로 줄인 크롭을 섞어 학습한 분류기 clsH (2026-11-12)

사용자 요청(11-12 저녁): "2040 크기로 줄인 크롭을 섞어 학습한 분류기를 만들고 싶다. 계획서 작성 후 실행은 Opus 5.5 에 맡기고 너는 검토."

- 실행: 단계마다 Opus 5.5(높음) 에이전트. 자료 눈 확인은 Opus 5.5(중간) 여러 대.
- 검토: 이 계획을 쓴 Fable 세션. 단계마다 수치를 직접 다시 재고 "**검토**" 줄을 단다.
- 대상: 겹쳐 보기(`ondevice.overlay`, 사본 앱 `dev.jjh.mahjong_calc.ondevice`)의 분류 단계. 서버·운영 모델·원래 앱은 안 바꾼다. 커밋 안 함.

> **결론(11-12 17시): 학습 안 함. 키워 읽기만으로 2040 을 4080 만큼 읽는다 → 키워 읽기가 채택 후보.**
> - 사용자 결정(같은 날, 0단계 실행 뒤·사용자와 이 세션이 그 값을 보기 전): "학습 없이 키우기만 따로 재 보고 4080 분류만큼 나오면 추가 학습하지 않는다. 별로면 넣기 전에 키우지 않고도 읽도록 학습한다." → 4-3 결정표를 아래 "4-3a" 로 바꿈. "4080 만큼" 의 문턱은 재기 전에 적은 c1 그대로.
> - 0단계 값(metrics 표 4-9): 안 배운 조합 원본 25/40·517/528 → 2040 그대로 14·465 → **2040 키워 읽기 24·518**. c1(패 ≥ 512, 장면 ≥ 22) 통과.
> - 그래서 1단계 뒷부분(독립 검토)·2단계(학습)는 하지 않았다. clsH·clsHc 는 만들지 않았다.

## 0. 요약

- 태블릿은 헤드 녹화 2040(2×2 평균, JPEG 85)을 계속 받고 있다. 겹쳐 보기를 이 프레임으로 돌리면 4080 을 따로 받을 필요가 없다.
- 운영 분류기(cls6)로는 안 됐다(metrics 표 4-8): 장면 32 → 10/40, 패 523 → 463/528. 틀린 것은 패 종류, 그중 만수 한자.
- 이 실험: 학습 크롭 1,548장의 원본 사진을 2040 으로 줄여 같은 상자로 다시 자른 "2040 사본" 을 원본 크롭과 섞어, cls6 에서 이어 학습한 **clsH** 를 만든다.
- 같이 재는 것 둘(학습의 몫을 따로 보려고):
  - **K(키워 읽기, 학습 없음):** 겹쳐 보기는 크롭을 줄이기만 한다(`_tensor`). 2040 에선 패가 128 칸 안에 절반 크기로 들어간다. 서버 `read_small` 처럼 긴 변 96 으로 키워 읽으면 cls6 그대로도 될 수 있다.
  - **clsHc(대조군):** 2040 사본 없이 같은 횟수만 이어 학습. clsH 의 이득이 사본 몫인지 추가 학습 몫인지 가른다.
- 합격 기준은 4절에 학습 전에 적는다. 설정당 한 번, 결과를 본 뒤 기준·세트를 안 바꾼다.

## 1. 배경

### 1-1. 지금 구조

- 겹쳐 보기 분류: `reader.detect_full` 상자 → `lr.cut` → 방향 후보마다 `reader.probs`. `probs` 의 `_tensor` 는 `thumbnail(128)` 로 줄이기만 하고 회색 128 칸 가운데에 붙인다.
- 4080 사진의 패 크롭 긴 변은 약 100~200px(학습 크롭 중앙 141px) → 128 칸을 채운다. 2040 에선 50~100px → 칸의 절반쯤.
- 운영 분류기 cls6(= 서버 `tile-cls-mnv3s-v3.onnx`): 합성 사전학습 + 실제 축 크롭 1,548장(B·C·D + 10-31, `data/index.json` 259 + `review.extra()` 1,289) 미세 조정, `AUG_R180`. 나눔 `cls6_{bcd,am,pm,all}`.
- 서버에는 작은 패용 `read_small`(긴 변 `SMALL_TILE` = 96 으로 BICUBIC 키움)이 이미 있다. 표시패·프레임 읽기만 쓰고 겹쳐 보기는 안 쓴다.

### 1-2. 이미 아는 숫자

| 근거 | 조건 | 값 |
| --- | --- | --- |
| 표 4-8 | 겹쳐 보기 prod, 원본 / 2040 | 장면 32 / 10 (/40), 패 523 / 463 (/528), 역할·주인 1,366 / 1,364 |
| 표 12-1 (나) | 화료 사진 강 94장, `read_small`(키워 읽기), 4080 / 2040 | 93 / 93 (고친 정답 94 / 94) |
| 표 12-3 | clsF_A(1020 프레임 크롭을 키워 넣어 이어 학습) | 실제 1020 프레임 오독 166 → 12, 12MP 강 94/94 유지 |
| 표 1-150·1-154 | cls6 낱장 홀드아웃(축 크롭) | 1,328/1,329 |

### 1-3. 가설(재기 전에 적음 — 사실 아님)

- 2040 실패의 큰 몫은 "패가 칸 안에 작게 들어가는 것" 이고, 키워 읽기(K)만으로 상당 부분 돌아올 수 있다. 근거는 표 12-1 의 2040 93/94(키워 읽기 경로)와 표 4-8 의 463/528(안 키움)의 차이뿐이라 같은 조건으로 재 봐야 안다.
- 그래도 학습을 한다(사용자 요청). 0단계 값이 무엇이든 1·2단계는 진행하고, 결론을 결정표(4-3)로 가른다.

### 1-4. 이 실험이 답할 질문

1. 2040 프레임으로 겹쳐 보기를 4080 만큼 읽게 만들 수 있나.
2. 그러려면 모델을 바꿔야 하나, 키워 읽기만으로 되나.
3. 2040 사본을 섞은 모델이 4080 입력을 잃지 않나(한 모델로 둘 다).

## 2. 후보

| 이름 | 분류기 | 읽기 | 뜻 |
| --- | --- | --- | --- |
| A0 | cls6 | 그대로 | 지금(표 4-8) |
| K | cls6 | 키워 읽기 | 학습 없는 대조군 |
| H0 | clsH | 그대로 | 모델만 바꾸면 되는지(참고) |
| **HK** | **clsH** | **키워 읽기** | **판정 후보(하나)** |
| C | clsHc | 키워 읽기 | 대조군 — 사본 없이 같은 횟수 이어 학습(참고) |

- 판정 후보를 HK 로 정한 이유: 서버가 작은 패에 이미 쓰는 규칙(`read_small`)과 같고, 입력 크기 차를 읽기 쪽에서 먼저 줄인 뒤 남는 화질 차만 모델이 배우게 하는 쪽이 4080 입력을 덜 건드린다.
- **키워 읽기 정의(채점·학습·기기 공통):** 분류기에 넣는 크롭의 긴 변이 96px(`lr.SMALL_TILE`) 미만이면 긴 변 96 으로 BICUBIC 키운다. 96 이상이면 그대로. 4080 크롭은 거의 다 96 이상이라 안 바뀐다.

## 3. 자료·학습 설정

### 3-1. 2040 사본 크롭

- 재료: cls6 미세 조정에 쓴 실제 크롭 1,548장 전부(`data/index.json` + `review.extra()`, 白 채움 크롭 포함). 라벨·나눔(`part`/`half`)은 원본 것을 그대로 물려받는다. 새 라벨 없음.
- 만드는 법: 크롭의 원본 사진(EXIF 방향 반영)을 `overlay_score.shrink(data, 2040)` 과 **같은 함수**로 줄인다(긴 변 ÷ 2040 이 정수에 가까우면 `Image.reduce` n×n 평균, 아니면 BOX, JPEG 85 로 저장했다 다시 읽음). 원본 상자에 실제 줄인 비율을 곱해 원본 크롭과 같은 방법(여유·돌림 `turn` 포함)으로 자른다.
  - 원본이 이미 긴 변 2040 이하인 사진(B·C·D 일부)은 줄지 않는다 → 그 크롭은 사본을 만들지 않고 수를 적는다.
- **자르기 재현 확인(사본을 만들기 전):** 같은 코드로 원본 크기 사진에서 다시 자른 크롭이 저장된 원본 크롭과 같은지(크기 같음 + 평균 화소 차 ≤ 2) 전부 대조한다. 안 맞는 크롭은 수·원인을 적고 사본에서 뺀다. 안 맞는 것이 5% 를 넘으면 멈추고 보고.
- 저장: `experiments/tile_classifier/data/half/`(`crops/`, `index.json` — 원본 `file`·`tile`·나눔·원본 상자·줄인 비율·사본 크기), 확인 그림 `sheets/`(원본 | 2040 사본 | 키운 사본 나란히, 종류별). 커밋 안 함(.gitignore 대상).
- 스크립트: `experiments/tile_classifier/half_crops.py build|check|sheets`.

### 3-2. 독립 검토(학습 전)

- Opus 5.5(중간) 에이전트 2대가 확인 그림을 반씩 나눠 본다. 볼 것: 사본이 원본과 같은 패인가(옆 패로 밀림·반쪽·빈 칸), 방향이 같은가. 라벨은 안 고치고 뺄 후보만 보고서로(`data/half/review_P{1,2}.json`).
- Fable 세션이 수(원본 1,548 = 사본 + 안 줄어든 것 + 뺀 것), 나눔 일치, 뺄 후보 표본을 직접 본 뒤 반영한다.

### 3-3. 학습 설정 (clsF 와 같게, 바뀌는 것만)

- 스크립트: `experiments/tile_classifier/half_train.py train|holdout`(clsF 의 `frame_train.cmd_train` 방식 — `train.train(pool, images, seed, aug, init=)`, 20 에폭).
- 시작 가중치: 나눔마다 `data/cls6_<part>.pt`(그 나눔 사진을 안 배운 것). `all` 은 `cls6_all.pt`.
- 묶음: cls6 와 같은 규칙(`train.main_synth` 의 pool — `bcd` 는 `half == "other"` 도 뺌). **2040 사본은 원본과 같은 나눔에만 들어간다**(시험 나눔 사진의 사본이 학습에 들면 누수).
- clsH: 원본 크롭 + 2040 사본. 사본은 뽑힐 때마다 절반은 그대로(작은 채로), 절반은 키워 읽기 규칙으로 키운 뒤 원본과 같은 `AUG_R180`. 원본 크롭은 지금과 같게.
- clsHc: 원본 크롭만, 그 밖은 같음.
- 씨드 30(둘 다). 모델 `server_bench/models/clsH_{bcd,am,pm,all}.onnx`·`clsHc_{…}.onnx`, 가중치 `data/clsH*.pt`. 두 번째 분류기(`_s1`)는 안 만든다.
- 누수 확인을 코드로: 나눔마다 학습 묶음의 사진 이름과 시험 나눔 사진 이름의 교집합이 0 임을 학습 기록(`data/half/train_<이름>.json`)에 남긴다.

## 4. 평가와 합격 기준 (학습 전에 적음)

### 4-1. 평가 세트

- **끝단(겹쳐 보기):** 테스트 세트 원본 40장(`sg.eval_scenes()`: B·C·D 6 + 10-31 20 + 11-07 14). `overlay_score.py`, 입력 원본 / `--scale 2040`.
  - **fold 조합이 주 판정**: B·C·D·10-31 은 그 사진을 안 배운 나눔 분류기, 11-07 은 `_all`(11-07 사진은 cls6·clsH 어느 학습에도 없다). 검출·역할 모델은 지금 fold 조합 그대로.
  - prod 조합(전부 `_all`)은 참고 — B·C·D·10-31 은 학습에 든 사진이라 낙관적.
  - 세트별(B·C·D / 10-31 / 11-07)을 같이 적는다. 날짜가 갈린 것은 11-07 뿐이다.
- **낱장(홀드아웃 크롭):** `train.holdout_eval` 의 축 크롭 1,329장(나눔 bcd·am·pm, `other` 뺌)을 그 나눔 분류기로. 세 벌: 원본 / 2040 사본 그대로 / 2040 사본 키움.
- **참고:** 11-07 오후 실제 1020 프레임(표 12-3 a 줄, `FS_CLS=<onnx> frame_split.py frames`) — cls6 오독 166, clsF_A 12.

### 4-2. 합격 기준

기준값(cls6)은 0단계에서 같은 도구로 다시 잰 값을 쓴다(학습 전에 metrics 표에 적음).

| # | 기준 | 뜻 |
| --- | --- | --- |
| c1 | 끝단 2040·fold·키워 읽기: 패 맞음 ≥ (원본·fold·cls6·그대로 패 맞음) − 5, 장면 맞음 ≥ (같은 조건 장면) − 3 | 2040 을 4080 만큼 읽는다 |
| c2 | 끝단 원본·fold·그대로: clsH 패 ≥ cls6 − 2, 장면 ≥ cls6 − 1. 낱장 원본 1,329장: clsH 틀림 ≤ cls6 틀림 + 2, 적5 ↔ 5 혼동이 cls6 보다 늘지 않음 | 4080 입력을 잃지 않는다 |
| c3 | 낱장 2040 사본 키움: clsH 틀림 ≤ cls6 틀림 ÷ 2. cls6 틀림이 10 미만이면 "여지 없음" 으로 적고 판정 안 함 | 학습이 읽기를 낫게 한다 |
| (참고) | C(clsHc) 의 같은 값, H0·A0 그대로 읽기, prod 조합, 1020 실제 프레임, 틀린 패 혼동 상위 | — |

c1 은 K(cls6)와 HK(clsH) 둘 다에 매긴다.

### 4-3. 결정표

| K 가 c1 | HK 가 c1 | HK 가 c2 | c3 | 결론 |
| --- | --- | --- | --- | --- |
| ✓ | — | — | ✗ 또는 여지 없음 | **키워 읽기만** 채택 후보(모델 cls6 그대로). clsH 미채택 |
| ✓ | ✓ | ✓ | ✓ | 둘 다 됨. clsH + 키워 읽기 채택 후보(낱장 이득), 고르는 것은 사용자 |
| ✗ | ✓ | ✓ | ✓ | **clsH + 키워 읽기** 채택 후보 |
| ✗ | ✓ | ✗ | ✓ | 2040 전용 후보(겹쳐 보기에만 따로 싣는 모델). 한 모델 겸용은 아님 |
| ✗ | ✗ | — | — | 미채택. 겹쳐 보기는 4080 유지 |

그 밖의 조합은 "미채택" 으로 적고 이유를 쓴다. 채택 후보가 나와도 기기 반영(3단계)은 사용자 결정 뒤.

### 4-3a. 결정표 — 사용자 결정으로 바뀜(11-12, 위 4-3 을 대신함)

| K(cls6 + 키워 읽기)가 c1 | 할 일 |
| --- | --- |
| ✓ | **학습 안 함.** 키워 읽기가 채택 후보(모델 cls6 그대로) |
| ✗ | 학습한다. 판정 후보는 **H0(clsH, 키우지 않고 그대로 읽기)** — 2040 사본은 작은 채로만 넣는다(3-3 의 "절반은 키움" 을 뺌). c1 을 "2040·fold·그대로" 로, c3 을 "낱장 2040 사본 그대로" 로 매긴다. c2 는 그대로 |

- c1 문턱(패 −5·장면 −3)은 재기 전에 적은 값 그대로다. 사용자 결정은 0단계 실행(16:40~16:43)이 끝난 뒤에 왔지만, 그 값을 사용자·이 세션이 보기 전이었다.
- 결과: K 가 c1 통과 → 첫 줄.

### 4-4. 금지

- 결과를 본 뒤 기준·평가 세트·씨드·에폭을 바꾸지 않는다. 다시 학습하지 않는다(코드 오류로 중단된 실행 제외 — 그 경우 무엇이 틀렸는지 적는다).
- 평가는 B·C·D + 10-31 + 11-07 원본과 그 사본만. 가림·사용자 문제 사진은 `sg.eval_scenes()` 가 뺀 그대로.
- 11-07 사진·프레임, 10-24·A·E 사진을 학습에 넣지 않는다.
- 앱·서버 운영 코드를 바꾸지 않는다(0~2단계). 채점 쪽 키워 읽기는 채점 스크립트 안에서만.
- 같은 시각에 나란히 돌린 것만 전·후로 적는다. 다른 세션의 `flutter drive`·측정 서버를 빌리지 않는다.

## 5. 단계

단계가 끝나면 실행 에이전트가 이 문서의 "진행:" 줄, `docs/metrics.md` 해당 표를 채운다. 검토는 그 아래 "**검토**" 로 덧붙인다.

### 0단계. 채점 도구 + 기준선(학습 없음) — 1시간

## 6. 위험과 한계

- **2040 은 흉내다.** 헤드 녹화는 12MP NV21 을 2×2 평균한 뒤 JPEG 85, 이 실험은 JPEG 사진을 풀어 2×2 평균한 뒤 JPEG 85 다. 실제 2040 프레임 확인은 매장 녹화(11-14)가 있어야 한다.
- 화료 사진은 판이 끝난 장면이다. 판 중 프레임(손·가림·움직임)은 안 잰다.
- B·C·D·10-31 은 나눔으로 사진은 갈리지만 같은 날·같은 패 세트가 학습에 있다. 날짜가 갈린 것은 11-07 14장(패 185장)뿐이라 작다.
- 장면 수 40 은 장면 맞음 1~2 차이를 가르지 못한다. 그래서 낱장 1,329장을 같이 본다.
- clsH 가 확신도 분포를 바꾸면 확신도 문턱을 쓰는 규칙(겹쳐 보기엔 지금 없음, 서버 가드레일·패보 v2 에는 있음)과 안 맞을 수 있다 — 서버에 넣지 않는 이유 중 하나.
- 끝단 값에는 검출·역할 오류가 섞인다(표 4-8 에서 역할·주인은 2040 에서도 거의 같았다).

- 검출기·역할 모델 학습, 합성 사전학습 다시 하기.
