# 계획서 — 버림 기록기의 헛 칸 처리 (2026-11-21 밤, 재기 전에 적음)

사용자 "기록기가 왜 그렇게 적었는지 확인해봐" → "고쳐서 재기". 원인 추적은 `docs/problem_log.md` 68번 끝 덧붙임 · `docs/metrics.md` 표 12-29 메모, 추적 도구 `experiments/paifu_frames/results/r19_check/trace.dart`.

## 1. 고치려는 것

r19(11-14 2반장 남4국) 오른쪽 자리에서, 놓이는 중인 패가 제자리 밖에서 확신도 0.40 으로 한 장면 잡혀 **헛 칸**이 생겼다. 한 장면짜리 칸은 출력 때만 걸러지고 칸 목록에는 남아서,

1. "마지막 칸만 안 보이면 울려 나감" 이 "두 칸이 안 보임" 이 되어 꺼지고(6삭 퐁 놓침 · 6삭 칸이 다음 패와 합쳐짐),
2. 가린 장면 뒤 "혼자 옮겨진 패" 규칙으로 진짜 패를 물려받아 진짜 칸이 된다(강에 한 장 더).

## 2. 후보 (모두 `DiscardRecorderConfig` 의 새 값 — 기본값은 지금 동작)

| | 이름 | 규칙 |
| --- | --- | --- |
| A | 지금 | 그대로 |
| B | `minNewSlotConf = 0.5` | 어느 칸에도 안 붙은 상자가 확신도 0.5 미만이면 **새 칸을 만들지도, 안 보이는 칸을 옮기지도 않는다.** 이미 있는 칸에 붙는 것 · 이동량 맞춤에는 그대로 쓴다(놓여 있는 패가 흐리게 읽힌 장면에서 칸을 잃지 않게). |
| C | `dropUnconfirmed = true` | 한 장면만 보인 칸(n = 1)이 그 자리의 마지막 칸이 아니게 되면 **확정 안 된 칸**으로 본다 — ① "안 보이는 칸" 을 셀 때 빼고 ② 그 칸이 안 보이는데 같은 자리의 다른 칸은 하나라도 붙은 장면이 `streakNeed` 번 이어지면 칸 목록에서 지운다. 마지막 칸은 지금 규칙 그대로(버리자마자 가져가 한 장면만 보인 진짜 버림은 늘 그 자리의 마지막 칸이다). |
| B+C | 둘 다 | |

- B 는 원인(놓이는 중인 패가 낮은 확신도로 잡힘)을 입구에서 막고, C 는 확신도와 상관없이 "뒤 칸에 밀린 한 장면짜리 칸" 을 치운다. 서로 다른 종류를 막는다.
- B 의 0.5 는 고정한다. 0.3 · 0.7 은 민감도로 적기만 하고 고르는 데 쓰지 않는다.
- 안 건드리는 것: 가린 장면에서 이동량 맞춤이 칸을 옮기는 문제(원인 사슬의 ③), 출력의 시각 다시 붙이기(④). 이번 범위 밖.

## 3. 재는 판 · 지표

표 12-36 · 12-37 과 같은 13판 · 같은 저장분 · 같은 재생(`replay_recorder.dart overlay`): 11-07 R2 · R3a · R4, 11-14 r11 과 2 · 3반장 아홉 판. **13판 모두 이미 본 판이다 — 통과해도 개발 판 숫자.** 11-07 세 판은 테스트 세트 날짜, 11-14 는 "평가 밖".

먼저 A 를 다시 돌려 표 12-36 · 12-37 의 "후" 줄(울려 나감 16 · 헛 0 · 잃음 0, 강에 남은 패 421/421, 헛 버림 4, 가져간 자리 15/15 · 묶음 14/14, 11-07 강 100/100 · 울려 나감 6/6)과 같은지 본다. 다르면 멈추고 보고(기록기가 그 뒤 바뀌었을 수 있다).

조건마다:
1. 강에 남은 패 — 순서까지 맞음 / 정답 수, 헛 버림 수, 빠짐 수(판별).
2. 울려 나감 — 낸 수 · 헛 · 진짜를 잃음, 가져간 자리 · 묶음 맞음. r19 의 6삭 퐁(영상으로 확인, 위쪽이 자리 오른쪽에서)은 새 정답 1건으로 더한다.
3. 눕힌 패(리치 선언패) — 지금 채점에 있는 대로.
4. **차례 규칙 위반 수**(새 지표, 정답 없이 셈): 기록을 패보로 바꿨을 때 "버림 뒤 다음 자리, 울기면 운 자리" 가 깨지는 곳의 수(판별). 손패 주인 뽑기 사건은 빼고 버림 · 울기만.
5. r19 오른쪽이 영상 정답과 같은가: `1z 4z 3z 9s 6s(울려 나감 · 위쪽 퐁) 9s 1m 1s 4s 1p`, 처음 보인 시각이 14:20:45 · 14:21:09 · 14:21:33 · 14:22:27 · 14:23:03 · 14:23:39 … 에서 ±6초.

## 4. 판정 (결과 보기 전에 정함)

- **통과:** ① 1 · 2 의 맞음이 A 보다 하나도 줄지 않고 빠짐 0 유지 ② 헛 버림 · 헛 울려 나감이 A 보다 늘지 않음 ③ r19 오른쪽이 영상 정답과 같음(5).
- **채택:** 통과한 조건 가운데 (헛 버림 + 차례 규칙 위반)의 13판 합이 가장 작은 것. 같으면 바꾸는 규칙이 적은 쪽(B → C → B+C 순).
- 아무것도 통과 못 하면 기록기는 그대로 두고, r19 는 패보를 직접 고친 것으로만 남긴다.
- 채택해도 운영 배포 · APK 는 이 계획에 없다(사용자 결정).

## 5. 채택되면 따라오는 일

- 기본값을 켜고 `test/discard_recorder_test.dart` 에 사례 시험.
- `experiments/paifu_frames/paifu_examples.py` 의 r19 수정 표(RETILE_DISCARDS · MISSED_DISCARDS · EXTRA_DISCARDS · MISSED_CALLS 의 r19 항목)는 **지금 기록기 출력의 번호**에 걸려 있다 — 예시를 다시 만들 때는 빼야 한다. 예시 재생성은 이 계획에 없다.

## 6. 한계

- 헛 칸 사례는 13판에 r19 하나뿐이다. 규칙을 그 한 판을 보고 만든다.
- 안 본 판이 없다. 다음 매장 판에서 다시 재기 전에는 "통과" 가 아니다.
- 거치 화면 실시간 · 태블릿 판독(표 12-41 · 12-42)은 다시 재지 않는다.
