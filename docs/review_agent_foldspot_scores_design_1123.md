# 설계서 — 복기 에이전트에 "보통 접는 자리" 와 점수 상황 사실 넣기 (지시문 a7 · 사실표 3) (2026-11-23 밤)

사용자 "복기 에이전트 기능에 대해 어떻게 평가하니" → 약점 3("말할 수 있는 내용이 얕다 — 밀기 · 접기는 판정 안 함 · 점수 상황 없음") → "2번부터 진행해줘"(= 밀기 · 접기와 점수 상황을 사실표에 넣기). 앞 흐름: `docs/push_fold_design_1122.md`(R3 시험 통과 · 앱 화면 반영, 에이전트 `fold_spot` 은 null 로 남김), `docs/paifu_review_agent_app_design_1122.md`(질문 창 · a6 운영), metrics 표 16-15 · 15-10 · 15-11, problem_log 74 · 80.

형식: 설계 · 검토 Fable 세션, 구현 Opus 5.5 높음 하위 에이전트. 실제 Gemini 호출 · 커밋 · 운영 배포는 사용자가 말한 뒤.

## 1. 만드는 것 · 안 만드는 것

| 만든다 | 안 만든다 |
| --- | --- |
| 사실표의 `fold_spot` 을 "보통 접는 자리" 사실(객체)로 채움 — 에이전트가 그 사실과 근거 숫자를 말함 | "접었어야 했다 · 밀면 안 됐다 · 잘 접었다" 같은 판정 · 평가 말(지표 3 이 65.2% < 70% — 표 16-15) |
| 사실표에 국 시작 점수 · 순위 · 점수 차 · 공탁(`game.scores`) — 에이전트가 그 값을 읽어 말함 | 점수로 밀기 · 접기를 판단, 뒤집는 데 필요한 타점 계산, 오라스 조건 계산 |
| 판 전체에서 접는 자리를 찾는 `find_turns` 조건 | 2샹텐 이하 · 울기 상대의 접는 자리(규칙 R3 밖) |

## 2. 사실표 3 (앱 `lib/paifu/agent_facts.dart`, `agentFactsVersion = 3`)

판 2 와 다른 곳은 둘뿐이다.

### 2-1. `turns[i].defense.fold_spot`

- `null` 또는 `{"shanten": 3, "ai_fold_pct": 94}`.
- 값이 있는 때: 그 차례의 `TurnReview.pushFold` 가 null 이 아닐 때(규칙 R3 — 리치를 받았고 · 버리기 전 3샹텐 이상 · 효율대로 버릴 패의 위험이 가장 안전한 패보다 5%p 이상 높음). `shanten` = `pushFold.shanten`, `ai_fold_pct` = `pushFoldAiFoldPct`(94).
- **플레이어가 밀었나 접었나는 넣지 않는다** — 이미 있는 `stance`(pushed · folded · between)를 쓴다. 앱 화면의 `PushFoldAction` 은 위험 차만 보고(2%p 미만이면 접음) `stance` 는 같은 구간일 때만 folded(a4 F1)라 드물게 갈린다. 에이전트는 `stance` 하나만 말한다.
- `null` 의 뜻은 "접는 자리 판정이 없다" 다. "접는 자리가 아니다 · 밀어도 된다" 가 아니다(R3 이 잡는 것은 리치 차례의 2.9% 뿐이고, 그 밖은 재지 않았다).

### 2-2. `game.scores`

- 패보에 `start_scores` 가 없으면 `null`. 있으면:

```json
{"hero": {"wind": "서", "score": 22000, "rank": 3},
 "others": [{"wind": "동", "score": 25000, "rank": 2, "gap": 3000, "ahead": true},
            {"wind": "남", "score": 31000, "rank": 1, "gap": 9000, "ahead": true},
            {"wind": "북", "score": 22000, "rank": 3, "gap": 0, "ahead": false}],
 "kyotaku": 1}
```

- `score` = 국 시작 점수(이 국의 리치봉 · 결과 반영 전). `rank` = 1 + (나보다 점수가 높은 자리 수) — 같은 점수면 같은 순위. `gap` = |그 자리 점수 − 내 점수|, `ahead` = 그 자리가 나보다 높은가(같으면 false). `others` 는 동 · 남 · 서 · 북 순. `kyotaku` 는 국 시작 때 걸려 있던 리치봉 수(모르면 null).
- 천봉 판 사실표(`tool/tenhou6_agent_facts.dart`)도 천봉 로그의 국 시작 점수 · 공탁으로 채운다.

## 3. 서버 (`mahjong-recognizer` 의 `app/review_agent.py`, 지시문 a7)

- **받는 사실표:** 판 1 · 2 는 그대로 받는다(판 2 의 `fold_spot` 은 null · bool — bool 이 와도 null 로 다룬다). 판 3 은 `fold_spot` 이 null 또는 `{shanten(3~8 정수), ai_fold_pct(1~100 정수)}`, `game.scores` 는 null 또는 2-2 꼴(값 검사: 점수는 100 의 배수 정수, rank 1~4, wind 넷이 겹치지 않음, hero.wind = game.hero_wind).
- **도구:**
  - `defense_info`: `fold_spot` 을 그대로 싣고, 값이 있으면 알림 "보통 접는 자리다(리치를 받았고 내 손이 N샹텐, 효율대로 버릴 패가 가장 안전한 패보다 뚜렷이 위험) — 강한 AI 는 이런 자리의 약 94% 에서 접는다. 판정이 아니라 참고다". null 이면 지금 알림("이 차례의 밀기 · 접기 판정은 없다") 그대로.
  - `find_turns`: 조건 `fold_spot?`(true 만) — `fold_spot` 이 있는 차례. 줄에 " · 보통 접는 자리" 를 붙이고 줄마다 `fold_spot` 칸.
  - `what_if` · `turn_info` 는 안 바꾼다.
  - `game_summary`: `scores`(사실표 그대로 + `basis`: "국 시작 점수(이 국의 리치봉 · 결과 반영 전)"). null 이면 `scores: null` 과 알림 "이 판에는 점수 기록이 없다".
  - `rule`: "밀기 접기" 글을 고치고("보통 접는 자리" 의 뜻 · 94% 의 출처 한 줄 · 판정이 아님), "점수" 를 더한다(국 시작 점수 기준 · 순위는 같은 점수면 같은 순위 · 필요한 타점 · 순위 판단은 계산하지 않음).
- **지시문 a7(바뀌는 줄만):**
  - `fold_spot` 이 있는 차례를 말할 때: "이 차례는 보통 접는 자리다" 와 근거(내 손 N샹텐 · 강한 AI 는 이런 자리의 약 94% 에서 접는다)를 사실로 말하고, 플레이어가 한 것은 `stance` 사실문으로 잇는다. "접었어야 했다 · 밀면 안 됐다 · 밀어도 됐다 · 잘 접었다" 는 `fold_spot` 이 있어도 쓰지 않는다.
  - "접었어야 했어?" 같은 판정 질문: "이 도우미는 밀지 접을지를 판정하지 않는다" 한 번 + (`fold_spot` 이 있으면) 보통 접는 자리 사실.
  - `fold_spot` 이 null 인 차례는 지금처럼 사실까지만. "접는 자리가 아니다" 라고 하지 않는다. 접는 자리였냐고 물으면 "이 차례에는 접는 자리 판정이 없다".
  - 점수: `game_summary` 의 `scores` 값만 "N점"(숫자 그대로, 쉼표는 써도 됨)으로 말한다. 더하거나 빼 새 점수를 만들지 않는다(차이는 `gap`). `scores` 가 null 이면 "이 판에는 점수 기록이 없다". 점수로 밀기 · 접기 · 필요한 타점 · 순위 전망을 판단하지 않는다.
- **검증(바뀌는 것):**
  - 검사 7: 판정 말(`VERDICT_WORDS`)은 `fold_spot` 이 있어도 위반(전에는 있으면 허락). 부정문 간접 의문 예외는 그대로.
  - 검사 10(새): 답에 "접는 자리" 가 있으면 evidence 에 `fold_spot` 객체가 있어야 한다. 없는데 썼으면 위반 "접는 자리 말(fold_spot 사실 없음)". 다만 같은 문장에 "판정(은 · 이) 없" 꼴이 있으면 통과("이 차례에는 접는 자리 판정이 없다").
  - 검사 11(새): "N점"(쉼표 허용)은 evidence 의 `score` · `gap` 값이어야 한다(전에는 "N점" 이면 무조건 위반). "N천 점 · N만 점" 같은 한글 수사 점수는 위반. "N위" 는 evidence 의 `rank` 값(지금 규칙 그대로 — scores 의 rank 도 들어간다).
  - `ai_fold_pct` 는 "N%" 허용 값에 들어간다.
- 대체 답(`fallback_answer`) · 그래프는 안 바꾼다. 응답의 `prompt` 값은 "a7".

## 4. 앱

- `lib/paifu/agent_facts.dart`: 2절대로. 주석의 "일부러 null" 설명을 고친다.

## 6. 한계

- "약 94%" 는 천봉 鳳凰卓 고수 판에서 S42 가 접은 비율이다(표 16-15). 매장 손님 판에서는 재지 못했다.
- 접는 자리는 리치 차례의 2.9% 뿐이라 대부분의 수비 질문에는 지금과 같은 답이 나온다. 매장 예시 22판에는 접는 자리가 없다.

- 지시문이 길어져 입력 토큰이 는다(a6 이 a5 보다 +25.6% 였다).
