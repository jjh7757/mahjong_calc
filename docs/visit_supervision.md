# 매장 실험 감독 절차

매장에 가져간 노트북의 Claude 세션이 태블릿(USB adb)과 헤드(HTTP)를 보며 실험을 감독한다. 도구는 `experiments/supervise/supervise.py`, 받은 기록은 `experiments/visit_<날짜>/`(커밋 안 함). 체크리스트는 그대로 쓴다: https://claude.ai/artifact/MA3eRQry3jbnLMMJvNkV2Z (db `visit/next`).

사용자가 "감독 시작" 이라고 하면 이 문서대로 한다.

## 원칙

- **세팅에 집중하고, 대국 중에는 끼어들지 않는다.** 거치·격자를 잡는 첫 20~30분은 단계마다 확인한다. 대국이 시작되면 아래 "바로 알릴 것" 만 알리고 나머지는 쉬는 시간에 모아서 말한다.
- **보고는 할 일 한 줄부터.** 사용자는 탁자에 앉아 있다. 길게 쓰지 않는다.
- **현장에서는 코드·서버를 고치지 않는다.** 앱 재설치, 서버 배포, 격자 규칙 변경은 집에 와서 한다. 현장에서 하는 일은 카메라 옮기기, 격자 저장, 설정 켜기, 다시 연결까지다.
- **대국을 멈추게 하는 건 사용자의 결정이다.** Claude 는 알리고 권하기만 한다.
- **규칙을 바꾸지 않는다.** 이번 사진은 체크리스트의 개발/테스트 나누기를 따른다. 테스트 쪽 사진은 원인 분석에 쓰지 않는다.
- **adb 는 보기만 한다.** 앱 조작(`input`), 설치, 기록 삭제는 사용자가 시킬 때만 한다.

## 집에서 미리 (출발 전)

1. **폰(헤드)은 adb 로 붙이지 않는다. 무선 디버깅도 끈다**(10-30 사용자 결정). 다만 끊김의 원인은 아니었다: 10-31 매장에서 폰 무선 디버깅을 끈 채로, 다른 공유기에서도 태블릿 → 폰만 같은 꼴로 끊겼다(원인 미확인).
2. 태블릿은 USB 케이블로 노트북에 꽂는다. `status` 로 태블릿·헤드 줄을 확인한다.
3. 헤드 토큰은 `experiments/visit_head.txt`(커밋 안 함)에 저장돼 있어, 매장에서는 IP 만 바꾸면 된다. 폰에서 "새 QR" 을 누르면 토큰이 바뀌니 누르지 않는다.
4. 노트북 충전기·태블릿용 USB-C 케이블 챙기기.

## 현장 연결

- 노트북·태블릿·폰을 같은 Wi-Fi 에. 기기 간 통신이 막혀 있거나 매장 Wi-Fi 가 없으면 폰 핫스팟으로 셋 다 붙인다(그러면 헤드 폰의 데이터·발열을 더 본다).
- 태블릿은 USB 로 노트북에 꽂는다. 무선 adb 는 쓰지 않는다.
- 사용자가 태블릿에서 헤드 QR 을 스캔한 뒤, Claude 가 `shot tablet` 으로 화면의 "카메라 헤드 http://IP:8765" 를 읽어 `head-set IP` 를 한다. 토큰이 바뀌었으면 사용자가 헤드 화면의 `http://IP:8765?t=토큰` 을 알려 주어 `head-set` 에 통째로 넣는다.
- **노트북에서 헤드가 된다고 태블릿에서도 되는 건 아니다.** 10-30 집 시험에서 태블릿 ↔ 폰만 끊기고(서로 ping 실패, ARP 미완료) 공유기·노트북 쪽은 정상인 일이 있었다. `status` 의 "헤드(태블릿에서)" 줄을 본다. 10-31 매장에서도 재현(공유기는 달랐음). 끊기면 태블릿 Wi-Fi 껐다 켜기 → 안 되면 폰 핫스팟.
- 폰 adb 가 없어 폰 배터리·온도는 볼 수 없다. 쉬는 시간에 사용자가 폰 화면으로 확인해 메모에 적는다.

## 단계별 감독

| 단계 | 체크리스트 | Claude 가 하는 일 | 통과 기준 |
| --- | --- | --- | --- |
| 연결 | 거치·연결 | `status`, `shot tablet`, `head-set` | 태블릿 붙음·앱 앞, 서버 응답, 헤드 토큰 정상, 태블릿에서 헤드 연결됨 |
| 거치 | `level`·`four`·`px` | `preview` 프레임을 Read 로 보고 판단 | 펠트 네 변이 화면과 나란함, 네 자리 손패·울기 자리가 화면 안, **먼 자리 패 앞면 폭 100px 이상** |
| 스트림 | `stream` | `shot tablet` | 배경에 미리보기, "스트림 긴 변 4080" |
| 격자 | `auto`·`grid`·`track` | `pull` 뒤 `<시각>_track/setup_###.json` 과 `shot tablet` | 자동 격자가 손패+울기 띠 4개·리치봉 상자·패산 구역을 맞게 잡음, 추적 문구에 "(격자를 맞추면 시작)" 없음 |
| 왕패 | `wall` | `shot tablet` | 첫 버림 뒤 도라 산 상자가 실제 왕패 위 |
| 빈 탁자 3분 | `idle` | 3분 뒤 `pull`, `_track` 의 읽기 파일 수 | 헛 강 버림·모서리 읽기·리치봉 읽기 0 에 가까움. 결과를 사용자에게 알려 `f_idle` 칸에 적게 함 |

자동 맞추기는 대국 시작 때 20초 간격 10회만 돌고 멈춘다. 패를 돌리기 전에 다 쓰면(10-31 매장에서 실제로 겪음) 격자가 저장되지 않아 추적이 안 돌고, 첫 버림 때의 도라 산 찾기도 안 돈다. 이때는 "격자 편집" → "자동 맞추기" → "저장 (편집 끝)".

거치 통과 전에는 대국을 시작하지 말라고 권한다. 10-24 손패 0/15 의 원인이 여기였다.

## 대국 중

백그라운드로 기다린다(도구가 끝나면 Claude 가 깨어난다):

```bash
python experiments/supervise/supervise.py watch --since <마지막으로 본 화료 폴더> --pending <정답 기다리는 폴더들>
```

처음에는 `--since` 없이 시작한다(그때부터 새 것만). 끝날 때 찍는 한 줄에 따라 처리하고 다시 부른다. 다음 호출의 `--since` 는 방금 본 폴더로 올린다.

- `NEW_HAND <폴더>`: `pull` → `report --since <방문 시작 시각>` → 그 폴더의 `meta.json`(경고·플래그·오류)과 `original.jpg` 를 본다. 판독이 사진과 다르면 사용자에게 고치라고 한 줄 알린다. 폴더를 `--pending` 에 넣는다.
- `LABELED <폴더>`: 정답이 저장됐다. `--pending` 에서 뺀다. 다음 화료까지 `label.json` 이 없으면 "이전 화료 대국에 반영 안 됨" 을 알린다(정답이 사라진다).
- `ALERT ...`: 아래 표대로.
- `TIMEOUT`: 그대로 다시 부른다. 대국이 끝나 쉬는 때면 `status` 한 번.

체크리스트의 카운터·시간 바는 사용자가 누르는 값이라 `watch` 에 안 잡힌다. `ArtifactData` get(`visit`/`next`)으로 읽는다. 문서가 없으면 아직 아무것도 안 누른 것이다.

### 바로 알릴 것 (대국 중에도)

| 상황 | 알릴 말 |
| --- | --- |
| 헤드 응답 없음, 폰 앱이 뒤로 감 | 폰을 앞으로. 안 되면 태블릿 "다시 연결" |
| 헤드 토큰 틀림 | 새 QR 이 나온 것. 태블릿에서 QR 다시 스캔, 새 주소를 받아 `head-set` |
| 판독 `error` 가 있거나 2번 연속 20초 넘음 | 원인 호출 이름과 함께. 3번 이어지면 Wi-Fi·서버 `status` |
| 2번 연속 손패 장수 틀림(`tileCountMismatch`) | 카메라가 밀렸을 수 있음. `preview` 로 첫 프레임과 비교한 뒤 알림 |
| 태블릿 온도 42°C 이상, 충전 안 되는 배터리 20% 미만 | 충전기·쉬는 시간 |
| 이전 화료에 `label.json` 없음 | "대국에 반영" 눌렀는지 |

### 모아서 말할 것 (쉬는 시간)

- 지금까지 시간 중앙·p90·최대, 맞은 수/전체, 틀린 반영
- 체크리스트 "꼭 찍을 장면" 중 아직 안 나온 것 (만들어 찍을 만한 것 추천)
- 추적 카운터와 사진이 어긋나는 것
- 사장님께 물어볼 칸(`q_*`) 중 빈 것

## 끝나고

1. `pull`, `report`, 체크리스트 db 읽기.
2. 사용자가 집에서 "체크리스트 결과 읽어서 metrics.md 에 넣어줘" 라고 하면 `docs/metrics.md`(CLAUDE.md 규칙: 평가 밖 표), `HANDOFF.md` 에 옮긴다.
3. `experiments/visit_head.txt` 는 헤드 토큰이다. 문서에 옮겨 적지 않는다.

## 한계

- 폰 앱이 뒤로 갔을 때 작은 프레임 요청이 실패하는지는 실기기로 안 봤다. 알림이 안 오면 태블릿의 "헤드 연결됨" 색을 믿지 말고 `preview` 로 프레임을 본다.
- 프레임이 검어도 알림은 없다. 거치 단계와 카메라 밀림 의심 때 `preview` 로 직접 본다.
- 15초 간격이라 실시간이 아니다. 화료 뒤 판독을 놓치면 안 되는 건 사용자가 앱에서 직접 본다.
- 사용자 자신이 메시지를 봐야 전달된다. 대국 중에 푸시로 부르지는 못한다.
- `label.json` 은 사용자가 확정한 값이라, 사용자가 잘못 넣으면 Claude 도 맞다고 센다.
- 사람이 패를 만지는 과정은 3초 간격 프레임으로만 본다.
- 승인 창 없이 도는 것은 `.claude/settings.local.json` 에 허용한 `python experiments/supervise/supervise.py ...` 한 줄 명령뿐이다(이 저장소 폴더에서 실행할 때). adb 를 직접 부르거나 명령을 이어 붙이면 승인 창이 뜨니, 대국 중에는 도구 명령만 쓴다.
