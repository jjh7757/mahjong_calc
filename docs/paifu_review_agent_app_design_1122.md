- **가장 큰 한계:** 기기에 저장되는 판은 지금 대부분 "버림만" 이라 질문 단추가 보이지 않습니다. 실제로 질문할 수 있는 판은 예시 판과 손패가 든 판뿐입니다(7절).

| 내 버림 · 그 밖(최선 · 좋음 · 리치 중 등) | 그 차례 질문은 추천하지 않고 아래 줄의 판 전체 질문만 |
| 내 버림이 아닌 걸음 · 단계 걸음 | "이 판에서 제일 아까운 수는?" · "이 판 총평 해 줘" · (남의 리치가 있으면) "{바람} 리치 뒤에 나는 어떻게 했어?" |

남이 리치한 차례이면서 등급도 낮으면 수비 질문 둘을 먼저 놓고, 남는 한 자리에 등급 질문을 놓습니다. (1단계에서 확인: 지금 리뷰는 남이 리치한 차례를 '수비' 상태로 두어 등급을 매기지 않으므로 이 조합은 실제로 생기지 않습니다.)

손패를 모르는 차례(손패 기록 없음 · 어긋남 · 짐작 손패)는 그 차례 질문을 추천하지 않습니다. 직접 물으면 에이전트가 "모른다" 고 답합니다.

### 3-3. 지금 보는 차례 붙이기

직접 쓴 질문에는 보통 "이 수" 처럼 차례 번호가 없습니다. 서버는 질문 글에서 `N순 · N번째 · N차례 · N턴` 을 찾아 그 차례를 확인했는지 검사합니다.

- 입력 줄 위에 **"N순에 대해"** 켜기 / 끄기 칩을 둡니다. 내 버림 걸음에서는 기본으로 켜져 있고, 그 밖의 걸음에는 칩이 없습니다.
- 켜져 있고 질문 글에 차례 번호가 없으면 앞에 `N순에 대해: ` 를 붙여 보냅니다. 글에 이미 번호가 있으면 안 붙입니다. 대화 목록에는 붙인 글 그대로 보여 줍니다(무엇을 보냈는지 보이게).
- 차례 번호를 찾는 정규식은 서버(`review_agent._QUESTION_TURN`)와 같은 뜻으로 Dart 에 두고, 시험에서 같은 예문으로 맞춥니다.

## 7. 한계 · 위험

1. **질문할 수 있는 판이 적습니다.** 매장에서 저장되는 판은 지금 대부분 "버림만" 이라 복기 화면도 질문 단추도 없습니다. 쓸 수 있는 판은 예시 11판과 손패가 든 판(손패 복원을 거친 판)입니다. 손패 복원은 Claude API 를 쓰는데 지금 금지 상태입니다. 이 기능이 매장 판에서 쓰이려면 손패 기록이 먼저 있어야 합니다(이번 범위 밖).
2. **이어 묻기는 처음 잽니다.** 3단계 B 에 못 미치면 끕니다.
3. **검증이 못 잡는 틀림이 남습니다.** 코드가 대조하는 것은 답 속의 패 · 숫자 · 위험 단계 말 · 판정 말입니다. "왜 그런가" 를 푼 문장이 틀린 것은 사람이 읽어야 잡힙니다(표 15-7 의 말투 흠 포함).
4. **답이 느릴 수 있습니다.** 중앙 6초, 드물게 50초. 기다리는 동안 화면은 쓸 수 있게 둡니다.
5. **요청 제한이 서버 전체 합**이라 여러 기기가 같이 쓰면 서로 깎습니다. 지금은 사용자가 혼자 쓰는 전제입니다.
6. **직접 쓴 질문 글은 서버를 거쳐 Gemini 로 갑니다.** 사실표에는 이름 · 패보 id 가 없고 서버 로그에는 질문 · 답을 찍지 않습니다.
7. **웹 빌드는 운영 서버를 못 부릅니다**(서버에 CORS 가 없음). 웹은 개발용 서버로 눈 확인할 때만 씁니다.
8. 서버 키가 APK 에 들어 있는 것은 사진 판독과 같은 기존 구조입니다.
9. 판단(밀었어야 · 접었어야)은 여전히 답하지 않습니다. 밀기 · 접기 판정(`docs/push_fold_design_1122.md`)이 통과해 `fold_spot` 이 채워진 뒤의 일입니다.
