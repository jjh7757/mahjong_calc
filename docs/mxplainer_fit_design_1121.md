# 설계서 — Mortal-S42 의 버림을 mahjong-helper 틀로 맞추기 (2026-11-21)

**설계만 — 구현 · 실행 · 새 내려받기 없음.** 출발점: Mxplainer 논문(arXiv 2506.14246, 사용자 "논문 분석해" → "설계해 줘"). 앞 흐름: `docs/paifu_review_grader_design_1118.md` 12절, metrics 표 16-3, problem_log 72.

## 0. 요약

- **생각:** 논문은 "사람이 읽을 수 있는 탐색 틀 + 적은 수의 가중치" 를 블랙박스의 행동에 맞춰, 가중치와 계산 과정으로 설명한다. 우리는 그 틀이 이미 있다 — mahjong-helper 이식 엔진(`lib/engine/discard_rank.dart` · `risk.dart`). 엔진이 내는 후보별 값(유효패 · 개량 · 속도 · 화료율 · 국수지 · 방총 위험)은 그대로 두고, **그 값들을 어떻게 섞어 순서를 정하는지만** Mortal-S42 의 선택에 맞춘다.
- **왜 지금:** 표 16-3 에서 이식의 고정 순서는 S42 첫째 버림과 22 ~ 24/33 으로 지금 평가기(23/33)와 같았고, 후퇴 권장은 0/6 이었다. "값은 쓸 만한데 섞는 규칙이 S42 와 다르다" 가 남은 가설이다. 이 실험이 그 가설을 잰다.
- **논문과 다른 점(일부러):** ① S42 는 Q 값을 준다 → 순위만이 아니라 "S42 기준으로 얼마나 손해인 버림을 골랐나" 를 잴 수 있다. ② 논문은 대리 모델만 조작해 보고 "설명이 맞다" 고 했다. 우리는 S42 가 로컬에 있으니 **S42 자체에 입력을 바꿔 넣어** 설명이 맞는지 확인한다(5절).
- **새로 받는 것 없음:** 천봉 鳳凰卓 1,000판(tenhou6 JSON)이 `experiments/paifu_frames/results/handinfer/tenhou_raw/logs/` 에 이미 있다(표 17-2 때 받음). API 호출 0.

## 1. 무엇을 알고 싶나

1. 엔진 값을 다시 섞기만 해도 S42 첫째 버림과의 일치가 **고정 순서보다 의미 있게** 오르나.
2. 맞춘 가중치가 읽히나 — "유효패 1장 = 국수지 몇 점 = 방총 위험 몇 %p" 같은 교환 비율이 다시 뽑아도 같은 값으로 나오나.
3. 틀이 대는 이유("도라라서 남김" · "리치가 있어서 안전패")가 S42 에게도 진짜 이유인가.
4. 틀로 안 잡히는 차례는 어떤 것인가(점수 상황 · 손역 진행 · 울기 판단 등) — 틀의 한계를 목록으로.

## 3. 틀

### 3-1. 대상 결정

hero 가 패를 뽑고 **버릴 패를 고르는 차례**만. S42 쪽 답 = 그 차례 후보 중 리치 · 화료 · 깡을 뺀 가장 높은 Q 의 패(표 16-3 과 같은 정의). 뺄 것: 자기 리치 뒤(선택지 1개), 후보가 1종류뿐인 차례. 울기 여부 · 리치 여부는 이번 범위 밖.

결과는 늘 두 묶음으로 나눠 적는다 — **위협 없는 차례** / **위협 있는 차례**(남의 리치, 또는 엔진 텐파이율이 높은 울기 상대). 지금 평가기는 뒤쪽을 `defense` 로 빼고 등급을 안 매긴다.

### 3-2. 후보별 값(엔진이 이미 냄)

| 묶음 | 값 | 단위 |
| --- | --- | --- |
| 속도 | 버린 뒤 샹텐(지킴 / 후퇴) · 유효패 장수 · 개량 평균 · 전진 뒤 유효패 평균 · 속도 점수 | 장 · 점수 |
| 타점 | 화료율(텐파이만) · 국수지 · 다마 / 리치 기대 타점 · 후리텐 가능성 | % · 점 |
| 수비 | 그 패의 합친 방총 위험(`mixed34`) · 모두에게 안전패인지 | %p |
| 패 성질 | 도라 · 적5 · 역패 자패 · 객풍 자패 · 노두 · 중장 | 0/1 |

값은 "그 차례 후보 중 가장 좋은 값과의 차" 로 넣는다(유효패가 최선보다 3장 적다 · 위험이 최선보다 4%p 높다). 그래야 가중치가 교환 비율로 읽힌다.

### 3-3. 섞는 식(여기만 맞춘다)

```
점수(후보 c) = Σ_k  w_k[구간] × 값_k(c)        P(c) = softmax(점수)
```

- **구간** = 버리기 전 샹텐(0 / 1 / 2 / 3 이상) × 위협(없음 / 있음). 원본 정렬이 샹텐마다 다른 열쇠를 쓰는 것(텐파이는 국수지, 1샹텐은 유효패 × 국수지, 2샹텐 이상은 속도)을 가중치로 풀어 쓴 꼴이다. 수비 가중치를 샹텐별로 두는 것이 곧 "얼마나 멀면 접나" 다.
- 가중치 수: 값 약 12 × 구간 8 에서 안 쓰는 칸(화료율은 텐파이만 등)을 빼면 60 안팎. 논문(126개)보다 적다.
- 맞추기: S42 첫째 버림을 정답으로 한 교차 엔트로피 + L2. 검증 40판으로 L2 세기만 고른다. 덧붙여 S42 의 Q 를 부드러운 정답(softmax(Q/τ))으로 쓴 것도 한 번 돌려 차이를 적는다(S42 는 Q 크기가 공식 모델과 달라 τ 는 검증 판에서 고른다).
- 점수가 값의 가중합이라 **Dart 로 되돌리기는 곱셈 · 덧셈뿐**이다. 논문의 "동치 신경망 변환" 은 여기서는 필요 없다 — 솔직히 말하면 이 1단계는 "엔진 값 위의 선택 모형(조건부 로짓)" 이다.
- 2단계(1단계가 모자랄 때만): 엔진 **안쪽** 상수(국수지의 1,500 · 후퇴 권장 조건 · 속도 점수의 섞는 비율)를 풀어 같이 맞춘다. 이때는 논문처럼 그 계산을 PyTorch 로 다시 써야 한다. 지금은 설계하지 않는다.

## 5. 평가

### 5-1. 비교 대상(같은 결정 묶음 위에서)

| 이름 | 것 |
| --- | --- |
| B0 | 지금 평가기(샹텐 → 유효패 장수) |
| B1 | mahjong-helper 순서, 후퇴 권장 끔(표 16-3 에서 가장 높았던 것) |
| B2 | mahjong-helper 원본 순서 |
| **F** | 맞춘 틀(3-3) |
| U | 같은 값을 받는 자유로운 모델(얕은 신경망 또는 부스팅) — "값은 같고 섞는 식만 풀었을 때" 의 위쪽 한계. 설명용이 아님 |

### 5-2. 지표

- **첫째 일치:** 고른 패 = S42 첫째 버림. 둘째 안 일치도 같이.
- **Q 손해:** S42 가 매긴 Q 로 (S42 첫째의 Q − 우리가 고른 패의 Q) 의 평균과 90백분위. 순서만 다른 같은 값 버림은 손해 0 에 가깝게 나온다 — 논문이 top-3 로 뭉갠 부분을 직접 잰다.
- 구간별(샹텐 · 위협 · 순목 초중종) 표, 판 단위 부트스트랩 95% 구간.

### 5-3. 판정 기준(안 — 결과 보기 전에 사용자 확정)

주 판정 = 시험 200판 **첫째 일치 F − B1**.

| 결과 | 판정 |
| --- | --- |
| +5%p 이상이고 구간 아래 끝 > +2%p | 가치 있음 → 4단계(추천 순서 · 설명에 쓰기) 검토 |
| +2 ~ +5%p | 사이 → 가중치 해석만 남기고 제품엔 안 넣음 |
| +2%p 미만 | 접음 — "엔진 값으로는 S42 를 더 못 따라간다" 로 닫음 |

덧붙이는 조건: 위협 있는 차례에서 F 가 B1 보다 낮으면 "가치 있음" 이라도 수비 쪽은 쓰지 않는다. U − F 가 크면(예: 10%p 이상) "섞는 식이 너무 단순" 이라고 적고 2단계 거리로 넘긴다.

### 5-4. 설명이 맞는지(반사실 확인 — 논문에 없는 부분)

S42 에 넣는 mjai 사건을 한 군데만 바꿔 다시 물어, 틀이 예측한 쪽으로 S42 가 움직이는지 본다. 시험 판에서 조건에 맞는 결정을 각 200개까지.

| 바꾸는 것 | 틀의 예측 | 보는 것 |
| --- | --- | --- |
| 도라 표시패를 바꿔 그 패가 도라가 아니게 | 도라 가중치만큼 그 패를 버리는 쪽으로 | S42 첫째 버림이 바뀌는 방향 · 그 패의 Q 순위 변화 |
| 남의 리치 선언을 지움(버림은 그대로) | 수비 가중치가 0 이 된 순서로 | 같음 |
| 점수만 바꿈(1위 ↔ 4위) | **변화 없음**(틀에 점수 칸이 없다) | S42 가 실제로 바뀌는 비율 = 틀 밖에 있는 판단의 크기 |

기준(안): 앞 두 줄에서 방향 일치 70% 이상이면 그 가중치는 "S42 의 이유" 로 읽어도 된다고 적는다. 미만이면 "맞추기는 됐지만 이유는 다름" 으로 적고 설명에 쓰지 않는다.

### 5-5. 가중치를 읽기 전에

- 판 단위 부트스트랩 20번에서 부호가 바뀌거나 변동이 30% 를 넘는 가중치는 해석하지 않는다(유효패 · 개량 · 속도 점수는 서로 겹쳐 흔들릴 수 있다 — 흔들리면 하나로 묶는다).
- 값 묶음을 하나씩 빼고 다시 맞춘 표(속도 / 타점 / 수비 / 패 성질). 일치가 "패 성질" 에서만 오르면 그것은 버림 순서 습관이지 판단이 아니다.

## 7. 만들 것 (형식: 설계 Fable · 구현 Opus 5.5 높음 · 검토 Fable)

1. `tool/tenhou6_features.dart` — tenhou6 한 판 + 자리 → 버림 결정마다 JSONL(판 · 국 · 자리 · 몇 번째 버림 · 실제 버린 패 · 구간 정보 · 후보별 값). 엔진 입력은 `mh_context.dart` 와 같은 뜻으로 만든다(보이는 패 셈 · 적5 · 풍). 검토: 매장 4판을 `paifu_to_tenhou6` 로 바꾼 것에 돌려 `paifu_review_dump` 의 값과 같은지 대조.
2. `experiments/paifu_review/mxfit/s42_batch.py` — `mortal_local.py` 의 `to_mjai` · `decode` 를 가져와 엔진을 한 번만 읽고 판 × 자리를 돈다. 결정마다 합법 행동 전체의 Q 를 JSONL 로.
3. `mxfit/join.py` · `fit.py`(torch CPU) · `eval.py`(B0 ~ U · 지표 · 부트스트랩) · `counterfactual.py`.
4. 검토는 세션이 `eval.py` 를 다시 돌려 같은 숫자인지, 맞붙이기에서 버린 패 어긋남이 0 인지, 시험 판이 맞추기에 안 섞였는지(판 ID 교집합 0) 본다.

## 9. 한계

- S42 는 강함이 검증 안 된 개인 모델이다(problem_log 71). 맞춘 것은 "S42 의 취향" 이지 정답이 아니다.

## 11. 1단계 규격 — 맞추기 (2026-11-21 밤, 돌리기 전에 적음)

### 11-1. 판 나눔

개발 200판을 ID 순으로: **앞 140 = 맞춤 / 다음 20 = 고르기(L2 세기 · τ · U 의 멈춤) / 뒤 40 = 검증.** 검증 40판은 어떤 고르기에도 쓰지 않는다 — 6절의 멈춤 판정(F − B1 < +2%p 면 접음)은 이 40판으로 한다. 시험 799판은 열지 않는다.

### 11-2. 대상 · 정답

주 묶음(표 16-5 와 같음: 뽑고 버리는 차례, 자기 리치 뒤 · 울기 직후 · 후보 1종류 제외). 정답 = `s42Discard`.

### 11-3. 후보별 값 (3-2 를 구체화)

지키는 후보 = 버린 뒤 샹텐이 그 차례 후보 중 최소인 것, 물러나는 후보 = 그보다 큰 것. 엔진의 유효패 · 개량 · 속도는 샹텐이 다르면 눈금이 달라(물러나는 후보의 유효패 75장 등) 섞어 비교하지 않는다.

| 이름 | 정의 | 눈금 |
| --- | --- | --- |
| back | 물러나는 후보면 1 | — |
| dWaits · dImprove · dNextWaits · dSpeed | 지키는 후보끼리의 최댓값과의 차(≤ 0). 물러나는 후보는 0 | ÷ 10 |
| dAgari | 화료율 차(지키는 후보끼리, 버린 뒤 텐파이일 때만) | ÷ 10 (%p) |
| dRound | 국수지 차(지키는 후보끼리) | ÷ 1000 (점) |
| furiten | 후리텐 가능성 0 / 0.5 / 1 | — |
| backSpeed | 물러나는 후보의 속도 점수 − 지키는 후보 최고 속도 점수. 지키는 후보는 0 | ÷ 10 |
| dRisk | 그 패의 합친 방총 위험 − 후보 중 최소 위험(≥ 0, 모든 후보) | ÷ 10 (%p) |
| safeAll | 모두에게 안전패면 1 | — |
| dora · red · yakuhai · guestWind · terminal · honor | 엔진이 낸 표시 그대로(dora · yakuhai 는 겹수) | — |
| edge | 수패의 \|숫자 − 5\| ÷ 4, 자패 0 (패 코드에서 계산) | — |

null(NaN)은 차를 낼 때 빼고 그 후보 값은 0. 눈금은 고정 상수다(자료에서 배우지 않음) — 가중치를 눈금으로 나누면 "1장 · 1,000점 · 10%p 당" 으로 읽힌다.

### 11-4. 식 · 맞추기

- 구간 = 버리기 전 샹텐(−1 과 0 을 묶음 / 1 / 2 / 3 이상) × 위협(`riskSeats` 비었음 / 있음) = 8. 구간마다 위 18개 값의 가중치를 따로 둔다(그 구간에서 늘 0 인 값은 뺌). **3-3 에서 60 안팎이라 한 것이 100 을 넘는다 — 논문(126)과 비슷한 크기.**
- 점수 = 가중합, 손실 = 정답 패의 교차 엔트로피 + L2. L2 세기는 {0, 1e-4, 1e-3, 1e-2} 중 고르기 20판의 첫째 일치로. 씨 고정, 전체 배치.
- 부드러운 정답(softmax(Q/τ), τ ∈ {0.1, 0.3, 1.0} 을 고르기 20판에서)도 한 번 — 채택 기준은 아니고 적기만.
- **U:** 같은 18개 값 + 문맥(샹텐 · 위협 · 자기 버림 번호 · 멘젠 · 친)을 받는 작은 신경망(은닉 64 × 2, 후보마다 점수 → softmax), 고르기 20판에서 멈춤. 설명용이 아니라 "섞는 식을 풀면 얼마나 더 되나" 의 참고.
- 동률: 점수가 같은 후보는 패 번호 순으로 가른다(엄격). S42 패가 최고 점수와 1e-9 안이면 "동률 포함" 으로도 센다.

### 11-5. 검증 40판에서 적는 것

B0 · B1 · B2 · F · F(부드러운 정답) · U · 플레이어 실제의 첫째 일치 · 둘째 안 · Q 손해(평균 / 90백분위), 구간별, **F − B1 의 판 단위 부트스트랩 95% 구간**. 값 묶음을 하나씩 뺀 F(속도 = back ~ backSpeed 중 속도 쪽 / 타점 = dAgari · dRound · furiten / 수비 = dRisk · safeAll / 패 성질 = dora ~ edge)와 패 성질만 쓴 F. 구간 없이 가중치 한 벌만 쓴 F. 맞춤 140판을 판 단위로 20번 다시 뽑아 맞춘 가중치의 부호 뒤집힘 · 변동.

### 11-6. 검토용 산출물

`weights.json`(구간 · 값 이름 · 눈금 · 가중치 · 고른 L2), `preds_val.jsonl`(검증 결정마다 열쇠 · 후보별 점수 · 고른 패 · S42 패) — 세션이 가중치와 맞붙인 자료만으로 점수를 따로 다시 계산해 같은지 본다.
