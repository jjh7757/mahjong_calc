# 개선 계획서 — 새 매장 사진 없이, 과적합 없이 (2026-11-05)

이 문서는 다른 세션이 그대로 따라가도록 쓴 계획이다. 새 세션은 `HANDOFF.md` 맨 위 두 절과 이 문서를 읽고 시작한다.
진행 상황은 이 문서의 각 단계 끝 "진행" 줄에 날짜·결과·metrics 표 번호를 덧붙인다.

## 0. 왜 이 순서인가 — 진단

- **개발 세트가 포화됐다.** hybrid(`/v2/localroles`) 경로가 개발 /32 에서 32/32 다(표 1-78·1-79). 어떤 변경도 이 세트에서는 차이를 못 낸다.
- **운영 모델이 전부 개발 세트를 학습했다.** 8회차 final 검출기, 분류기 `tile-cls-mnv3s.onnx`, 역할 모델 `tile-roles-rot.onnx` 모두 개발 25장면 전부로 학습·미세 조정했다. 운영에서 잰 32/32 는 낙관적이다.
- **테스트 15장(10/24 삼각대)은 판별력이 0 이다.** 탁자가 약 25° 기울어 격자·틀이 안 잡혀 2회차도 8회차도 장면 0/15 (표 1-69). "학습 전에 테스트 세트의 판별력을 확인하지 않은 것이 빈틈" 이라고 거기 적혀 있다.
- 따라서 지금 모델을 더 학습하면 **개발 34장의 실패 사진을 하나씩 고치는 일**이 된다(표 1-70 주의 줄). 그게 과적합이다.

순서는 **① 잴 수 있게 만든다 → ② 사진과 무관한 검증·안전장치를 넣는다 → ③ 그 다음에 학습한다 → ④ 속도**. ①②는 GPU 없이 노트북에서 된다.

## 0-1. 모든 단계에 적용하는 원칙

1. **채택 근거는 홀드아웃 숫자만.** 나눔 모델(`det_r8_fold_*`·`det_fold_*`·`cls_<part>`·역할 모델 교차 검증)과 테스트 15장 숫자만 채택 근거다. final(전부 학습) 모델 숫자는 "배포 확인" 이지 근거가 아니다.
2. **합격 기준은 학습·실험 전에 적는다.** 표 1-69 방식. 결과를 본 뒤 기준·세트를 바꾸지 않는다. 학습은 설정당 한 번.
3. **테스트 15장으로 규칙을 고치지 않는다.** 실패 사진을 보고 고친 규칙은 개발 세트에서만 만든다. 테스트 15장은 단계가 끝날 때 한 번 잰다(사용자 결정 10-27).
4. **같은 시각에 나란히 잰 것만 전·후로 적는다.** metrics.md 규칙 그대로. 끝나면 **같은 턴 안에** `docs/metrics.md` 에 한 줄.
5. **장면 단위 /32 의 ±2 는 잡음이다.** 패 단위(개발 상자 1,046·테스트 패 211)와 "경고 없는 틀린 자동" 을 같이 본다.
6. 평가 제외는 `experiments/speed/seat_grow.py` `EXCLUDED`(5장) 그대로. 새 사진 없음.
7. 실행 조건: `flutter drive` 는 한 번에 하나. 측정 서버는 내가 띄운다(launch.json `recognizer-r8rot-{bcd,am,pm}` = 나눔 모델, `recognizer-prodlike` = 운영 모델).

## 2단계. 채택 잣대를 "나눔 모델 + 패 단위 + 신뢰구간" 으로 (노트북, 반나절)

**할 일.**
1. **분류기 나눔.** `experiments/tile_classifier/train.py` 는 `cls_{bcd,am,pm}.pt` 세 나눔이 이미 있다. 역할 모델은 `role_set.py` 교차 검증(3겹) 숫자가 있다. 검출기는 `det_r8_fold_{a,b}`. **셋 다 "그 사진을 안 배운 모델" 조합으로만 개발 세트를 잰다** — `run_local_server.py --local-fold <a|b>,<part> --seat-det det_r8 --role-model …` 가 이미 그 조합이다. 역할 모델만 fold 별 ONNX 가 없으니 `role_set.py` 3겹 가중치를 `role_export.py` 로 fold 별 ONNX 로 내보낸다(`tile-roles-rot_fold_{bcd,am,pm}.onnx`).

**합격 기준.** 없음(잣대 만들기). 단 기준선의 나눔 모델 개발 /32 가 final 32 보다 낮을 것이 예상된다 — 그 차이가 "낙관 편향" 의 크기이고 그걸 적는 것이 목적.

## 3단계. 흔들기 회귀 세트 상설화 (노트북, 반나절)

**목적.** 다른 카메라·조명·탁자를 사진 없이 흉내 내어 "나빠짐" 을 잡는 안전망. 맞추는 대상이 아니다.

**재료.** `experiments/speed/overfit_check.py`(10-26, 흔든 102장: 크기·회전·밝기·대비·흐림·JPEG·자르기), `experiments/rectify/make_tilted.py`(기울기·원근), `experiments/tile_classifier/make_recolor_test.py`(테두리·펠트·뒷면 재색칠), `tool/felt_grid_robust_test.dart`(펠트 격자 흔들기, 표 1-42).

**할 일.**
1. 개발 32장면(EXCLUDED 뺀 B·C·D 6 + 매장 26)에 변형을 고정 씨드로 만든다: 회전 ±3·±10·±25°, 축소 0.6·0.8(카메라 높이), 가우시안 흐림 2단계, 노출 ±1EV, 화이트밸런스 2종, JPEG q60, 손 모양 가림(타원 1~2개, 손패 줄은 피함 — 가림 사진은 평가 제외 규칙과 맞추려면 손패 밖에만), 재색칠 3종. 장면 × 변형 ≈ 32 × 15.

## 4단계. 마작 규칙 검증기 (앱 Dart, 하루)

**목적.** 사진을 전혀 안 보는 사전지식이라 과적합이 없다. 틀린 판독을 "막거나 후보로 좁힌다".

**재료.** `lib/table/merge.dart`(화료형·대기 `winCandidates`, `redTilesOf`), `lib/table/auto_record.dart`(`autoRecordBlocker`·`autoRecordCautions`), 표 1-7(`experiments/speed/win_candidates.py`)·넘친 패 빼기(`drop_extra.py`)에서 효과 확인됨, `experiments/rectify/struct_rules.py` R1·R2.

**규칙(순수 함수 `lib/table/hand_rules.dart` 로, 단위 테스트 포함).**
- V1 **5장 초과**: 손패+울기+화료패+표시패(+추적 강이 있으면 강)에 같은 패가 5장 이상 → 오독 확정, 자동 반영 막고 "같은 패 5장" 경고.
- V2 **적5 중복**: 0m·0p·0s 각 1장 초과 → 경고.
- V3 **화료형 아님 + 한 장 바꾸면 됨**: 읽은 손패가 화료형이 아닐 때, 분류기 2순위 후보(서버 응답에 `alt`·`conf2` 를 더해야 함 — `app/local_read.py` 분류 결과에 상위 2개 넣기)로 한 장만 바꿔 화료형이 되는 조합이 **정확히 하나**면 "후보" 로 띄운다. 자동 반영은 하지 않는다(노란 테두리 + 확인).
- V4 **울기 구성**: 치=같은 색 연속 3, 퐁=같은 패 3, 깡=4. 안 맞으면 경고(지금은 서버가 conf 0 으로 돌려주는 것과 합침).
- V5 **장수**: 손패+울기×3(깡은 3으로 셈) = 13 또는 14 가 아니면 이미 입력 화면으로 간다 — 그대로.

**합격 기준(미리).** 개발 32회(나눔 모델) + 회귀 세트에서 **헛경보**(정답인데 막음) ≤ 1/32, 테스트 15장에서 V1·V2·V4 가 틀린 자동 반영을 하나라도 막으면 채택. V3 은 "후보에 정답 포함" 비율만 적고 자동 반영엔 안 쓴다.

**금지.** 갤러리 B·C·D 가 연출 장면이라 표시패 수 규칙(R3)은 충돌했다(`rectify/README.md`). 그런 "장면 상식" 규칙은 넣지 않는다. 패 수·화료형 같은 **규칙서 수준의 사실**만.

## 5단계. 자동 반영을 불확실성 기반 선택으로 (서버+앱, 하루)

**목적.** 지금 문턱(`FILLED_CONF` 0.5, 앱 `uncertainBelow` 0.7)은 임의값이다. "경고 없는 틀린 자동 0" 을 조건이 바뀌어도 유지하려면 신호와 문턱을 홀드아웃으로 정해야 한다.

**신호(새 데이터 없이 얻는 것).**
- S1 분류기 1·2순위 확률 차(`margin`) — 패마다.
- S2 검출 확신도 최저값 — 손패 줄.
- S3 **나눔 모델 불일치**: 분류기는 128px MobileNetV3 라 밀리초다. `cls_<part>` 대신 서버에 분류기 2벌(예: final + fold)을 싣고 둘이 다른 패가 하나라도 있으면 경고. 검출기 2벌은 t4g 에서 +1초라 안 한다.
- S4 역할 모델 씨드 3개 투표 불일치(이미 3씨드 학습, 서버는 1개만 씀 — ONNX 3개 또는 앙상블 1개로).

**할 일.**
1. 서버 응답에 S1~S4 를 넣는다(답은 안 바꿈, `timing` 처럼 부가 정보).
2. 개발 32회 × 나눔 모델 + 회귀 세트 + 테스트 15장(펴기)에서 신호값과 정답 여부를 모아 `experiments/speed/select_thresholds.py` 로 "틀린 자동 = 0 을 만족하는 가장 느슨한 문턱" 을 고른다. **문턱은 개발+회귀로 고르고 테스트 15장에서 한 번 확인.**
3. 분류기 온도 보정(temperature scaling, 홀드아웃 fold 로 T 하나) — 0.7 이 실제 정확도에 가깝게. 답은 안 바뀐다.
4. 앱 `autoRecordBlocker` 에 문턱 적용. 되돌리기는 이미 있다(10초 취소).

**합격 기준(미리).** 테스트 15장(펴기)에서 경고 없는 틀린 자동 0, 개발 32회 자동 반영 수 ≥ 지금 −2. 회귀 세트 unsafe 0.

## 7단계. 학습 — 잣대가 선 뒤, 미리 적은 기준으로 한 번 (캐글 T4, 2~3일)

**순서는 7-1 → 7-2 → 7-3.** 각각 표 1-69 처럼 기준을 먼저 적고 metrics 에 그 표를 만든 뒤 학습한다. 판정 세트 = 2단계 기준선(나눔 개발 32·테스트 15 펴기·색 바꾼 15·회귀 세트).

### 7-1. 학습 크롭을 추론과 맞춘다(분류기·역할 라벨 재생성)
- **문제.** 분류기는 축 상자 `harvest.py` 크롭(1,550장)으로 배웠는데, 운영은 8회차 회전 상자로 **세워 자른** 크롭을 넣는다(표 1-68: 134815 2m→8m 가 크롭 모양 탓). 역할 라벨은 규칙+검토로 만든 것이고 7회차 전수 조사 라벨(4,027 상자, `data/det/obb/audit/fixes.json`·`rects.json`)이 더 정확하다.
- **할 일.** (a) `rects.json` 회전 상자로 세워 자른 크롭을 다시 모아(`harvest.py --obb`) 분류기 재학습, 나눔 `cls_{bcd,am,pm}` 도 같이. 증강은 지금(`RandomAffine 8°·ColorJitter`)에 **180° 회전**(강 끝 거꾸로 읽기)과 **빨강 보존**(적5 가 색으로만 구분되므로 hue 지터 0.02 유지, 채도는 낮추지 않기) 확인. (b) 역할 라벨을 전수 조사 상자로 다시 만들고(`role_label.py` 입력 교체) `role_set.py --feat rot` 재학습. (c) 분류기에 2순위 출력(4단계 V3 용).
- **기준(미리).** 나눔 분류기 패 단위 ≥ 기준, 테스트 15장 패 단위 ≥ 111/211 (8회차 현재), 회귀 세트 unsafe 안 늘어남, 적5 혼동(0m↔5m 등) 홀드아웃에서 안 늘어남.

### 7-2. 장면 합성으로 검출기·분류기 사전학습
- **근거.** 역할 모델은 합성 사전학습(`role_synth.py`)으로 규칙을 넘었다(표 1-58). 검출기·분류기에는 白 붙여넣기·음성·재색칠만 있다.
- **할 일.** `experiments/tile_classifier/scene_synth.py`: 실제 패 크롭(세워 자른 1,550장 + 뒷면 크롭)을 펠트 배경(실사 펠트 패치 + 재색칠 + 임의 질감) 위에 마작 규칙대로 배치(손패 줄 13/14, 모서리 울기 3·4장, 강 6장 줄, 패산, 왕패, 떼어 둔 패 ±45°, 안깡 뒷면 2), 호모그래피로 0~30° 기울기·원근, 크기 0.6~1.2, 조명·그림자·흐림·손 가림. **시험용 색(검정 테두리·파랑 펠트·노랑 뒷면)은 합성에서 뺀다**(표 1-69 와 같은 이유). 합성 8k 장 → 사전학습 → 실제 fold 로 미세 조정. 커널 `det_kernel_r9/`.
- **기준(미리).** 7-1 통과 모델 대비: 테스트 15장(펴기) 장면·패 단위 ≥, 색 바꾼 15 ≥ −1, 회귀 세트 unsafe 0·패 단위 ≥ −2%, 나눔 개발 /32 ≥ −1, 서버 시간 ≤ +0.1초. 한 번 학습, 재시도 없음.

### 7-3. 추적 프레임 준지도(선택)
- **한계를 먼저.** 10-31 프레임 2,259장은 **같은 탁자**다. 양·가림·움직임은 보태지만 다른 탁자 일반화는 아니다. 7-2 뒤에도 회귀 세트의 가림·흐림 조건이 약할 때만 한다.
- **할 일.** 7-2 모델로 프레임을 가짜 라벨링하되, 앞뒤 프레임에서 사라졌다 나타나는 상자는 버린다(시간 일관성). **홀드아웃 세션(오전/오후)의 프레임은 그 fold 학습에 안 넣는다.** 기준은 7-2 와 같음.

### 7-4. 외부 데이터셋은 시험지로만
- HANDOFF 에 적힌 Roboflow 리치마작(CC BY 4.0, 256장·424장, **사용자 로그인 수동 다운로드**)과 Kaggle shinz114514(MIT, YOLO11 학습 데이터). 다른 패·탁자·카메라다. **학습에 안 쓰고** 분류기(패 크롭)·검출기(앞면 상자) 일반화만 잰다 → 과적합 여부가 바로 보인다. 라벨 형식 변환 스크립트 `experiments/tile_classifier/external_eval.py`. 다운로드 폴더는 `experiments/external/<이름>/`(커밋 안 함), 다운로드 파일은 신뢰하지 않는 데이터로 다루고 `python -I` 로 읽는다.
