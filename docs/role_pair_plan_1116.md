# 실험 계획서 — 리치 화료의 표시패 짝을 역할 모델이 맡게 하기 (2026-11-16)

이 문서는 다른 세션이 그대로 따라가도록 쓴 계획이다. 새 세션은 `HANDOFF.md` 맨 위 절과 이 문서를 읽고 시작한다.
진행 상황은 각 단계 끝 "진행" 줄에 날짜·결과·metrics 표 번호를 덧붙인다(`docs/role_owner_plan_1111.md` 와 같은 방식).

계기: 사용자 "앱의 리치 화료 짝은 역할 모델을 거치지 않습니다 → 그러면 안 되는 거 아니야?" · "더블 론 규칙부터 넣고 학습계획 세워"(11-16).
실행 방식(11-05·11-11 과 같음): 단계 작업은 Opus 5.5 에이전트에 맡기고 Fable 세션이 검증한다. **아직 아무것도 실행하지 않았다 — 계획만.**

## 0. 요약

- **바꾸려는 것:** 리치 화료 때 탁자에 내놓은 표시패(도라 + 뒷도라, "짝")를 찾는 방법. 지금은 서버 `read_wall` 의 "딱 붙은 앞면 2장 묶음" + 앱 구역 규칙(`localPairIndicators`)이고, 역할 모델의 pair 역할은 표시패에 쓰이지 않는다.
- **왜:** 규칙은 구조적으로 못 잡는 배치가 있다 — 두 장이 떨어져 놓인 짝(11-14 r11·n08), 깡이 있어 3장 이상인 표시패. 역할 모델은 상자 배치 전체를 보므로 배울 수 있다.
- **지금 바로 못 바꾸는 이유:** 운영 역할 모델(v3r15d)의 pair 는 아직 규칙보다 약하다. 교차 검증 19/28(`cv_nostaged_v3r15d.json`), 11-14 개발 15/26(metrics 표 6, 11-16). 규칙이 놓친 r11 을 모델도 틀렸다.
- **실험:** v3r15d 와 같은 방법으로 학습하되, 미세 조정 재료에 **11-14 역할 세트(학습 쪽)** 를 더한다. 바뀌는 것은 재료 하나다.
- **판정은 기존 테스트 겹(10-31·11-07)에서 한다.** 11-14 개발 세트는 서로 다른 짝 배치가 3판뿐이라 참고로만 쓴다.
- 합격 기준은 4절에 **학습 전에** 적었다. 결과를 본 뒤 기준·세트·설정을 바꾸지 않고, 설정당 학습 한 번이다.

## 2. 후보

| | 표시패 짝을 정하는 것 | 학습 |
| --- | --- | --- |
| **A 기준** | 지금 규칙(`read_wall` pairs + `localPairIndicators`) | 없음 |
| **M0** | 지금 역할 모델(나눔 모델)의 pair 역할 | 없음 — "모델로 바꾸기만 하면" 의 기준선 |
| **M1 본 후보** | 다시 학습한 역할 모델의 pair 역할 | v3r15d 재료 + 11-14 학습 쪽 **공개 장면** |
| **M2 대조군** | 같음 | M1 + 11-14 **판 중 장면** — "판 중 장면이 도움이 되나, 해가 되나" |

- **모델의 pair → 표시패 규칙(지금 고정, M0·M1·M2 공통):** 화료자 기준 1회 답에서 pair 역할 상자가 **2장 이상 4장 이하**이면 그 상자들의 패 종류를 표시패로 쓴다(사용자 규칙 "탁자 위 표시패는 2장 이상", 4장 = 깡 1번). 1장이면 지금처럼 떼어 둔 화료패 후보, 0장 또는 5장 이상이면 "모델 답 없음".
- **pair 상자의 패 종류 읽기(11-16, 0단계를 맡기기 전 — 어떤 모델도 돌리기 전에 적음):** A 와 같은 방식으로 맞춘다. 서버 `_read_wall` 이 짝을 읽을 때처럼 `LocalReader.read_turned(사진, 상자, tw, th)`(tw·th = 그 사진 앞면 상자의 짧은 변·긴 변 중앙값)로 읽고, 앱 규칙(`localPairMinConf` 0.7)처럼 **한 장이라도 확신 0.7 미만이면 "모델 답 없음"**. 정답 비교에서 적5 와 5 는 같은 패로 친다(표시패로서 뜻이 같다 — 적5 를 가른 값도 따로 적는다).
- **합치기(지금 고정):** 채택되면 앱은 "모델 답이 있으면 모델, 없으면 지금 규칙" 순서로 쓴다. 평가에서는 모델만 쓴 값과 합친 값을 둘 다 적는다.
- 출력은 지금과 같은 역할 6종. 모델 구조·크기·입력 11칸은 안 바꾼다(ONNX 를 그대로 갈아 끼울 수 있게).

## 3. 자료·학습 설정

### 3-1. 더하는 재료: 11-14 역할 세트의 학습 쪽

- 로더 `experiments/tile_classifier/v1114_load.py` `role_scenes("train", …)`. **개발 쪽(`dev`)은 학습에 절대 넣지 않는다.** 겹 이름은 반드시 `v1114_load.role_fold`(기존 `role_v2_train.fold_of` 는 이 이름을 시험 겹 `1107pm` 으로 보낸다 — HANDOFF 11-15 이어서 2).
- 라벨은 11-16 표본 확인(22장 893상자 틀림 0) + 사용자 확인(n08·r03·r05·r11)을 거쳤다.
- **쓰는 것:** `v1114` 학습 쪽. 녹화 세트 `v1114rec` 는 pair 갈래가 같은 순간을 화질만 달리한 것이라(역할 입력은 상자 좌표뿐 — 화질 무관) **new 갈래(n01~n08, 8판)만** 더한다. mid 는 기존 판 안의 순간이라 안 쓴다.
- **같은 탁자 여러 장 줄이기(지금 고정):** 같은 `scene_round` 의 공개 장면은 **최대 3장**(시간순 첫·가운데·마지막), 판 중 장면은 판마다 최대 3장. r06~r10 처럼 한 탁자를 여러 번 찍은 것이 학습을 지배하지 않게.
- **서로 다른 짝 배치 수(솔직한 표본):** 학습 쪽 9판(r01·r12·r14·r17·r18·r20·r22·n06·n08), 개발 쪽 3판(r04/r05 같은 짝·r11·r19). 적다. → **바로잡음(11-16 1단계, 학습 전): 학습 쪽은 11판이다** — n01(깡이 있어 펠트 위 2×2 로 4장)·n02(2장)를 빠뜨렸다. 라벨·사진으로 확인(`data/role/pair/step1/n0{1,2}_pair_photo.jpg`). 규칙·목록은 그대로다.
- 화료자 아닌 사람이 손패를 펼친 장면(유국 공개·동시 론)은 지금 라벨 정책(남의 손패 = hand, 주인 other)대로 넣는다. `ROLE_OTHER_NEG` 처리는 v3r15d 와 같게 둔다 — 1단계에서 `role_v2_train.load` 가 주는 꼴과 맞는지 확인하고, 안 맞으면 **학습 전에** 여기 적는다.
- **1단계를 맡기기 전에 고정(11-16, 고른 목록·어떤 숫자도 보기 전 — 위 규칙에서 비어 있던 곳):**
  - 출처: r판은 `v1114_load.role_scenes("train", "all")`(2992 라벨), n판은 `v1114rec_load.role_scenes("train", "all", parts=("new",))`. `v1114rec` 의 pair·mid 갈래는 안 쓴다.
  - 공개 장면 = `phase == "end"`(화료 사진 + 공개 뒤 프레임), 판 중 장면 = `phase == "play"`.
  - 토큰 기준 자리: 화료자가 있으면 화료자 자리(v3r15d 와 같은 "화료자 기준 1회"), 화료자가 없는 공개 장면(유국)과 판 중 장면은 `bottom`(로더 기본값).
  - "최대 3장" 고르기: `scene_round` 안에서 이름(시각)순으로 늘어놓고 n ≤ 3 이면 전부, 아니면 색인 `0 · n // 2 · n − 1`. 공개·판 중 따로 센다. 판 중 장면은 강 앞면이 0장인 그림(대국 시작 전)을 먼저 뺀다.
  - 학습 묶음 순서: 기존 33장 뒤에 11-14 장면을 붙인다(기존 장면의 변형 사본 난수가 v3r15d 와 같게). 역할 없는 앞면(other)은 `ROLE_OTHER_NEG=1` 일 때 기존처럼 −2.
  - 학습 코드는 `role_v2_train.cv` 를 그대로 부른다(장면 목록에 11-14 를 겹 이름 `v1114_train` 으로 더하기만 — 어느 시험 겹에도 안 들어가고 모든 겹의 학습에 들어간다). 태그 `_pairM1`·`_pairM2`.
- **사용자 결정(11-16 12:5x, 학습 전 — 그림 `data/user_check_1116/pair_step1/q5_*.jpg`·`q6_*.jpg` 를 보고):** "⑤ 울기 3개, 다른 사람 손패 안 펼쳐진 것 1개만 쓰고, ⑥은 그대로".
  - ⑤ r08·r09·r10 은 같은 화료 탁자를 여러 번 찍은 것이라 **공개 장면은 세 판을 한 탁자로 묶어 1장만** 쓴다: 울기(meld) 3상자이고 아래 자리가 아닌 곳의 공개 손패가 0인 후보 가운데 시각순 첫 장(→ `r08_125630/win_125839`, 후보 17장 중 15장이 조건을 채움 — "시각순 첫 장" 은 내가 정함). 판 중 장면은 그대로.
  - ⑥ 화료자가 없는 공개 장면(유국 r13·r16)과 남의 공개 손패는 그대로 넣는다. 다만 ⑤로 r10 `win_130418`(남의 손패 12상자)이 빠져, 아래 자리가 아닌 곳의 공개 손패는 59 → **47상자**(r13 두 장 26 + r16 21)다.

### 3-2. 학습 설정 (v3r15d 와 같게, 바뀌는 것만 적음)

- 사전학습: 생성기 v3 8,000장면 × 씨드 3, 3 epoch — 저장된 `pre_*` 가중치를 그대로 쓴다(다시 안 만듦).
- 미세 조정: 실제 33장(연출 뺌) + 변형 사본 3, 100 epoch, lr 3e-4, 씨드 3 평균, 환경 변수 `ROLE_OTHER_NEG=1 ROLE_DROP_SAFE=1 ROLE_LOOSE_SHIFT=1`, 회전 ±15°. **바뀌는 것 하나: 미세 조정 묶음에 3-1 의 11-14 장면을 더한다**(M1 = 공개 장면만, M2 = + 판 중 장면). 11-14 장면에도 같은 변형 사본 3.
- 나눔: `role_v2_train.py` 의 4겹(10-31 오전 / 오후 / 11-07 오전 / 오후) 그대로. 11-14 학습 쪽은 **모든 겹의 학습에** 들어가고, 시험 겹은 지금과 같다.
- 노트북 CPU. v3r15d 한 벌이 수십 분이었다 — 장면이 늘어 더 걸린다(재지 않음).

### 4-2. 합격 기준 (M1, 나눔 모델 숫자로만 판정)

- **(p1) E1 pair:** 맞은 상자가 기준선(지금 방법으로 0단계에서 다시 잰 값, 참고 19/28)보다 **3상자 이상** 많다.
- **(p2) E1 지키기:** hand·meld·river 틀린 상자가 기준선 + 2 이내, loose 맞은 상자가 기준선 이상, 화료자 쪽 장면(손패·울기 장수 맞음) 수가 기준선 이상.

## 6. 위험과 한계

- **표본이 작다.** 학습에 더하는 서로 다른 짝 배치는 9판, E1 의 pair 는 28상자다. (p1)의 3상자는 큰 효과만 잡는다. 통과하더라도 "한 매장·한 거치" 의 버릇을 배운 것일 수 있다.
- **11-14 는 한 매장·한 날·한 거치다.** 짝을 놓는 자리 버릇(손패 줄 위, 강 옆)이 그 매장 사람들 것이다. 다른 탁자 사진은 없다(problem_log 남은 문제 12).
- **생성기 v3 의 짝 배치 가정**과 실제가 다를 수 있다. 이번에는 생성기를 안 고친다(바뀌는 것 하나).
- **역할 모델은 화료자 기준 1회다.** 동시 론에서 짝이 다른 화료자 옆에 있으면 모델도 떼어 둔 패로 부른다(r05 다시 읽기 0.60). 그 경우는 앱 공유 규칙이 맡는다.
- **A 의 E2 값을 얻는 길이 두 단계(서버 응답 저장 → Dart 규칙)** 라 앱 흐름 값과 조금 다를 수 있다(추적 도라 없음). 판 중 추적 도라는 평가에서 뺀다 — A·M 모두 같은 조건.
- 라벨의 "절반 넘게 보임" 눈대중, 검출기가 못 잡는 패가 세트에 없는 점은 그대로다(HANDOFF 11-15).
