# 학습 방식과 평가 방식 정리

2026-11-11 대화에서 나눈 내용을 쉬운 말로 정리한 것이다. 세부 명령·숫자는 `experiments/tile_classifier/README.md`(끝 절 "누수 금지 풀"·나눔 대응표), `experiments/speed/ROBUST.md`, `docs/metrics.md`, `docs/problem_log.md` 가 원본이다.

## 1. 지도학습이다

세 모델 모두 사람이 정답(라벨)을 붙인 데이터로 "이 입력이면 이 답"을 배우는 **지도학습**이다. 비지도학습·강화학습은 쓰지 않는다.

| 모델 | 하는 일 | 정답(라벨) | 비고 |
| --- | --- | --- | --- |
| 검출기(YOLO26n, 회전 상자) | 사진에서 패가 어디 있는지 상자로 찾기 | 패마다 그린 상자(앞면·뒷면) | 공개 사전학습 가중치 `yolo26n-obb.pt` 에서 출발해 우리 사진·합성 사진으로 추가 학습(전이학습) |
| 분류기(MobileNetV3 Small) | 잘라 낸 패 한 장이 37종 중 무엇인지 | 패 조각마다 붙인 종류(1m~9m, 白, 적5 등) | |
| 역할 모델 | 각 패가 손패·울기·떼어 둔 패 등 무엇인지 | 상자마다 붙인 역할 | 합성 장면 생성기로 먼저 학습한 뒤 실제 라벨로 다듬음 |

라벨이 틀리면 모델은 틀린 답을 그대로 배운다(예: 손패 끝 3장을 울기로 단 라벨이 틀린 자동 반영의 원인이었음). 그래서 학습 전에 라벨을 따로 검토받는다.

## 2. 폴드(fold)와 교차 검증

### 왜 필요한가

모델이 공부(학습)한 사진으로 시험을 보면, 답을 외워서 맞힌 것인지 실력인지 알 수 없다. 그래서 **공부할 때 안 본 사진**으로 시험을 봐야 한다. 그런데 사진이 적어 일부를 시험용으로 영영 빼 두기는 아깝다.

### 방법

사진을 몇 묶음으로 나누고, 각 묶음을 **폴드**라고 부른다. 묶음 하나씩을 빼고 학습한 모델을 묶음 수만큼 만든다.

| | 공부한 묶음 | 시험 보는 묶음 |
| --- | --- | --- |
| 모델 ① | 2, 3 | **1** |
| 모델 ② | 1, 3 | **2** |
| 모델 ③ | 1, 2 | **3** |

묶음 1의 사진은 묶음 1을 안 본 모델 ①로, 묶음 2는 모델 ②로 채점한다. 이렇게 하면 모든 사진을 "처음 보는 사진"으로 한 번씩 채점할 수 있다.

### 이 프로젝트에서

- 묶음: **B·C·D 연출 사진 / 10-31 오전 / 10-31 오후**(역할 모델은 오후를 다시 둘로 나눔: pmA·pmB).
- 모델 종류마다 나눈 방식이 조금 다르다: 검출기 a·b, 분류기 bcd·am·pm, 역할 모델 bcd·am·pmA·pmB.
- 11-07 매장 사진은 원래 학습에 쓰지 않았으므로 운영 모델이 그대로 처음 보는 시험이 된다.
- **운영 모델(prod)** 은 모든 개발 사진으로 학습한 것이라, 그 사진들로 채점하면 거의 100% 가 나온다(외운 시험).
- **폴드 모델** 은 채점용으로만 만들어 둔 것이다. "처음 보는 매장 사진에서 실제로 얼마나 맞힐까" 를 짐작할 때 쓴다.

### 용어

- **K-폴드 교차 검증(K-fold cross-validation):** 위 방법 전체.
- **그룹 K-폴드(Group K-fold) / 리브 원 그룹 아웃(Leave-One-Group-Out):** 사진을 무작위로 섞지 않고 장면·시간대 묶음으로 나누는 것. 같은 장면을 여러 번 찍은 사진이 공부와 시험에 나뉘어 들어가면 사실상 같은 사진으로 시험 보는 셈이라 묶음으로 나눈다.
- **아웃 오브 폴드 예측(out-of-fold, OOF):** 각 사진을 "그 사진을 안 본 모델"로 낸 답. 회귀 채점의 `--models fold` 가 이것이다.
- **홀드아웃(holdout):** 아예 학습에 안 쓰고 남겨 둔 시험 세트(11-07 사진 등).
- 교차 검증은 과적합을 **막는** 방법이 아니라 **드러내는**(측정하는) 방법이다. 외운 시험(prod)과 처음 보는 시험(fold) 점수 차이로 모델이 외웠는지 일반화했는지 판단한다. 과적합을 실제로 줄이는 것은 아래의 합성·증강·사전학습이다.

## 3. 데이터 누수 방지 — "누수 금지 풀"

시험 볼 사진이 다른 경로로 공부 자료에 새어 들어가는 것을 막는 규칙이다.

- 합성 데이터는 실제 사진에서 **패 조각을 오려 내서** 펠트 위에 붙여 만든다.
- 오전 사진을 시험 보려고 오전 사진을 학습에서 뺐는데, 합성에 오전 사진 A에서 오려 낸 "3만" 조각을 썼다면, 모델은 A 속의 그 3만(같은 조명·각도·얼룩)을 이미 본 셈이다. 시험 점수가 실제보다 좋게 나온다.
- 그래서 합성 재료 통(풀)을 나눔마다 따로 만들고, **시험 볼 쪽 사진에서 나온 조각은 그 모델의 재료에 하나도 넣지 않는다.** 패 앞면·뒷면·펠트 배경 조각 모두.

| 모델 | 공부(학습·합성 재료) | 시험 보는 사진 | 합성에서 빼는 조각 |
| --- | --- | --- | --- |
| 오전 시험용 모델 | 오후 사진 + 기타 | **오전** | **오전** 사진에서 나온 조각 |
| 오후 시험용 모델 | 오전 사진 + 기타 | **오후** | **오후** 사진에서 나온 조각 |

"기타" 는 시험에 쓰지 않는 다른 사진들로, 양쪽 재료에 다 들어간다.

## 4. 합성과 증강

둘 다 쓴다. 하는 일이 다르다.

- **합성(synthetic data):** 없는 장면을 새로 만들어 데이터 양을 늘린다.
  - 검출기: 라벨 붙은 패 조각을 펠트 사진 위에 붙여 장면을 만든다(9회차는 나눔마다 합성 8,000장으로 먼저 학습 → 실제 사진으로 다듬음).
  - 역할 모델: 사용자가 정해 준 규칙(손패 줄·울기 묶음·떼어 둔 패·외톨이 앞면 등)으로 장면을 만드는 합성 장면 생성기 v3 로 먼저 학습.
  - 합성 위치·종류를 알고 붙이므로 라벨이 자동으로 따라온다(이것도 지도학습).
  - 위 누수 금지 규칙이 그대로 걸린다.
- **증강(augmentation):** 있는 학습 데이터를 조금씩 변형해 같은 패를 여러 모습으로 보여 준다.
  - 검출기: 뒤집기·회전·모자이크 등.
  - 분류기: 패 조각을 확률 0.5 로 180° 돌리기(cls6 부터, 거꾸로 놓인 패) 등.
  - 역할 모델: 회전 ±15°(v3r15), 일부 패 무작위로 빼기, 기울기, 손패 끝에서 떨어진 2~4장 등.
  - 세부 값(밝기·색 범위 등)은 학습 스크립트마다 다르다(이 문서에서 하나하나 확인하지 않음).

## 5. 회귀 테스트

무언가를 바꿨을 때, 예전에 잘 되던 것이 망가지지 않았는지 다시 확인하는 시험이다("뒤로 돌아갔다" 는 뜻).

- 세트(`experiments/speed/robust_suite.py`): 테스트 원본 40장(B·C·D + 10-31 + 11-07, 가림·사용자 문제 사진 뺌)에 일부러 나쁜 조건을 입힌 **고정 21가지 변형** — 회전 ±3·±10·±25°, 축소 0.8·0.6, 흐림 약·강, 밝게·어둡게, 전구색·형광등, 손 가림, 펠트·테두리 색 바꾸기, JPEG 강압축.
- 40장 × 21 = 840장(같은 장면 두 번 세는 무게를 넣어 966회)을 매번 똑같이 읽히고, 맞춘 장면·패, 그리고 가장 중요한 **"경고 없이 틀린 것(unsafe)"** 을 센다.
- 판정 규칙(바꾸기 전에 미리 정함): unsafe·틀린 자동 반영이 하나라도 늘면 안 되고, 패 단위가 기준보다 2% 넘게 떨어지면 안 된다.
- 회귀 변형은 증강과 모양이 비슷하지만 **학습에 쓰지 않는다.** 시험 전용이고, 결과를 보고 그 사진에 맞춰 규칙을 고치지도 않는다(시험 문제를 미리 보여 주는 셈이므로).
- 두 갈래로 돌린다: `--models fold`(처음 보는 사진에서도 되나) / `--models prod`(기존 것이 망가지지 않았나).

## 6. 예: 2026-11-11 재저장 생략 결정

- 기기 판독(태블릿 단독)에서 받은 사진을 서버처럼 q90 으로 다시 저장하는 단계를 빼면 장면당 약 1.4초 빨라진다(5.92 → 4.46초).
- prod 회귀로 비교하니 장면 수는 같고 패는 +13 이었지만, 형광등 변형 k12(D 장면 사진) 한 장이 경고 없이 틀리는 쪽으로 바뀌어 unsafe 가 11 → 13 이 되어 규칙에 걸렸다.
- 같은 방식끼리 다시 돌리면 답이 똑같고(0/120), 방식 사이 차이는 그대로 재현됐다 → 차이는 재저장 여부 때문. 원본·가벼운 변형은 같고, 경계 조건(강한 흐림·노출·색 틀어짐·0.6배 축소)에서만 갈렸다.
- 사용자 결정으로 기기 판독은 재저장 생략을 택했다(실사용에서 1.4초가 크게 체감됨). 위험은 알고 감수.
- fold 회귀(처음 보는 사진)로는 아직 비교하지 않았다.
