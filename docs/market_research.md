# 시장 조사와 수요 확인 (2026-10-23)

새 세션이 "비슷한 게 이미 있나", "누가 쓸까" 를 다시 조사하지 않도록 정리한 것. 출처는 각 항목 링크. 정확도·판매 여부는 확인 안 한 것이 많다(표시함).

## 결론

- "손패 촬영 → 점수 계산" 앱은 국내외에 이미 많다. 개인용 앱으로는 이것만으로 차별화가 어렵다.
- 일반 패로 **테이블 전체**를 읽어 리치·방총자·뒷도라까지 판독하고 **대국 기록·정산**까지 하는 상용 제품은 찾지 못했다. 탁자 단위 자동화는 전용 IC 패 탁자(パイリーダー, 2012)나 대학 연구(Projection Mahjong)뿐.
- 그래서 차별점은 "계산" 이 아니라 "기록 자동화" 이고, 대상은 개인보다 **매장·대회·오프라인 방송** 쪽이 유망하다(검증 전 가설).
- 커뮤니티·스트리머 반응은 좋지 않았다(2026-10-23, 설명만 듣고 한 반응). 이유는 **"이미 있다"**(손패 촬영 앱이 많다)였다(2026-10-23 사용자 확인). → 차별점(테이블 전체 판독 + 기록 자동화) 전달이 과제. "필요 없다"·"설치 귀찮다"·"정확할까" 는 나오지 않았다.

## Projection Mahjong (후쿠이대 長谷川 연구실) — 키오스크와 가장 가까움

- 출처: [EC2023 논문(공개, 본문 읽음)](https://ipsj.ixsq.nii.ac.jp/record/227470/files/IPSJ-EC2023023.pdf), [2026-02 저널(Multimedia Tools and Applications, 오픈 액세스, 2026-11-08 본문 읽음)](https://link.springer.com/article/10.1007/s11042-026-21151-7)
- 구성: 탁자 바로 위 카메라 + 프로젝터(스피커 내장) + PC. 프로젝터가 자풍·장풍·국·본장·리치봉 자리·점수·연출을 탁자에 투영. 파란 화면 투영 → 카메라로 투영 위치 자동 보정.
- 흐름: 각자 오른쪽 앞 "트리거 영역" 에 **패를 엎어 놓으면 화료 선언**(ResNet18 이진 분류, 250장 100%) → 프로젝터가 손패·울기·화료패·도라 놓을 자리를 비추고 사람이 **옮겨 놓음** → YOLACT 인식(약 3.5초) → Python `mahjong` 라이브러리로 점수 → 연출. 리치봉은 가운데 영역에서 분류 모델, 30fps 5회 연속일 때 인정, 국당 1회만. 일발은 도라 표시패를 눕혀 표시. 유국·종료는 키보드 키. 방총자 결정 방법은 논문에 없음.
- 실험(8명, 동풍전): 점수 확정 시간 손계산 32.0초/13.8초 vs 시스템 28.4초/33.8초 — **재배치·확인·재인식 때문에 빠르지 않았음**. 분위기(대면 대비 p=0.021)·시청각 즐거움은 유의하게 좋음, 원활함·사용성은 유의차 없음. 한계: 패 인식 오류, 강·패산 미인식, 우연역 대부분 미지원.
- **2026 저널 = V2 (본문 확인, 위 EC2023 은 V1).** 추가: 리치를 자리별로 감지, 네 명 점수 자동 관리, 유국 텐파이 자동 판정, 종료 조건 자동, 역 음성 안내, 구역별 인식 모델. 화료패를 **화료자 자기 구역에 놓으면 쯔모, 방총자 구역에 놓으면 론**(= 방총자 결정 방법), 화료패를 눕히면 +1판(영상개화 등), 도라 표시패를 전부 눕히면 일발. 여전히 국 시작은 키 입력, 화료 후 구역에 맞춰 패를 놓음 — 본문은 "각 구역에 놓는다" 지만 **데모 영상에서는 손패는 그 자리(화료자 앞 구역)에서 눕히기만 하고, 도라 표시패와 화료패만 구역으로 옮김**(2026-11-08 사용자가 영상 확인).
  - 점수 확정 시간(RQ3, 10명 연구실 아마추어, 퀴즈 손을 탁자에 배치): **시스템 쯔모 15.88±7.11초·론 15.06±3.16초(패 놓는 시간 포함)** vs 손계산(역 모르는 1명 뺀 9명) 54.21·65.48초, 숙련자 2명만 29.25·45.48초. 인식+계산은 약 2.3초, 나머지는 사람이 패 놓는 시간. 손계산 쪽은 패 다루는 시간 제외. 정확도 20문제 시스템 60/60, 사람 평균 44.3/60.
  - 인식: 손패 22장 사진 99.30%(V1 86.71%), 화료 신호 250/250, 리치 오검출 0.004%(52,800프레임). 한계(논문 스스로): 연구실 한 곳만, 조명·그림자·카메라 높이·탁자·패 종류 바뀜 미검증, 흐린 사진에서 오독, 실험 인원 적음. 비용 어림: 랙 $140 + 프로젝터 $350~700 + 4K 카메라 $70 + GPU 노트북 $1,400.
  - **고친 것(2026-11-08):** 앞서 "손계산보다 빠르지 않았다" 고 쓴 건 EC2023(V1) 결과였다. V2 는 손계산보다 2~4배 빠르다. 남은 차이는 "도라 표시패·화료패를 구역으로 옮겨야 함·국 시작 키 입력·한 실험실 조건".
- 가져올 것: (1) 엎은 패로 화료 신호 → 카메라 헤드 자동 촬영 트리거, (2) 리치봉 N프레임 연속 감지, (3) 패를 옮기게 하지 말 것 — 확인 단계가 남으면 자동화 이점이 사라짐 → 정확도 측정 후 자동 반영, (4) KPI "화료 선언 → 점수 확정 시간" 을 손계산과 비교, (5) 키오스크 화면으로 프로젝터도 선택지(밝은 매장 조명은 미검증).
- 2026 V2 읽고 다시 고른 것(2026-11-08): (1) 소개·비교 숫자 — V2 15초(손패 눕히기·도라 표시패·화료패 옮기기 포함) 대 우리 앱 흐름 중앙 6.22초(표 1-114, 옮기기 없음), 손계산 기준 54·65초/숙련자 29·45초/정답 44.3/60. (2) 리치 = 자리별 구역 분류 + 5프레임 연속, 실제 대국 영상 52,800프레임으로 오검출 측정 → 우리 리치 추적 버그(`cameraMoved` 가 후보를 지움, 2차 대국 0/5)와 평가 방식에 참고. (3) 유국 텐파이 자동 판정을 V2 가 함 → 우리 남은 일. (4) 시간 측정 규약(신호 → 결과 표시, 재인식 포함 전체 시간)을 매장 손계산 비교에 그대로. (5) 화료 신호 엎은 패는 동시 론·유국 공개와 헷갈리지 않는 "몸짓" 신호라 볼륨키 대안 후보(10-28 자동 촬영 안 하기 결정과는 별개). 안 가져올 것: 일발·영상개화를 패 눕히기로 표시(사용 규칙이 늘어남), 도라 표시패·화료패를 구역으로 옮기기.
