## 문제 1: 칸 번호로 상대 손패 추정 — hero 로는 접음, 대기 수트로 재정의해 천봉 1,000판 → "사이"

- **원인:** 11-20 밤에 시작한 hero 손패 실험을 사용자 "재개해" 로 이어 v2(리치 텐파이 조건 · 위쪽 한계 C\* · C\*mix)까지 돌리니 결과 전 기준 두 개 모두 **❌ 접음**(13장 적중 B 6.13 · C 5.69 · C\* 6.02, 표 17-1). 완전 정렬하는 세 판에서만 수트 구성이 좁혀짐. 사용자 "외부에서 검색해서 알아볼래?" → 理牌読み(리파이 읽기)의 "수트 장수 → 대기 수트" 를 찾음(계획서 6절, 칸 위치를 쓴 연구는 못 찾음).
- **해결방안:** 사용자 "대기 수트로 재정의" → 자료 "천봉 공개 패보 + 습관 흉내"(계획서 7절).
  - 진짜 손패 정답 판이 바닥나 tenhou.net 2026년 四鳳南喰赤 147,980판에서 씨 20261121 로 1,000판(1초 간격, 실패 0, 내려받기 사용자 허락) → 국 10,563 · 리치 7,480 → 개발 200판 1,437 / 시험 799판 6,043.
  - 칸 번호는 우리 8판 정답 줄에서 센 습관(H1 완전 정렬 r12 · r17 · r19 / H2 수트 묶음 · 끝 붙임 r16 · r13 / H3 거의 정렬 r11 · r15 · L16)을 3:2:3 으로 흉내 — 진짜 사람 칸 번호 아님.
  - 사용자 "다른 기술도 종합해서 확인하는 거지?" → 결과 전에 강 읽기 특징 23개를 모은 학습 기준선 S 를 더하고 주 판정을 SP − S 로 바꿈.
  - 시험 6,043 리치: 대기 수트 1위 적중 S 45.3% → SP 49.8%, **SP − S 섞음 +4.4%p [+3.2, +5.8] · H1 +8.6%p [+6.5, +10.9] → 판정 "사이"**. H2 +0.8%p [−1.6, +3.2] · H3 +2.8%p — 이득은 완전 정렬하는 사람에게 몰림(표 17-2).
  - 구현 · 실행 Opus 5.5 높음 하위 에이전트(14 프로세스, 개발 28분 · 시험 1시간 53분), 세션이 `riichi_test.jsonl` 에서 따로 계산해 A · B 가 소수까지 같음, 누설 검사 40/40. API 0달러.

### 시행착오

1. v1(11-20)과 v2 는 입력이 다름 — 도중에 `assets/paifu` 가 다른 세션(r18 복원)에서 다시 쓰여 차례 116 → 123. 그래서 v1 숫자와 나란히 비교하지 않음.
2. 지표 눈금을 세션이 따로 잼: 수트별 장수 정답을 줘도 13장 적중은 +2.2장뿐 → "+2장" 기준은 수트 구성을 다 아는 것과 맞먹는 문턱이었음(기준은 안 바꾸고 판정 그대로).
3. 처음 비교 기준 B 는 한 줄 휴리스틱이라 칸 번호 효과가 부풀 수 있음 — 사용자 질문으로 인정하고 S 를 결과 전에 더함. 개발 판은 SP − S +7.4%p 였다가 시험에서 줄어, 개발 판 숫자로 말했으면 부풀었을 것.
4. ε(칸 번호 가정을 A 와 섞는 비율)은 계획에 없던 세기 — 0 으로 해도 판정 같음.
5. 한계: 칸 읽기 정확도(나간 칸 7/10 · 들어간 칸 3/7, 표 12-16)를 곱하지 않은 위쪽 한계. 진짜 판 r18 은 배패 줄 어긋남 하나("3s 9m 5s")로 P · SP 가 삭수를 강하게 가리킴 — 사람의 어긋남은 단단한 제약을 깨 확신 있게 틀림.
