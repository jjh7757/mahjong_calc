## 문제 1: 10-31 매장 오후 사진에서 떼어 둔 화료패·모서리 울기·내놓은 표시패를 못 읽음

- **원인:** 자리 판독은 화료자 자리 크롭(폭 40)만 봄. 떼어 둔 화료패, 모서리 울기, 리치 화료 때 탁자 위에 내놓은 표시패 2장이 크롭 밖에 있었음. 오후 15장 중 손패 정답 3장뿐이었고, 틀린 12장 중 5장은 손패 줄은 맞고 크롭 밖 패만 빠진 것.
- **해결방안:** 화료자 쪽 넓은 구역을 따로 읽는 `/v2/seatwide`(위치는 YOLO, 종류는 조각)와 화료패 후보 고르기, 탁자 위 표시패 짝 찾기를 넣음 → 운영 259c39a·d9da053 배포. 해결됨(매장 오후 앱 흐름 3/13 → 10/13).

### 시행착오

1. 10-31 매장 사진 중 정답이 없던 19장을 원본 확대로 직접 읽어 정답을 만듦(모양 검사 19/19). 이걸로 다시 채점해서 크롭 밖 문제가 드러남.
2. 화료자 쪽 탁자 절반을 통째로 Gemini에 3번 읽힘 → 떼어 둔 패 자리는 더 잘 잡지만 패가 작아져 오독이 늘어 오전 4/10·오후 1/15. 미채택.
3. 위치는 YOLO로 탁자 절반에서 찾고 종류는 조각으로 읽음 → 오후 6/15로 나아졌지만 B·C·D가 8/12로 떨어져 단독으로는 미채택. 운영 답과 합치고 "펠트 위 외톨이 1장을 더해 화료형이면 떼어 둔 패"(사용자 규칙: 탁자 위 표시패는 2장 이상) → 오후 8/15.
4. 사용자 제안으로 손패만으로 가능한 화료패를 세어 봄 → 정답 23장 모두 정답이 후보 안에 있었음. 손패가 한 장 모자라면 대기패로 화료패 후보를 내게 함.
5. `/v2/seatwide` 를 앱 흐름에 붙임 → 오후 3/13 → 7/13.
6. YOLO가 놓친 돌아간 낱장을 펠트 위 패 크기 색 덩어리로 찾음 → 로컬 오후 5/26 → 19/26, 운영 259c39a 확인 오후 10/13·틀린 자동 반영 0.
7. 격자를 사진마다 맞추면 나아지나 시험 → 14/23 → 15/23로 흔들림 범위, 미채택.
8. 리치 화료 때 탁자 위에 내놓은 표시패 짝 규칙(강 높이·손패 줄 가까이의 2장 묶음) → 리치 10장 중 짝 맞음 0 → 6, 리치 아닌 장면 헛 짝 0. 운영 d9da053 배포. 판 상태 추적 리치를 흉내 내 재니 오후 표시패 6 → 8/13.

## 문제 2: 넓은 구역 판독을 붙이니 판독이 느려짐

- **원인:** 처음엔 자리·강 판독이 끝난 뒤 이어서 불러 시간이 그대로 더해짐(오후 중앙 16.2초). 같은 순간에 미리 보내게 바꾸자, 운영 서버(t4g.small)에서 넓은 구역 틀 잡기가 자리 판독과 CPU를 나눠 써 자리 판독이 2~3초 느려짐. 로컬 노트북에선 안 보이던 비용.
- **해결방안:** 미리 보내기 + 서버에서 검출을 한 번에 하나만, 자리·강 먼저 돌리는 우선순위 게이트 → 운영 9c2e4c5 배포(22:20). 해결됨.

### 시행착오

1. 넓은 구역 판독을 자리 판독과 같은 순간에 미리 보냄(로컬) → 오후 중앙 16.2 → 10.3초.
2. 운영에서 두 흐름을 동시에 돌려 비교 → 서버가 포화돼 시간 비교가 안 됨. 강 끝 헤지 12초가 거의 매번 걸려 부하만 더했음.
3. 운영 단독 흐름으로 다시 잼 → 자리 판독 10.4 → 13.1초로 느려짐. CPU를 나눠 쓴 탓으로 봄.
4. 우선순위 게이트 배포 → 자리 판독 10.2초로 복귀, 전체 14.5 / 19.7 / 65.9초, 틀린 자동 반영 0.
