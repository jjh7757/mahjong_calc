## 문제 1: 합성 사전학습이 회귀 세트는 좋게 하고 테스트는 나쁘게 함(개선 계획 7-2)

- **원인:** 검출기 몫. 합성으로 사전학습한 검출기 상자에 옛 분류기를 붙이면 나빠졌고, 분류기만 바꾸면 좋아졌음.
- **해결방안:** 분류기만 합성 사전학습(7-2a, 새 씨드) → 채택, 분류기 v2(서버 feat/cls-alt 599473e). 운영 반영은 11-07 08e44b0, 해결됨.

### 시행착오

1. 7-2 검출기 + 분류기 둘 다 합성 사전학습(실제 패 크롭을 마작 규칙대로 놓은 8,000장면) → 회귀 unsafe fold 26 → 22·prod 17 → 7 로 크게 좋아짐. 그러나 테스트 15장 189 → 188, 색 바꾼 15장 145 → 139 로 미채택.
2. 검출기만 바꿔 봄 → 회귀 unsafe 26 → 50. 새 검출기와 옛 분류기의 조합이 문제.
3. 7-2a 분류기만, 이미 한 번 본 계열이라 기준을 "unsafe 4 이상 줄어야" 로 올려 미리 적음 → fold 26 → 22, prod 17 → 11, 테스트·색 바꾼 그대로 → 채택.
4. 서버 시간 첫 측정 +0.14초(기준 +0.1 초과) → 바꾸지 않은 검출 단계까지 같이 느려져 노트북 부하로 보고, 사용자 결정으로 번갈아 3번 다시 잼 → +0.00초.

## 문제 2: 격자가 초록 펠트·이 탁자 비율에 기대서 다른 탁자에서 안 될 것(개선 계획 8b)

- **원인:** 지금 격자는 사진 좌표 선 4개 + 이 탁자에서 잰 상수. 색 바꾼 15장 0/15, 전구색 0/32 가 그 증거.
- **해결방안:** 가운데 기기·패산으로 중심·방향·패 크기를 잡는 탁자 기준점. 앱이 격자를 가졌으면 지금 경로, 없으면 새 경로(hybrid) → 채택(기본 켬 후보, 서버 feat/table-frame 18a54ca). 운영 반영은 11-07.

### 시행착오

1. 8b-1 오프라인(색 안 씀): 기기 찾기 개발 25/26·테스트 15/15·색 바꾼 15/15. 패산은 화료 때 3/26 이라 판 시작(패산 올라온 첫 프레임)에만 쓰고 화료 때는 기기로.
2. 8b-2 패 단위 구역표 JSON 하나를 앱(Dart)·서버(Python)가 같이 읽게 함 → 같은 예제로 같은 상자.
3. 8b-3 `rot`(기준점으로 세워 자르기) → 테스트 펴기 없이 158 → 191, 색 바꾼 145 → 181. 그러나 개발 패 434 → 429, 경고 없는 틀린 자동 1 → 미채택. 원인은 크롭 정의(바람개비 경계에서 잘린 손패 끝, 넓어진 크롭에 들어온 떼어 둔 패, 잘린 조각이 헛 짝).
4. 8b-3b `rot2`(세 손실을 고친 것) → 겨냥한 손실은 사라졌지만 새 손실 두 장면으로 433 → 429, 미채택.
5. 8b-3c 처음 설계는 "저장 격자 ↔ 기준점이 1u·3° 안이면 지금 경로" 였음 → 측정 전 대조해 보니 saved 6/31. 사진 한 장의 방향 추정이 같은 거치에서도 0.3\~4.2° 흔들림. 문턱을 버리고 "앱이 격자를 가졌는지(`grid_src`)" 로 정함 → 개발 32/32 답 같음, 격자 없을 때 191·179 → 채택(자정 직후 판정).

## 문제 3: 오프라인 실험 때 태블릿 → 폰 헤드 연결이 여러 번 끊김
