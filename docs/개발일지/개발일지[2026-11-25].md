## 문제 6: supervisor 가 흐름 밖 · 사용자 답을 넣는 길에 구멍 — 구현 4-①(흐름에 끼움) · 4-②(확인 페이지)

### 시행착오

## 문제 7: 패보 · 측정 기록이 JSON · 마크다운에 흩어져 SQL 로 못 물음 — 운영 공용 Postgres 에 적재

## 문제 8: 대국 기록을 볼 곳이 남의 사이트(마블리)뿐 — 대국 기록 사이트 `mahjong-records` 와 앱 올리기

- **원인:** 끝난 대국은 태블릿 안에만 있고, 밖에서 볼 기록은 앱이 자동 등록하는 마블리 쪽뿐. 사용자 결정(설계서 `docs/records_site_design_1125.md` 0절): 마블리와 연계 안 함(남의 사이트) · 화면도 흉내 안 냄 · 로그인은 관리자 한 명 + 매장(태블릿) 키 · 조회는 링크로 공개(색인 막음).
- **해결방안:**
  - **서버 · 웹**(새 저장소, 2aaca24): FastAPI + Postgres(database `mahjong` 의 schema `app` — 분석 표 `public` 과 섞이지 않게) + React. 업로드 멱등 upsert(`created` · `updated` · `unchanged`) · 매장 키는 sha256 만 저장 · 관리자 scrypt + 서명 쿠키 · 5번 틀리면 15분 잠금 · 웹 여섯 화면(순위표 · 멤버 · 대국 목록 · 상세 · 패보 재생 · 관리자). 판독 서버와 저장소 · 컨테이너를 나눔(DB 장애 · 배포 실수가 판독을 막지 않게), 기존 도메인의 `/records` 경로로.
  - **앱 올리기**(4ecfec0): `lib/game/records_upload.dart` — 본문(대국 + 정산 4줄 + 패보 + 앱 버전) · 대기열 · 401/403 멈춤 · 연결 실패는 남김, 설정 "기록 사이트" 화면(기본 꺼짐) · 지난 대국 "기록 ✓". 새 시험 21개. 태블릿 사본 앱 `.ondevice` 에 설치해 실제 업로드 확인(시험 대국은 숨김 · 삭제).
  - **패보 재생**(8e8b5f2): 앱 재생 화면과 같은 구성(초록 탁자 + 오른쪽 패널), 앱 패 그림(CC0) 사용.
  - **엔진**(dfa2425 · 5b297f9): 앱 순수 Dart 점수 · 복기 엔진을 `dart compile js -O2` 로 묶음(168KB · gzip 54KB) — 로직을 TS 로 옮기지 않음, **패보 22판 Dart VM ↔ JS 다름 0.** 패보 화면에 들어올 때만 불러옴.
  - **마블리 가져오기**(d547622 · ded807d): 받아 둔 1,600판을 폐기된 전용 매장으로 넣는 SQL(여러 번 부어도 같음, 규칙에 안 맞는 판은 사유와 함께 건너뜀), 11-14 2반장 9판 · 3반장 11판 패보를 그 대국에 붙임. 이름 공개 여부는 사용자가 정함.

### 시행착오

1. 키오스크 화면 안내 글씨가 어두운 배경에서 안 보임 — `kioskWrap` 바깥 context 로 테마를 읽어 밝은 테마 글자색이 그려짐 → `kioskTextTheme` · `kioskColorScheme`, 태블릿에서 확인(a21cbc3).
2. 엔진 첫 묶음은 커밋 전 원본에서 만들어짐 → 커밋된 dfa2425 에서 다시 묶음(336c258, 22판 다름 0).
3. 엔진 룰은 앱 기본값(`RuleSet.standard`) — 룰을 바꾼 매장은 점수가 다를 수 있음. 정산 · 별은 앱 값을 그대로 믿음(서버 재계산 없음).
4. 관리자 잠금이 전역이라 누가 일부러 틀리면 관리자도 15분 못 들어감. 마블리 판과 앱 대국이 같은 판이면 두 번 셀 수 있음.
5. 관리자 비밀번호 · 매장 키는 저장소 밖 무시 파일에만 둠(커밋 · 대화에 안 씀).
