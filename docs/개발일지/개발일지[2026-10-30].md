# 개발일지(2026-10-30)

## 문제 1: 매장 가기 전 전체 점검에서 결함이 여럿 나옴

- **원인:** 기능을 빠르게 붙이면서 추적·촬영 동시성, 재시도, 서버 운영 설정을 따로 검토한 적이 없었음.
- **해결방안:** 앱·서버를 네 영역(엔진·게임 / 판독·추적 / 화면 / 서버)으로 나눠 검토하고 고침. 앱 6건 + 점수·기록 5건(26afca3·22e4086), 헤드 묵은 프레임(1c22618), 서버 10건(운영 d9cc340). 해결됨.

### 시행착오

1. 추적기가 확정보다 적게 읽히면 기준을 안 바꿔서 5초마다 읽기를 끝없이 반복함(300초에 50회, 429 원인) → 그 순간을 새 기준으로 삼게 고침.
2. 왕패 상자가 격자 편집 밖에서도 끌림(전날 "편집 on/off" 결정 위반) → 편집 중에만 끌리게 함.
3. 점수: 더블 역만을 꺼도 대사희가 2배로 계산됨, 울었는데 뒷도라를 셈 → 고침.
4. 헤드 `/capture` 가 1.5초 뒤 묵은 프레임을 성공으로 돌려줌 → 손패 공개 전 사진으로 판독할 수 있어서 3초 안에 새 프레임이 없으면 실패로 바꿈.
5. 서버: 실행기 스레드 수, 분당 제한이 추적·화료를 한 통으로 셈, Gemini 429 재시도 없음 등 → 토큰 버킷·재시도로 고쳐 배포함.
6. 배포 뒤 앱 흐름 B·C·D 12회 → 12/12, 틀린 자동 0, 10.5 / 12.7 / 29.1초, 429 0.

## 문제 2: 집 실기기 점검에서 패가 없는데 추적이 계속 읽기를 보냄

- **원인:** 폰이 위로 누워 흰 천장을 찍자, 천장 전체가 "흰 면"이라 노출 흔들림이 패 1~2장 분량 변화로 잡힘.
- **해결방안:** 확정과 같게 읽히면 한 번에 확정, 헛 변화는 다음 읽기를 미루기, 탁자를 확인한 뒤에만 추적(ac449d1). 해결됨.

### 시행착오

1. 태블릿 + 폰 헤드로 29분 → 모서리 읽기 28회, 헛 강 버림 11개.
2. 남은 프레임 150장을 재생해 규칙만 바꿔 봄 → 24회.
3. 확정과 같게 읽히면 한 번에 확정 → 15회.
4. 헛 변화면 다음 읽기를 10·20·40초… 최대 120초 미룸 → 10회.
5. 탁자 확인 뒤에만 추적 → 0회.
6. 같은 점검에서 자동 맞추기 10회 뒤 멈춤, 편집 꺼짐 때 끌기 안 됨, 헤드를 뒤로 보내면 촬영 실패(묵은 프레임 안 줌)를 확인함.
7. CI APK 는 노트북 빌드와 서명이 달라 덮어 설치가 안 됨 → CI 도 같은 debug 키로 서명하게 함(93dea71).

## 문제 3: 유국으로 남은 리치봉을 이번 판 리치로 볼 위험

- **원인:** 리치봉만으로 리치를 정하면, 유국 뒤 남은 봉 주인을 이번 판 리치로 착각함(사용자 지적).
- **해결방안:** 유국한 판의 리치 자리를 기억해 두고, 봉이 남은 자리는 강의 눕힌 패(리치 선언패)로 리치를 정함(82e13e3·6396644). 서버 눕힌 패 판정을 고쳐 운영 배포(4954b47). 해결됨.

### 시행착오

1. YOLO11 강 틀의 가로/세로 비율 > 1.15 로 판정 → 처음엔 "헛 잡음 2"로 적었지만, 그림을 보니 B 왼쪽 2통은 실제로 눕혀 있었음. 정답 표를 잘못 적은 것이라 정정함. 실제로는 10/12, 놓침 2.
2. 한 장이 위아래 두 상자로 쪼개져 넓게 잡히는 숨은 헛 잡음을 찾음.
3. 판정을 비율 1.05 + 높이 0.6~0.8 + 겹친 상자 제외로 바꿈 → 눕힌 패 있는 강 12/12, 없는 강 24/24.
4. 도중 유국에도 추적이 본 리치를 공탁에 넣어 봉 주인을 남김(eade16d).
