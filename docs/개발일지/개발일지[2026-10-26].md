## 문제 1: 화료자(앞면)를 픽셀로 못 정해 네 자리를 다 읽음

- **원인:** 뒷면(연보라) 비율로 정했는데, 왼쪽 자리처럼 패산이 같이 들어가면 앞면이어도 비율이 넘음(장면 C).
- **해결방안:** 흰 패 면 안에 갇힌 무늬 넓이를 자리별로 재서 고름 → 한 자리로 정한 비율 8/12 → 12/12, C 한 판 Gemini 18 → 8회. 해결됨(앱).

### 시행착오

1. 뒷면 비율 기준값 조정 → C 앞면 0.026 과 엎은 자리 0.011~0.033 이 겹쳐 못 가름. 흰 면 비율은 테이블 흰 테두리가 섞여 무의미.
2. 무늬 넓이 → 12/12. 다만 D 는 1·2등 차가 1.9배(기준 2배)라 울기 많은 장면에선 실패할 수 있음. 벽시계 시간은 거의 그대로, 이득은 비용.

## 문제 2: 강 끝 판독이 장면 꼬리를 만듦

- **원인:** 자리별 강 끝 3호출 중 하나가 생각을 3~4천 토큰 하면 장면이 30초대가 됨. 호출이 많을수록 폭주가 걸릴 기회가 늘어남.
- **해결방안:** 크롭 3장을 한 호출로(`/v2/last3`) + YOLO11 로 강 틀을 잡아 마지막 패 조각만 Gemini 로 읽기("검출기 = 어디, VLM = 무엇"). 운영 배포 93088d6, 해결됨.

### 시행착오

1. 장수 힌트(정답 장수를 프롬프트에 넣어 상한부터 봄) → 꼬리가 안 줄어 접음(p90 18.6 → 24.2초).
2. 3장 한 호출 → 론 패 54 → 60/60, 중앙 8.5 → 5.9초·p90 32.7 → 14.4초. 생각 0 이라 같은 패를 늘 같은 쪽으로 틀리지만(C 오른쪽 6통 → 8삭) 방총자 판단엔 영향 없음.
3. 참고표를 넷째 사진으로 → 자리별 300 → 319/360 채택. 무늬 배치 안내·"6장씩 끊어 세기" 문구는 효과 없음.
4. 강 틀을 모델이 적게 함(rows) → 170/180 이지만 출력이 늘어 느려짐. 픽셀로 틀 잡기 → 위치 14/18(붉은 中 을 패로 못 찾음).
5. 공개 YOLO26(HaseLab)으로 위치만 → 18/18, 읽기 180/180·중앙 4.3초. 라이선스 표기가 없어 보류.
6. YOLO11(nikmomo, MIT 저장소) → 기본 신뢰도에선 강 패를 놓침(구조 2/18), 0.04 로 낮추니 위치 18/18·읽기 180/180. 비상업·AGPL 조건으로 서버에 넣음(사용자 결정). 운영 t4g.small 에서 틀 잡기 1.5~1.6초.

## 문제 3: Gemini 없이 패 종류를 읽을 수 있나

- **원인:** Gemini 는 느리고 돈이 들고 같은 사진을 다르게 읽음.
- **해결방안:** 판독엔 안 씀(미채택). 결정(사용자): 판독은 Gemini 만, YOLO 는 우리 사진이 학습 데이터로 쌓이면 다시 봄. 검출기는 위치 잡기로만 이어짐.

### 시행착오

1. 공개 YOLO26(HaseLab) 학습 없이 CPU → 사진당 0.2~0.7초, 패 85~92% 지만 손패 통째 0~1/6(Gemini 34/36). 남는 패는 크롭 안 손패 밖의 진짜 패라 병목은 검출.
2. 격자 자동 설정·검증기로 쓰기 → 점수 10/12(수동 11/12), Gemini 호출 3 → 2. 이득이 작음. int8 양자화로 운영 서버 격자 설정 5.1 → 1.75초·메모리 216~272MB(처음엔 출력층까지 양자화해 아무것도 못 찾았음).
3. 템플릿 매칭 63~68%, SIFT·ORB 40~62%, 비전 임베딩(DINOv2·CLIP) 20~30% → 14장 통째는 거의 0.

## 문제 4: 자리 판독 꼬리 지연(밤)

- **원인:** 꼬리는 사진이 부르는 생각에서 옴(먼 자리·기운 자리 C k15 43%, D 0%).
- **해결방안:** YOLO11 로 손패 틀을 잡고 조각을 번호 칸 한 장 그림으로 붙여 읽기(로컬 실험). 안전장치 켠 채 C·D p90 19.7 → 13.5초, 틀린 반영 0. 진행 중(서버 반영은 10-28).

### 시행착오

1. logprobs 로 패별 확신도를 받아 1번 읽기 → 3.8 Flash 에서 400, 불가.
2. 같은 요청 3개 대신 번호 붙인 3개 → 셋이 같이 늦는 일은 사라지지만 p90 18.4 → 23.9초. 그대로 둠(사용자).
3. 틀 + 조각 13장 따로 → p90 16.2 → 9.4초지만 입력 +68%. 한 장 그림으로 붙이니 입력 10.6k → 3.7k, 운영 검출 실측 0.9초.
4. 과적합 점검(설정 405조합·흔든 사진 17종·장면 하나씩 빼기) → 흔든 사진 15% 가 "틀렸는데 검사 통과"(토막 겹친 곳 중복, 흰 테이블 테두리를 패로). 무늬 없는 상자 버림·줄 모양 검사로 0%.
5. [평가 밖] A·E·매장 크롭 → 안전(위험 0)은 일반화, 속도 이득은 안 됨(白·무더기·기운 크롭).
