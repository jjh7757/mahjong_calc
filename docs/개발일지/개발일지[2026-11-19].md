## 문제 8: API Opus 에 무엇을 주나 — "SAM 2 오류 잡기" 지시문 + color 만 ❌, 원본 되살려도 c1 유지

## 문제 10: r16 3순은 왜 틀렸나 → "패가 실제로 움직인 때부터" 절 — 첫 판은 오염된 판, 다시 재 25/25(본 판)

- **원인:** 사용자 "r16 3순 따져 봐"(측정 없음). 실제는 D 가 끝 그대로, 손이 덮은 082\~096 에 가지런히만 함 — SAM 2 칠이 한 칸씩 오른쪽 패에 내려앉아 '13' = 실제 D. 가르는 근거는 084\~086 원본(줄 끝 패 흰 면 그대로 · 손은 오른쪽으로만). API Opus 는 c1 · e2 모두 그 구간을 "보고 잘못 읽음". 사용자 "81~89는 결국 패이동 한개도 없는건데 이것만 보게 된 이유가 뭐니" → 살필 곳을 SAM 2 의 이상(번호 겹침 · 칠 없는 패)이 정했고, "패가 실제로 움직인 때" 를 먼저 세우는 순서가 없었음.
- **해결방안:** 사용자 "재 봐" → c1 지시문에 `MOTION_SECTION` + 첫 메시지에 칸 틀 사건 목록(`slotgrid.py events`)(m1). 이어 r16 13순을 따지다 사용자 "그러면 어떻게 해야 맞출수 잇을까" → "진행해봐" → 손 위에 뜬 숫자 표시 + "숫자의 움직임은 패의 움직임이 아니다" 한 줄(m2).
  - 사건 목록 버그를 고쳐 두 판을 같은 시각에 나란히: **m1b 25/25 · m2b 25/25, 둘 다 조용한 틀림 0.** m2b 는 unsure 1 · 시간 중앙 50.2 / p90 149.5 / 최대 155.0초 · 8.80달러(c1 11.54)(표 12-84).
  - 기본 설정 후보 = m2b(motion2). 단 절 · 표시는 r16 3순 · 13순을 보고 만든 것이라 25차례는 이 지시문에 대해 "안 본" 차례가 아님.

### 시행착오

1. **뒤집힌 결과:** m1 을 처음엔 24/25 · 조용한 틀림 0 · 10.17달러로 적음(표 12-83) → m2 의 r16 13순 답에 "사건 목록이 52:xx(이 창 밖)라 무시했다" 가 나와 세션 버그를 찾음. `redirect_stdout` 을 스레드 안에서 써 사건 목록이 차례끼리 섞이고 진행 로그가 사라짐 → m1 · m2 둘 다 **오염된 판**. 스레드 전에 차례마다 만들어 결과 `events` 에 남기고 다시 잼(m1b · m2b). m1 의 "r16 13순 못 고침" 은 버그 탓이었을 수 있음(m1b 는 맞힘).
2. r16 3순 원인을 적을 때 세션은 처음에 API 답의 "060 에 D 를 붙임" 을 그대로 옮김 → 사용자 "앞에 동작을 안보고 81~89만 본거야?" 로 앞부분을 뒤늦게 봄(결론은 그대로). "못 본 것" 이라 적었다가 도구 기록을 보고 "보고 잘못 읽음" 으로 고침.
3. 떠 있는 숫자 판정의 살색 조건은 손 안 닿은 첫 프레임에서도 줄 전체를 걸어(패 등 색) 뺌 → 넓이만.
4. 사용자 "api무료토큰 다써서 이제 cluade api 쓰면 안돼" — 이 흐름(k1 \~ m2b)의 API 비용은 결과 파일 합으로 약 66달러. 이후 `claudeagent.py run` · `rebuild_api.py` 등 API 부르는 명령은 금지, Opus 판독은 Claude Code 하위 에이전트로, 새로 쓰려면 먼저 묻기.
