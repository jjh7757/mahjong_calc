## 문제 1: API 금지 뒤 읽는 쪽 — m2b 를 Flash 로 ❌, 하위 에이전트 Opus 는 SAM 2 없이도 24/25

- **원인:** 11-19 밤 사용자 "api무료토큰 다써서 이제 cluade api 쓰면 안돼". m2b(움직인 때부터 + 사건 목록 + 떠 있는 숫자)는 API Opus 판에서만 25/25(표 12-84).
- **해결방안:**
  - (11-19 밤) 사용자 "m2b 모델만 flash로 바꿔서 테스트해봐" → fm2 **❌ 18/25 · 조용한 틀림 6 · unsure 0 · 답 없음 1**(r17 11순, Gemini 429 한도). 겨냥한 r16 3순 · 13순은 맞혔지만 틀린 6 모두 "k 맞고 j 한두 칸 어긋남". 어려운 8 은 5/8 · 3 으로 g3 와 같은 수, 7.02달러 · 시간 중앙 148.7초(표 12-85).
  - 사용자 "sam2 출력은 도움이 되고 있지?" → "Opus 에게 SAM 2 없이 원본과 사건 목록만 준 판 재봐". Claude Code 하위 에이전트 Opus 25개(`opusread.py prep --nosam`, 새 `TASK_NOSAM`) → **24/25 · 조용한 틀림 1(r17 11순 3·13) · unsure 0**, SAM 2 있는 판(11-18)은 25/25. 시간 중앙 114 / p90 178 / 최대 366초(표 12-86).

## 문제 3: SAM 2 번호가 이웃 패로 넘어감 — 제약 다시 나누기 13/31, SAMURAI · 붙들기 · 가설 채점 ❌

- **원인:** 사용자 "가려진 패를 가시화할 방법" → "이 기능은 sam2에 적용해야지 손관절은 빼고" → "D 추적 돌려". `sam2xray.py` 영상에서 한 패에 번호 둘 · 진짜 D 번호 없음 · D 마스크도 들린 패로 감이 보임(측정 아님).
- **해결방안:**
  - 사용자 "sam2 오류 안나게는 못하는거니" → "진행해" → `idsolve.py`(패 하나에 번호 하나 · 장수 보존 · 손 걷힌 뒤 다시 찍기 · 갈리면 unsure): 손에서 버림 31 의 k · j 둘 다 SAM 2 그대로 0 → **13/31**, 조용한 틀림 10 → 6, unsure 16. 남은 틀림 대부분은 손 밑 D 끼운 칸. 규칙을 정답 보며 6번 고친 개발 숫자(표 12-94).
  - 사용자 "sam 2 본인이 출력 고치게는 못만드니" → "3부터 진행해봐" → SAMURAI 규칙 원숭이 패치 **❌ judge 0/3 그대로, idsolve 얹으면 1/3 → 2/3** — 그 하나도 칼만 고르기가 아니라 기억 고르기 + 문턱 −1 몫. XPU 재현 잡음이 차이만큼 큼(표 12-96).
  - 사용자 "1번 진행해봐" → 가림 동안 칼만 붙들기 hold · refuse **❌ judge 0/3 · idsolve 2/3 그대로**. refuse 는 한 칸 미끄러진 진짜 패를 끝까지 거부해 세 차례 모두 엉뚱한 번호를 버림으로 냄 → SAM 2 안에서 자리로 정체 고치기는 접음(표 12-99).
  - 사용자가 붙인 외부 제안(CoTracker3 · OC-SORT · 순서 보존 줄 상태) 검토 → "가설 채점 재 봐" → `hyposcore.py` **❌ 손 31 둘 다 맞음 13 → 5, unsure 16 → 55**, 무게 9조합 모두 ≤ 6(표 12-100).

### 시행착오

1. 세션이 처음 가시화를 손 관절 기준으로 만든 것은 사용자 뜻(SAM 2 에)과 어긋남 — 사용자가 바로잡음.
2. hold 에서 (나) 꼴은 미리 짐작한 "후보가 모두 이웃 위" 보다 단순했음 — 버린 칸으로 이웃이 미끄러져 들어와 멈춘 예측 상자가 그 이웃 위에 놓임.
3. **잘못 짚은 것:** 가설 채점 전 "자리 거리 비용이 쏠림의 원인" 이라 봄 → 실제는 손 밑에서 끊겼다 다시 잡힌 마스크가 밀리기 전 칸을 덮어(16차례) SAM 2 근거 자체가 또 하나의 "안 움직임" 근거였음.
4. 판단: 위 카메라 · 초당 5장 저장 재료에는 "손 밑에서 어느 패가 밀렸나" 정보가 없음 — 원본을 보는 Opus 읽기가 그 정보를 쓰는 길.

## 문제 4: SAM 없이 검출 상자 + 다중 객체 추적기 — 일곱 팔 ❌, 두 출력 근거 맞추기 G 도 ❌

### 시행착오

3. G 기준 "쯔모기리 거르기" 를 쯔모기리 차례만 세게 적어 hand 를 쯔모기리로 낸 2 가 기준에 안 잡힘 — 세션이 허술하게 씀, 표에 따로 적음.
4. 설치된 판에 `frame_rate` 인자 · `lap` 이 없어 글자대로 못 한 곳 셋. 이제 23차례도 본 판.
