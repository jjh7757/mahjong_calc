## 문제 1: 서버 없이 태블릿만으로 매장 대국이 되나 — 확정한 정답 12/12

- **원인:** 11-13 까지 준비한 구성(헤드 폰 핫스팟·인터넷 없음·헤드 1:1 녹화·태블릿 자체 판독 + 실시간 보기·무충전)을 매장에서 처음 씀. 자체 판독(`reader: local`)은 그동안 테스트 사진과 재생으로만 쟀고, 1:1 헤드 사진도 4:3 을 잘라 만든 흉내로만 잼.
- **해결방안:** 저녁에 태블릿을 무선 디버깅으로 붙여 기록을 받음(`experiments/visit_20261114/captures/`). 화료 기록 27개(취소 1·오류 3 포함), 14장면.
  - 사용자가 확정해 저장한 정답 12장 = 판독 **12/12**. 장면으로는 **12/14**. 경고 없이 틀린 답이 자동 반영된 것 0.
  - 시간(판독이 끝난 23회) **8.2 / 10.8 / 12.9초**. 가장 느린 호출은 `local_dora`·`last3` 6.7\~7.1초. (참고: 11-07 서버 판독은 8.6 / 13.5 / 14.6초 — 날·사진이 달라 전·후 비교는 아님.)
  - 추적 도라 표시패: 값이 있던 11/12 가 모두 정답 안에 있음.
  - 1반장(11:26\~12:35)·2반장(13:07\~14:27)은 결과 화면이 모두 맞음. 틀린 2장면은 3반장 시작(문제 3).

### 시행착오

1. 처음엔 노트북에 오늘 기록이 없어 못 찾음(`visit_20261114` 폴더 없음, adb 목록 빔) → 태블릿 무선 디버깅을 켠 뒤 `supervise.py pull`.
2. 12:02 위 화료 첫 사진은 울기(2p 퐁)를 손패에 넣어 13장으로 읽음 → 경고로 막혔고 다시 찍어 맞음.
3. 12:30 화료는 확정한 정답이 저장되지 않아 직접 채점은 못 함. 같은 손패를 12:59 에 다시 찍은 사진은 맞음.
4. 반장을 헷갈리게 설명함 — 내가 "2반장 문제" 라고 묶어 썼는데 사용자 "2반장 실패한적없는데 3반장을 실패했지". 2반장 6판은 결과가 모두 맞았고(정답 저장 6/6), 화면에 안 보이는 리치 추적만 0/8 이었음(문제 2).
5. 1반장 리치 추적을 "5/5" 라고 했다가 바로잡음 — 12:59 다시 찍기까지 센 값. 1반장만 세면 3판·4자리 **4/4**(metrics 표 11 도 고침).
6. 첫 보고를 영어로 써서 "한국말로 해" 를 두 번 들음.
7. 131625·143404·143425·144647 에 손·팔이 보임. 11-14 는 테스트 세트 밖이라 `EXCLUDED` 는 안 고침.

## 문제 2: 2반장 리치 추적 0/8 — 카메라를 옮긴 뒤에도 옛 격자를 1시간 반 씀

- **원인:** 12:56 에 카메라가 밀려 펠트가 사진에서 잘림(거치 점검 bad) → 펠트를 못 찾아 기기 판독 `localsetup` 으로 격자를 잡음(가운데 기기 x 0.60·y 0.46, 펠트 기준 없음) → 12:57\~12:58 에 카메라를 옮김 → 13:16 프레임의 기기는 x 0.52·y 0.52 인데 격자·리치봉 상자는 옛 자리(프레임에 그려 확인). 카메라 이동 감시 `FeltWatch` 는 비교할 펠트 기준이 없으면 나중에 펠트를 찾아도 **격자는 안 고치고 기준으로만 삼음** — 손으로 맞춘 격자를 지키려던 규칙. 14:35 에 사용자가 손으로 다시 맞출 때까지 그대로.
- **해결방안:** 이 날은 원인까지만. 2반장 6판·8자리 **0/8**(`sticks_seen` 이벤트 0). 점수는 화료 사진의 횡치(`riichiMismatch`)가 리치를 대신 채워 맞음. 1반장은 펠트 자동 맞추기 + 카메라 이동마다 다시 맞춤(11:32·11:36·11:37)이라 **4/4**, 리치 없는 판에 헛 리치 0 — 리치봉 픽셀 판정이 실기기에서 처음 확인됨. 고침은 11-16(problem_log 65번).

### 시행착오

1. 강 버림 수도 그 사이 위 자리 1\~6 으로 치우쳐 있었음 — 같은 격자 탓.
2. 11-13 에 넣은 `localsetup`(서버 없는 자동 맞추기)이 매장에서 실제로 불렸고, 그 길로 잡은 격자에는 펠트 기준이 없다는 구멍이 여기서 드러남. 재생·테스트 사진에서는 카메라가 안 움직여 못 봄.

## 문제 3: 3반장 시작에 화료 판독이 두 장면 실패 — 결과 화면까지는 안 감

- **원인:** ① 14:34 오른쪽 론(143404·143425·143449): 문제 2 의 옛 격자라 오른쪽 손패를 0장 읽음(`tileCountMismatch`) → "앞면으로 눕힌 손패를 못 찾았습니다" 경고로 막힘. ② 14:46(144647·144653): 14:35 에 손으로 맞춘 뒤 격자가 없는 상태(`layout_mode: locate`) → 앱이 서버 `/v1/locate` 를 부르려 했고 자체 판독 모드가 막아 **0.7초 만에 오류로 끝남.**
- **해결방안:** 원인만 정리. ①은 문제 2 와 같은 뿌리. ②는 자체 판독 모드에서 격자가 없을 때 갈 길이 없는 버그 — 아직 안 고침.

### 시행착오

1. 태블릿 화면 녹화 두 개 가운데 3.3GB 쪽(14:30\~15:45)에 두 실패 장면이 담겨 있었는데, 사용자 지시로 노트북 사본은 지움(문제 4). 태블릿 원본은 그대로.

## 문제 4: 시연 영상 — 2반장 태블릿 화면 녹화를 잘라 유튜브에

- **원인:** 사용자 "1반장 테블릿 녹화영상도 가져왔니?" → 태블릿 화면 녹화는 두 개뿐(13:06\~14:30 84분 656MB = 2반장, 14:30\~15:45 75분 3.3GB = 3반장), 1반장 녹화는 없음. 2반장 영상에 사람 얼굴이 나오는 곳이 있어 그대로는 못 올림.
- **해결방안:** 원본 1:26.5\~1:32.6 을 빼고 1:21:30 까지만 남김 → `experiments/visit_20261114/screen/2반장_화면녹화_편집.mp4`(1:21:23, 소리 없음). 잘린 자리 앞뒤 프레임(원본 1:26.27·1:32.72)에 머리·상체 없음을 확인. 노트북의 원본 두 개는 지움. 사용자가 본인 채널에 **일부 공개**로 올림 — "Camera-Based Riichi Mahjong Score Calculator – Live Store Demo", https://youtu.be/4LbvlWbvBe0

### 시행착오

1. 사용자가 "1분 27 \~ 1분 31" 이라고 했는데 내가 여유를 둔다고 1:26\~1:33(7초)을 뺌 → "7초를 왜 니맘대로 뺴" → 말한 구간만 다시 자름.
2. 얼굴 구간을 0.5초 간격으로 뽑아 1:29\~1:31.5 로 봤는데 실제 프레임 시각과 어긋나 있었음 → 프레임을 하나씩 보니 머리·상체는 1:29.55\~1:32.52 → 사용자가 1:26.5\~1:31.5, 다시 1:26.5\~1:32.6 으로 정함.
3. "사람 머리 나오는 곳 찾기" 를 1,550장 눈으로 보면 150만\~200만 토큰 → 코드로 어두운 덩어리를 거르고 후보만 붙여 보는 안(3만\~6만)을 냈지만, 사용자가 구간을 직접 알려 줘서 안 돌림.
4. 81분 통째 대신 2\~3분 요약본을 권했지만 만들지 않음. 이 영상은 2반장이라 리치 추적이 0/8 이었으니, 추적이 리치를 잡는 장면은 고친 뒤 다음 매장에서 찍어야 함.
