## 문제 1: 회전 상자 검출기(8회차)를 운영에 올리자 오히려 틀리는 사진이 생김

- **원인:** 검출기 잘못이 아니라 그 뒤 규칙이 예전 상자 모양에 맞춰져 있었음. 상자가 몇 px 커지자 모서리 白 퐁 찾기가 흔들렸고, 36° 기운 떼어 둔 화료패는 축 상자 기준 흰 비율(0.399)에 걸려 버려짐.
- **해결방안:** 白 2장 이상이면 퐁 3장, 탁자 끝을 여러 줄에서 찾기, 흰 비율을 회전 상자 안에서 재기 → 운영 b57e2ce·bfdfa5b, 해결됨.

### 시행착오

1. 8회차가 白 퐁 3장 중 2장만 잡은 164501 이 오히려 틀림 → 채울 자리에 상자가 하나라도 겹치면 포기하던 규칙 탓. "白 2장 이상이면 퐁 3장" 규칙을 넣어 맞음.
2. 171245 는 8회차에서 모서리 白 을 0장 잡고 채우기도 안 됨 → 손패 상자가 커져 탁자 끝 찾는 기준 줄이 4px 내려간 것. 여러 줄에서 찾도록 고침.
3. 8회차 + 서버 정리를 운영에 올림(b57e2ce) → 운영 31/32, 183627 의 기운 떼어 둔 4만을 버림. 회전 상자 안에서 흰 비율을 재니 0.767 로 통과 → bfdfa5b 배포, 32/32.
4. 강·표시패 검출도 8회차로 합쳐 봄 → 완전 맞음 25 → 21, 경고 없는 헛 리치 2건. 강 틀·짝 규칙이 2회차 상자에 맞춰져 있어 안 합치기로 함.

## 문제 2: 역할 모델이 손패 줄 끝 3장을 울기로 봄(124654)

- **원인:** 모델이 아니라 학습 라벨 문제. 울기 없는 13장 멘젠인데 규칙으로 붙인 라벨이 손패 끝의 떨어진 3장을 울기로 두고 있었음.
- **해결방안:** 라벨 6개를 고치고, 회전 상자 크기·기울기와 뒷면 상자를 입력에 넣어(11칸) 재학습 → 운영 bacd3f6, 해결됨.

### 시행착오

1. 11칸 모델로 재학습 → 테스트 15장 705/706, 모델 단독 29 → 31/32.
2. 앱 흐름으로 9칸과 비교 → 31/32 로 같음. 개발 세트가 이미 포화라 차이를 못 가림.

## 문제 3: 운영이 로컬보다 1.4초 느림(7.23초)

- **원인:** 스레드 경합이 아니라 서버 CPU 총량. 2 vCPU 에서 세 호출이 사실상 차례로 처리됨(동시 5.05초 ≈ 따로 합 5.33초). 늘어난 몫은 대부분 사진 전체 검출.
- **해결방안:** 앱은 안 쓰는 크롭을 안 자르고 요청을 일찍 보냄(1fb3404), 서버는 같은 원본 사진을 한 번만 받고 디코딩(f33d632) → 5.88 / 6.26 / 9.08초, 해결됨.

### 시행착오

1. 앱 크롭 빼기 → 로컬 2.86 → 2.22초, 판독 32장면 같음.
2. 운영에 직접 호출해 따로·동시 비교 → CPU 총량 문제로 확인. 측정 중 강 끝 요청 하나가 토큰 4개를 써서 계속 429 가 나는 버그도 찾아 1회로 고침.
3. 태블릿 실기기 릴리즈 앱으로 갤러리 26장 판독 → 22/26, 완료 → 기록 9.99초. 세로 화면에서 "펠트를 못 찾았습니다" 안내가 단추를 덮는 UI 결함 발견.

## 문제 4: 개발 세트가 포화돼 어떤 개선도 판별이 안 됨

- **원인:** 개발 32회가 32/32 이고 운영 모델이 개발 사진을 다 배움. 테스트 15장은 기운 탁자라 0/15 로 판별력이 없음.
- **해결방안:** 개선 계획서(`docs/improvement_plan_1105.md`)를 쓰고 "잴 수 있게 → 안전장치 → 학습 → 속도" 순서로 1~7-1단계를 진행함. 잣대는 해결됨, 학습은 진행 중.

### 시행착오

1. 1단계: 테스트 15장을 펴서 읽음 → 손패 0 → 6/15. 채점이 화료패까지 자리에서 찾던 버그와, 경고 없는 틀린 자동 3건(적5만 → 5만, F1400)이 처음 드러남.
2. 2단계: 그 사진을 안 배운 나눔 모델로 개발 32회를 다시 잼 → 운영 모델과 같음. 개발 32회로는 개선을 못 가린다는 결론.
3. 3단계: 개발 26장 × 흔들기 21변형 회귀 세트를 만듦 → 전구색 0/32, ±25° 회전·축소 0.6 에 약함. 벤치가 서버의 JPEG 재저장을 안 거쳐 3장 낙관적이던 것도 고침.
4. 4단계: 마작 규칙 검증기(같은 패 5장·적5 중복·울기 구성) → 헛경보 0, 그러나 F1400 은 못 잡음.
5. 5단계: 불확실성 신호 6종 → 남은 틀림이 "화료패 놓침" 유형이라 막는 신호는 하나도 안 켬. 5 패 빨강 검사만 경고로.
6. 6단계(자정 넘어): 같은 판 프레임 두 장 투표 → 불일치는 100% 틀림을 가리지만, 남은 오류는 늘 같은 쪽으로 틀려 못 막음. 기본 끔.
7. 7-1(새벽): 세운 크롭으로 분류기 재학습 → 회귀 unsafe 26 → 43 으로 미채택.
