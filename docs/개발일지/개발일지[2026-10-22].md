## 문제 1: 실제 패 사진이 0장이라 YOLO 로 패를 읽을 수 없음

- **원인:** 학습 사진이 없어 합성 데이터로 YOLO 를 학습했는데, 실제 매장 패에 전혀 전이되지 않음(패 글꼴·색·조명이 다름). 쓰려면 실제 사진 수백 장 라벨링이 필요함.
- **해결방안:** 패 읽기는 Gemini 3.8 Flash, 점수 계산은 앱 안 엔진이 맡는 구조로 정함(모델 오류가 계산 규칙에 섞이지 않게) → 채택(623fc6a), 해결됨.

### 시행착오

1. 합성 손패 12장(156패)을 Gemini Pro·Flash 에 넣음 → 패 단위 90~91% 지만 손패 전부 맞음은 4~5/12, 지연 평균 Flash 17초·Pro 31초. 처음엔 "VLM 은 보조용, YOLO 노선 유지"로 판단함.
2. 테이블 전경 실제 사진 1장 → Flash 는 56장을 지어내고(186초), 합성 학습 YOLO 는 8개 검출이 전부 오검출(의자 등을 백으로).
3. 눕힌 손패를 위에서 찍은 사진을 잘라 넣음 → Flash 13/13, 이어 국사무쌍 14/14·구련보등 13/13, 7~15초. 결론을 "모델보다 촬영 조건이 결정적"으로 바꿈.
4. 같은 손패 사진에서 합성 YOLO 는 13장 중 8장만 맞히고 중복 2개 → 실제 사진 라벨링 없이는 YOLO 노선이 성립하지 않는다고 보고 Gemini 로 감.

## 문제 2: 방송 화면처럼 패가 작게 찍히면 Gemini 도 못 읽음

- **원인:** 해상도. 원본에서 패 한 장이 약 40px 라 키워 보내도 정보가 늘지 않음. 다 맞혔던 폰 사진은 패가 110~120px 였음.
- **해결방안:** "패 한 장 100px 이상" 기준을 잡음. 12MP 폰을 90cm 높이에 두면 약 75px 라 부족 → 거치 높이 60~70cm 또는 2배 줌이 필요하다고 정리. 진행 중(매장에서 높이·줌별로 찍어 확인할 것).

### 시행착오

1. M리그 중계 프레임 전체 → 13장을 답했지만 거의 틀림, 80초.
2. 손패만 3배 확대 → 장수부터 틀려 8~9장, 39~58초. 확신이 없으면 생각 토큰이 5천~8천으로 불어나 느려짐.
